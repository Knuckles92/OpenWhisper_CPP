# Database, history, calendar, export, stats

Area `a09-history-stats`. Source root: `D:\coding\whisper_local` (read-only). About 10.4k Python lines across 17 files. Everything below was read in full; tests were read for the pure-logic modules and skimmed (names + key assertions) for the Qt ones.

## What the user gets

- **History sidebar** (right-hand slide-out, Ctrl+H, edge tab on the window edge): newest-first cards of every dictation, file transcription, command/transform/action/walkthrough rewrite and failed recording. Debounced search (250 ms) over text, raw text, timestamp string, source name, title, device name and app name. Each card shows time, saved-audio chip (file size), model badge, chips (kind, AI cleanup, "Original", app, where kept), title, 100-char preview, Play and "Transcribe again". Right-click menu, delete confirmation with "also delete the audio" choice and "Don't ask me again". Header menu: Export history..., Open recordings folder, Clear history, Clear history + recordings.
- **History entry dialog** (click a card): full transcript, details grid, Original/AI toggle with "Use this version", Copy / Copy Raw / Transcribe Again / Delete, playback bar.
- **History calendar** (View > History Calendar, Ctrl+Shift+D, calendar glyph in the sidebar header): month grid painted by hand, tinted by how much was recorded, with a line per recording, kind filter chips (Dictations / Files / Meetings), Where filter (only when records live on more than one computer), year strip, month/year picker popup, day agenda with cards, streak chip, busiest-day jump, milestone stars (1st, 10th, 50th, 100th, 250th, 500th, every 1000th recording).
- **Export dialog** (Export history...): all / selected, date range, "only with audio", Markdown / Plain transcript / JSON, one file per transcription or one combined file, cancelable background export with progress.
- **Stats window** (tray menu "Stats", main-window `stats_requested`): non-modal; week / month / all time; words dictated with trend chip and bar chart, four numbers (time saved, speaking pace, dictations, day streak), "Across OpenWhisper" feature rows (meetings, files, walkthroughs, actions, commands, snippets, dictionary) that open their feature on click, hour-by-weekday heat grid, top apps, share bars (app kind, AI cleanup, language), 53-week activity map, next-milestone bar, Reset stats.
- **Recordings retention**: saved WAV copies of recordings are rotated by count or folder size; deleted with entries when asked.
- **Paste/copy last original** (shortcut and tray): undo of AI cleanup for the newest dictation.
- **Transcription stats strip** (`TranscriptionStatsWidget`): Transcription Time / Audio Duration / File Size under a finished transcription.

## Data and formats

**Files on disk** (all under the user data root, `config.user_data_path`; `data_root()` is in a01):

**Timestamps**: history `timestamp` is `datetime.now(timezone.utc).isoformat()` (`2026-03-15T14:30:00.123456+00:00`); legacy and imported rows may be naive local wall time. Accepted parse forms: whatever `datetime.fromisoformat` accepts plus `Z`.

**Export file formats**: Markdown, txt and JSON exactly as in Modules/history_export; JSON envelope `{format_version:1, exported_at, entries:[22 fields]}`; per-entry JSON is the bare 22-field object, indent 2, UTF-8, `ensure_ascii=False`.

## Platform-specific code

- Cmd+V vs Ctrl+V in the copy-original message (`history_actions.py:15`); macOS/Windows/Linux file manager reveal is in `file_reveal` (a02).
- Omarchy UI (Linux/Hyprland) variant: `use_omarchy_ui()` -> square-ish radii in `PlaybackProgress` and stats charts (`_rounded` radius 1.0). Not needed unless the Omarchy theme is ported (a02 owns the decision).
- Python `strftime` locale: on Windows the C locale (English) is used for `%b`, `%a`, `%p`; Qt can change it on Unix. `calendar.month_name/day_abbr` are English the same way.
- First weekday comes from `QLocale().firstDayOfWeek()`; `MonthGrid`, `ActivityMap`, `HourGrid` all follow it.
- SQLite WAL on network drives or some Linux filesystems can fail; the Python code does not guard it (pragmas assumed OK).
- Windows path rules: recordings paths compared with `os.path.normcase(abspath(...))` (`failed_recording_for_path`); keep case-insensitive compare on Windows only.
- Windows file deletion semantics: `os.remove` can fail if a file is open (playing); `_delete_recording_file` returns False and logs. C++ playback must release the file when stopped.

## Porting notes

**Decomposition (Qt-free core vs Qt layer)**
- `src/core` (or `src/engine/history/`, plain C++20, no Qt): `time_utils` (ISO parse/format, local conversions), `format_utils`, `titles`, `history_types` (entry struct incl. transient `stored_on/also_on/remote_audio`), `database` (sqlite3 wrapper, schema, migrations v6..v18, repository queries returning value structs), `history_manager` (recordings folder, retention, version logic, last dictation), `history_export`, `history_calendar` (marks/index/month stats), a thin `history_service` for threading rules. The history manager needs a `RecordSync`-style interface (null implementation now) and a `LiveEvents` clear hook so the host/automation areas plug in later without touching this core.
- `src/app` (Qt Widgets): `HistorySidebar`, `HistoryItemWidget`, `ChipFlow`, `HistoryEdgeTab`, `HistoryEntryDialog`, `PlaybackControl`/`PlaybackProgress`, `ExportDialogBase` + `HistoryExportDialog`, `HistoryCalendarDialog` with `MonthGrid`, `MonthPicker`, `YearStrip`, `MonthTitleButton`, `KindChip`, `AgendaCard`, `CalendarGlyphButton`, `StatsDialog` + charts, `TranscriptionStatsWidget`, `history_actions`.
- Keep the loader rule: workers deliver results through a long-lived relay `QObject` with generation/token ints; widgets never get held or signalled from worker threads.

**Order of work**
1. time/format/titles core + tests with golden vectors.
2. database + migrations + history CRUD/search (decide DB file name and whether to open an existing OpenWhisper DB: see open questions).
3. history_manager (recordings save/rotate/usage, versions) + retention settings wiring.
4. export core + calendar core.
5. History sidebar + card + entry dialog (+ playback once a05's player exists), then export dialog.
6. Calendar dialog and its widgets (largest UI chunk).
7. Stats dialog + charts (needs a05 `dictation_stats` first) and the stats strip.
8. Host-kept records (only if the remote-computer engine is kept).

**Risks**
- Rounding: Python `round()` is half-to-even (`format_audio_duration`, stats percentages, `_duration`, `_trend`); use `std::nearbyint` with the default rounding mode, and format floats with the same `%.1f` digits.
- ISO timestamp parsing breadth (`fromisoformat` in 3.12 accepts many shapes) and local-time conversion around DST; test with the PDT case and with fall-back hours.
- Case-insensitive search: SQLite `LIKE` and `lower()` are ASCII-only, matching Python's behavior; non-ASCII text will not match case-insensitively in either. A native build can improve this (ICU or a registered Unicode-folding function) as a feature gain; keep `%`/`_` literal.
- Existing OpenWhisper DB compatibility: if FioriVoce reuses `openwhisper.db`, schema version 18 and every column must be identical (including meeting tables, AUTOINCREMENT, FTS5 external-content triggers). If it starts its own DB, still keep the same schema so imports/backups work.
- Preview truncation (`rsplit(' ', 1)[0] + "..."`) works on Python code points; use Unicode-aware cutting in C++ (100 code points, not bytes or UTF-16 units).
- Painted calendar UI (MonthGrid/MonthPicker/charts) depends on `current_ui_font_scale()` and palette tokens: port a02's scale and token color API first.
- Per-export dialog threading model (relay + tokens + cooperative cancel) is subtle and was fixed for crashes; copy the design, not just the API.
- `ExportDialogBase` is shared with the meeting exporter (a31): port as a base class with the same virtual hooks.
- Filenames: Markdown per-entry exports end in `.markdown`, single-file exports in `.md`; decide whether to keep.
- Rebrand: strings mention "OpenWhisper" (Stats intro "What you do with OpenWhisper...", "Across OpenWhisper", default export name `openwhisper_history`); FioriVoce naming is a deliberate difference to confirm.

**Estimated C++ size**: core ~2.4k lines (database 900, manager 450, export 350, calendar 350, format/time/titles 350), Qt app ~7.5k (sidebar + card + chip flow 1.4k, entry dialog 0.5k, playback 0.35k, export dialogs 0.8k, calendar dialog 0.9k, calendar widgets 1.7k, stats dialog 0.95k, charts 0.6k, stats strip 0.12k, history actions 0.1k). About 10k lines total (close to the Python 10.4k since the code is UI-heavy).

**What native code can do better**
- No Python/GIL: history list load, search, calendar indexing and stats counting are plain SQL + loops; the calendar index for tens of thousands of rows can stay in memory and update incrementally instead of the full reload on every change (the Python code rebuilds on each refresh, merged by 60 ms).
- Prepared statements and a covering index on `(timestamp)`; ask SQLite for just the 101 rows needed (already done), and add an FTS5 index for history text so search is not a full table scan of `LIKE '%x%'` (currently scans text/raw_text/etc. every keystroke after the 250 ms debounce).
- Startup: lazy-open the DB on a worker thread; avoid constructing the calendar dialog until opened (already lazy in Python).
- Painted widgets (`MonthGrid`, charts) already avoid per-day widgets; keep it so.
- Save the recording copy with a single streaming copy and `FlushFileBuffers`; retention scans can use `std::filesystem::directory_iterator` and a cached sorted list instead of re-listing and re-statting for each rotation.
