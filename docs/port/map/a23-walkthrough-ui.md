## What the user gets

Everything on screen around a walkthrough (talk while taking screenshots, get one document of words plus pictures), except the screenshot capture/drawing overlay (a22/a07) and the document renderers (a22).

- **The Walkthrough tab** (main window, third tab). Left: a 320 px settings column read top to bottom (Start/Finish button, the two shortcuts, CAPTURE, WRITE-UP, COPY sections, a "Walkthrough settings" link). Right: a "stage" that shows exactly one of three panes: the storyboard (editable review) of the newest or chosen walkthrough, a "Recording your walkthrough" card while one records, or an empty state ("No walkthrough open": three-step how-to plus the 3 newest walkthroughs). The settings never move when the stage changes; in a window too narrow for both, the column stacks above the stage.
- **The live column** (`WalkthroughPanel`): a frameless always-on-top 296 px card pinned to the screen's right edge while recording. The user's voice is drawn as rows of ticks like lines of writing; each kept screenshot drops in as a numbered thumbnail below the words; the section being spoken sits in a dashed "open slot". Footer: Snap (+ menu chevron), Hold for note, Undo, Pause, Cancel, Done. Hover a thumbnail for up / down / remove. At Done the ticks close into lines while the document is written ("Writing it up..."), then a summary ("1:15 · 1 screenshot") and the card fades. Never takes focus, is left out of screenshots, can be dragged by anything that is not a button. No column on Wayland / Omarchy desktops.
- **The Snap menu**: a no-focus popup beside the column: Region / Window under the pointer / Whole screen / In 3 seconds; the pick is taken now and repeated by Snap and the Screenshot shortcut.
- **A flying screenshot card** (`ScreenshotFlight`): a 0.68 s arc that carries the just-kept screenshot from where it was drawn into its slot in the column.
- **The ready card** (`WalkthroughReadyCard`): a corner card (bottom-right of the pointer's screen) saying "Walkthrough/Write-up copied|saved", with thumbnail, a draggable file chip, Review, and a ... menu (open, show in folder, four copy formats). Auto-hides after 14 s / 4 s.
- **The storyboard** (`WalkthroughReview`, shared by the tab and the library dialog): each section is a row of screenshot beside its editable words; edit text, include/omit a screenshot, drag a row (or Alt+Up/Down) to reorder; Save rebuilds PDF + Word + Markdown off the UI thread; Copy PDF / Markdown / Word / for agent; open or show files; AI write-up vs "As spoken" switch; version picker for earlier write-ups; Redo AI write-up, Redo as <style>, Redo with a new prompt; recover an interrupted draft; delete.
- **Side-panel Walkthroughs page** (`PastWalkthroughsPanel`): replaces History in the side panel while the Walkthrough tab is open: search + one card per capture folder (newest 60), "Open library" link.
- **Saved Walkthroughs dialog** (`WalkthroughLibraryDialog`): 1100x780 modeless-style dialog: left list of every walkthrough + retention picker ("Keep walkthroughs": Forever / 1 week / 30 days / 90 days / 1 year), right the same storyboard.
- **Write-up styles UI**: style field + menu, prompt popover (Start from, prompt text, Save as style..., Delete style), New style dialog, "Redo with a new prompt" dialog.

## Porting notes

Suggested C++ decomposition (namespace `fv`, camelCase in `src/app`; Qt-free logic in `src/walkthrough` or `src/engine`-style core that builds without Qt):

1. **Qt-free core** (new `src/walkthrough/ui_model/`, ~700-900 lines): `WalkthroughColumnModel` (tick model, sections, move/remove), `level_to_height`, easing functions, panel layout math (`_per_row`, `_rows`, block layout, footer/shot-tool rects as `struct Rect{double x,y,w,h}`), `flight card_rect`, `day/time/shots/started` formatters, `summarize` text logic, card title/search matching, copy-tip table, `COPIED`/hint strings, style-menu selection logic. Unit-test with doctest/catch against golden vectors from Python. The library/styles/document code is a22's core and must exist first (manifest I/O, `write_up_parts`, `save_review`, `retry_write_up`, `delete_entry`, retention).
2. **Qt layer** (`src/app/walkthrough/`): `WalkthroughTab` (+ `Field`, `RecentRow`, `PromptPopover`), `WalkthroughReview` (+ `Editor`, `Grip`, `Preview`, `CopyCorner`, `Row`, `Board`, `CopyGroup`), `WalkthroughPanel` (custom painted), `SnapMenu`, `ScreenshotFlight`, `WalkthroughReadyCard` + `FileChip`, `PastWalkthroughsPanel`, `WalkthroughLibraryDialog`, `WriteUpPromptDialog`, `IconPainter`. Reuse a02/a01 foundation widgets (switch, segmented bar, badge, reflow, flow layout, studio split) rather than re-creating; if they are not ported yet, port them first because the Walkthrough tab is the first user of `StudioSplit`/`Stage`.
3. **Order of work**: (a) a02 token/stylesheet pipeline + icons + shared widgets and a22 library read paths; (b) `PastWalkthroughsPanel` + `summarize` (easy, proves the loader pattern); (c) `WalkthroughReview` read-only (rows, preview, header), then editing/dirty/save bar, then `run()` gate and worker, then copy/redo/draft/delete; (d) `WalkthroughTab` column + stage + recents; (e) library dialog; (f) panel model + painting, then Snap menu, flight, ready card (these need the runtime/session signals from a22/a03); (g) write-up UI pieces last if the agent backend is kept.
4. **Risks**:
   - Pixel parity of the painted panel (tick rows, shadow stack, spring/ease timings): port constants verbatim and compare with screenshots; use `QPainter` identically, including `CustomDashLine` pattern `[3, 2.5]` and alpha math.
   - `@token` stylesheet substitution and `QStyle::unpolish/polish` on dynamic properties: the tab/review depend on `[tone]`, `[unset]` selectors; the C++ app needs the same property-driven restyle.
   - No-focus floating windows: `WindowDoesNotAcceptFocus` + `WA_ShowWithoutActivating` + macOS non-activating helper; the Snap menu deliberately is not a `Qt::Popup`; the prompt popover deliberately is. Test on Windows first.
   - Hit-testing is manual in the panel/menu (rects recorded at paint time): keep the hover/pressed/repaint ordering or buttons will miss clicks while the card is animating.
   - `QTextEdit` auto-height via `documentSizeChanged`; `Reflow`/`StudioSplit` size-policy tricks (`Ignored` width) are load-bearing for the narrow-window behaviour pinned by tests.
   - Locale: `%a/%b/%A/%B/%p` must be English regardless of system locale (use `QLocale::c()`).
   - Strings mention "OpenWhisper" (draft banner, mime type): replace with "FioriVoce" and say so in the divergence notes.
   - Time-dependent code (`time.monotonic`) must be injectable for tests.
   - The a22 library accepts `Path` and enforces folder/file name regexes; use the same rules (symlink refusal, 8 MB JSON cap) when C++ reads any manifest from this UI.
5. **Rough C++ size**: model/logic ~900; Qt UI ~5,200 (tab 1,100; review 1,500; panel 1,300; ready card 420; past panel 450; library dialog 420; snap menu 220; flight 130; icons 100; write-up dialog 150; copy tips 60); plus a ~700-line QSS resource (the strings in the two stylesheets and theme.qss rules). Total about 6,000-6,500 lines plus resources.
6. **Native improvements**: decode thumbnails and recents with `QtConcurrent` and `QImageReader::setScaledSize` (already the pattern; keep it) and cache by (path, mtime) so reopening the tab does not re-decode; compute the recents/cards list without constructing the full `Walkthrough` document (read the manifest JSON once and only the first shot); `std::jthread`/`QThreadPool` replaces per-call raw threads; the panel can paint to a cached `QPixmap` of static parts (header, footer) and animate only the body at 60 Hz; load `Preview` pixmaps lazily as rows scroll into view for very long walkthroughs (Python decodes every row up front); run `save_review` PDF rendering with `QPdfWriter`/`QTextDocument` in the core without a second app-wide gate if the new architecture allows concurrency.
7. **Behavioral decisions to keep**: unsaved-edit guards everywhere (switch folder/version/close/refresh/retention), single app-wide operation gate for review work, and "never write settings from a reload" (signals blocked).
