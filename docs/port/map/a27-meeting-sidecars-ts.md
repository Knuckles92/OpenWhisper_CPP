# Meeting agent sidecars (TypeScript: Pi and OpenCode)

Area a27. Source roots (read-only): `D:\coding\whisper_local\sidecar` (Pi harness, Node 20+) and `D:\coding\whisper_local\sidecar-opencode` (OpenCode v2 harness, Bun 1.3.14). Real source is 2,675 lines across 24 files; areas.json lists 7,218, presumably counting lockfiles. Everything below was read in full.

Paths in this document are relative to `D:\coding\whisper_local` unless stated.

## What the user gets

The user never sees these programs. They are the "agent core" behind Meeting Mode's live intelligence: while a meeting is recorded and transcribed, an LLM runs in an agentic tool-calling loop and edits the live meeting dashboard (key points, decisions, action items, risks, timeline, live notes, topic, rolling summary, participants, transcript text fixes, an inbox of open questions, and note-taker blocks). Settings choose the core: Pi (default, Node) or "OpenCode v2" (Bun, separate Downloads component, Models -> Meeting). Visible effects:

- A dashboard activity strip with strings such as "Reviewing the last few minutes...", "Updating the dashboard...", "Model is thinking through the transcript...", "Retrying a dropped model request..." (strings live in the Python host, `meeting/agent/sidecar.py:_PROGRESS_DETAILS`; they are driven by the `progress` events this area emits).
- Errors: "The installed meeting agent is out of date. Update it from Downloads.", "OpenCode runtime is missing. Install OpenCode v2 from Downloads.", "This model cannot use meeting tools with the Pi engine.", "OpenCode initialization failed. Check the selected provider and reinstall the component if needed.", "OpenCode model turn failed (HTTP 401)".
- The agent can search earlier meetings and the user's knowledge folder (read-only tools), and can ask or resolve questions in the quiet question inbox.

The sidecar holds no authority of its own. It is a transport: five tools forward to the Python host, which validates every operation. The Python side (`meeting/agent/sidecar.py`, `opencode_sidecar.py`, `tool_policy.py`, `tool_specs.py`, `prompts.py`, `scheduler.py`) is a different area (meeting agent host); this area is only the TypeScript child programs.

None of these are Whisper/Moonshine/Qwen speech engines, so nothing is `drop (engine-specific)` in the stated sense, but build and packaging plumbing for the JS runtimes is dropped if the agent loop is native.

### Added by check

- OpenCode provider differences from Pi that a single native loop must reconcile (`sidecar-opencode/src/provider.ts`): (a) `reasoning` has NO kind default; only `metadata.reasoning` enables it (Pi defaults true for kind openrouter/openai); (b) no built-in base URLs for openrouter/openai (SDK route supplies them) and no `no base URL for provider X` error; baseURL is omitted from settings when empty; (c) for kind openrouter the `reasoning.effort` body field is set whenever `metadata.reasoning`, ignoring `compat.supportsReasoningEffort === false`, and a null `thinking_levels.medium` falls back to "medium" there (elsewhere null disables effort); (d) `store:false` is added for any `responses` protocol including openrouter; (e) only two compat flags are honored (`maxTokensField`, `requiresReasoningContentOnAssistantMessages`); `thinkingFormat`, `supportsDeveloperRole`, `authHeader` (opencode_go/opencode_zen) are Pi-only; (f) model capabilities hard-coded `tools:true, input:["text"], output:["text"]`; (g) provider name is `options.provider` but plugin removes all providers except id "openwhisper" (config key is "openwhisper").
- OpenCode embedded-host extras: agent "meeting" system text is the constant "Follow the meeting host instructions." (replaced per request by the context hook); custom tools registered with `codemode:false`; `fs.fff:false`; session created with `location:{directory}`; tool input schema is the neutral JSON Schema passed through; tool result returned as `{content: text}`; tool execute also requires `request.id === context.sessionID`, emits `tool_execution_start` before and `tool_execution_end` after, and re-checks `active !== request || canceled` after the call. `agent_end` is emitted only on success; no `auto_retry_end` is emitted; `auto_retry_start` only when a retry is accepted. If cancel lands right after session creation the pass returns `aborted` before subscribing. `isBusy` = an active pass exists. `dispose` marks closed, interrupts any active session, then `host.close()`. Activity stream end without abort throws "OpenCode activity stream disconnected" internally, surfaced as "OpenCode activity stream failed".
- Pi vs OpenCode failure semantics differ: Pi `turnFailure` looks only at the LAST assistant message and fails only on `stopReason=="error"` (error text = `errorMessage`, else `state.errorMessage`, else "model turn failed"); stop reasons length/aborted count as success. With no assistant message the text is `state.errorMessage` else "model produced no assistant message". OpenCode additionally fails on finish `length` and `content-filter`, and hides provider text (only "(HTTP status)").
- Pi `runTurn` resets `lastUsage`/`aborting`, clears `agent.state.messages`, and an exception from `prompt()` while `aborting` returns `aborted:true` with the last usage. `abort()` failures only log warning "abort failed: ...". `isBusy` swallows errors as false. Usage-subscription failure logs "usage subscription unavailable: ...". Thinking level "medium" is set both via createAgentSession option and `setThinkingLevel` (ignored if missing). `PI` version string is `"dev"` when `__PI_VERSION__` is not baked, `"unknown"` at build when package.json unreadable.
- RPC edge cases not listed above: blank lines skipped; non-object JSON logs "RPC message is not an object; ignored" with no reply; a remote error response rejects with `RpcRemoteError(code default -32603, message default "remote error", data)`; request timeout error text `RPC request '<method>' timed out after <N>ms`; `log` notifications can themselves fail and fall back to stderr; handler result `null/undefined` is sent as `{}`.
- Tool definition details to port verbatim: labels "Patch meeting state", "Ask a question", "Resolve a question", "Search past meetings", "Search knowledge folder"; parameter descriptions (e.g. op "Op name, e.g. add_item.", evidence "At least one supporting transcript segment id.", ops "State-patch operations, applied in order, validated per-op.", limit "Maximum hits to return (default 10, max 20)."); patch_state/ask/resolve have `additionalProperties:false`, search tools `required:[]`; missing args default to `text ""`, `evidence []`, `question_id ""`, `answer_text ""`, `confidence 0` before forwarding; `summarize` counts any falsy `ok` as rejected. Tool `details` carry the raw host response (`{error}` on bridge failure). Description texts say "OpenWhisper meetings" (rebrand to FioriVoce deliberately if prompts are ported), and instruct models never to copy `past:...`/`file:...` refs into evidence and not to retry when recall/knowledge folder is disabled.
- Host rejection reasons the tools surface to the model (host-side, listed for the contract): human_edited, human_named, revision_mismatch, low_confidence, question_limit, `polish_only`, `notes_only` (ops outside a polish or notes pass).
- Packaging release tags: component `component-opencode-<sdk>-<n>` kept off "Latest"; never overwrite a published archive. Optional paid benchmark `benchmarks.meeting_mode.live_agent_eval --harness opencode` (consolidation budget 300 s idle / 900 s cap, invented text only) is a regression script, not shipped behavior.

## Modules

### sidecar/src/main.ts (4 lines)
Calls `startSidecar({harness:"pi", info:()=>({pi_version}), createSession})`.

### sidecar/src/rpc.ts (231 lines)
Responsibility: symmetric NDJSON JSON-RPC endpoint on stdin/stdout.
Surface: `RpcEndpoint(input=stdin, output=stdout)` with `onRequest`, `onNotification`, `onClose`, `start`, `notify`, `request(method, params, timeoutMs)`, `log(level,msg)`; `RpcRemoteError(code,message,data)`; constants -32700, -32601, -32603.
Async model: Node event loop; `readline` lines each handled by `async handleLine`; requests dispatched with `await` but not serialized with each other (a slow handler does not block later lines because `handleLine` is fired with `void`). Pending map keyed by string id; optional per-request timer `RPC request 'm' timed out after Nms`.
Edge cases to keep: `closed` guard in `send` (rpc.ts:~148); result `?? {}`; params `?? {}`; `log` falls back to stderr `[sidecar:level] msg`; a request whose `send` throws rejects and clears its timer; id comparison via `String(msg.id)` so numeric and string ids both work (the host uses ints, the sidecar uses `sc-N`); message with both no method and no id warned.

### sidecar/src/session.ts (61 lines)
Neutral types shared by both harnesses: `ParamSpec`/`ObjectSpec`, `MeetingToolDef {name,label,description,parameters,execute(params)->{text,details?}}`, `TurnResult {aborted, usage}`, `HarnessSession {runTurn,isBusy,abort,dispose}`, `CreateSessionOptions {provider, modelId, apiKey, baseUrl, kind, modelMetadata, headers, tools, log, onEvent}`, `SessionProgress {type, delta?, toolName?}`, `TurnContext {requestId, systemPrompt}`. This interface is the natural seam for a C++ `IAgentSession`.

### sidecar/src/text-provider.ts (41 lines)
`TextModelMetadata {protocol, tools, context_window, max_output_tokens, reasoning, pi_compat, thinking_levels}` and `protocolConfig(baseUrl, metadata, headers)` (see A27-17). Pure function, golden-vector candidate.

### sidecar/src/tools.ts (315 lines)
`createMeetingTools(rpc, counters)` returns the five tools in order: patch_state, ask_question, resolve_question, search_past_meetings, search_context_files. `OpCounters {applied, rejected}` is mutated by the tools and read by the runner. The five long description strings (tools.ts:17-37) are model-facing prompts and must be ported verbatim; the host's prompt builders in `meeting/agent/prompts.py` and `tool_specs.py` reference the same vocabulary. Edge cases: `params.ops` non-array -> empty array; `results` non-array -> empty; a tool bridge error is a normal textual result (model may self-correct), never a thrown error, so the agent loop survives.

### sidecar/src/runner.ts (262 lines)
`startSidecar(adapter: HarnessAdapter {harness, info(), createSession})`. State: `session`, `systemPrompt`, `activeRequestId`, `checkpointChain`, `canceledRequests: Set`, shared `counters`, `lastProgressAt`. Constants: PROTOCOL_VERSION 1, progress throttle 2000 ms, shutdown delay 25 ms. State machine: Uninitialized -> (initialize) Ready -> per checkpoint Idle -> Running (active request id set, counters zeroed) -> Idle; `canceled` pre-set for queued ids; `shutdown`/stdin-close -> exit. `checkpoint before initialize` throws. Counters are global per sidecar, reset at the start of each run (safe because runs are serialized).

### sidecar/src/pi-adapter.ts (405 lines)
The only file importing `@earendil-works/pi-coding-agent@0.84.1` (`createAgentSession`, `defineTool`, `ModelRuntime`, `SessionManager.inMemory()`) and `typebox@1.3.11`. Creates a private agent dir, `ModelRuntime.create({modelsPath, authPath, refreshOnCreate:false})`, `setRuntimeApiKey`, `getModel`, `noTools:"builtin"`, `thinkingLevel:"medium"` when reasoning, in-memory session. Throws `model not found: provider/model (check models.json in agent dir)`. `abort()` sets `aborting` so a throw from an aborted `prompt()` is reported as `aborted:true`, not an error. `isBusy` = `session.isStreaming`. Tool result shape to Pi: `{content:[{type:"text",text}], details}`. Several `TODO(pi-api)` notes (models.json location, `noTools` semantics). ## Data and formats

No settings keys, database tables or user files are read or written by this area directly. Contract surface:

- Environment inputs: `OPENWHISPER_SIDECAR_TOKEN` (required), `OPENWHISPER_LLM_API_KEY` (key; default "dummy"), `OPENWHISPER_LLM_BASE_URL` (fallback base URL), `PI_TELEMETRY=0` (set by the host for Pi), OpenCode isolation vars (A27-32). Settings that choose the core live elsewhere: `SettingsKey.MEETING_AGENT_CORE` with values "pi" (default) / "opencode" (`services/settings.py`, `MeetingAgentCore`).
- Process launch (Python side, for the contract): Pi `<payload>/node.exe <payload>/bundle.cjs` (POSIX: `<payload>/node` if executable else PATH `node`); OpenCode `<payload>/bun[.exe] --no-install <payload>/main.mjs`, cwd = private runtime root. stdio piped, `CREATE_NO_WINDOW` on Windows, UTF-8.
- Temp files: Pi `<os tmpdir>/openwhisper-pi-<random>/models.json` and `auth.json` path (carries headers; deleted on dispose/failed start). OpenCode root `<tmp>/openwhisper-opencode-<pid>-<random>/` with `.openwhisper-owner.json`.
- Wire protocol (JSON-RPC 2.0, NDJSON, protocol version 1):
  - host -> sidecar requests: `initialize`, `checkpoint`, `cancel`, `ping`, `status`, `shutdown` (shapes in A27-03..07).
  - sidecar -> host requests: `tool.patch_state {ops, request_id}` -> `{results:[{ok, reason?, target_id?, seq?, current_revision?}]}`; `tool.ask_question {text, evidence, request_id}` and `tool.resolve_question {question_id, answer_text, confidence, evidence, request_id}` -> `{ok, reason?, ...}`; `tool.search_past_meetings {query, meeting_id, limit, request_id}` and `tool.search_context_files {query, relative_path, limit, request_id}` -> `{ok, text}`.
  - notifications: `hello`, `log {level in debug|info|warning|error, msg}`, `progress {request_id, event, delta?, tool?, streaming}`.
  - checkpoint reply: `{applied:int, rejected:int, usage:{...}, canceled?:true}`.
- Host-side timings that constrain this area (for context, `meeting/agent/sidecar.py`): hello 10 s, live pass hard wall 60 s, stall 45 s, cancel 5 s, RPC 30 s, ping every 10 s with 3 misses, restart backoff 1/5/30 s with max 3 in 10 min.
- Existing installs depend on: the component archives and their pins in `services/components.py` / `services/opencode_catalog.py`; a C++ app that replaces the sidecar need not honor them, but must not clobber them if both apps share a data directory.

## Porting notes

Decision first (open question for the owner): the TypeScript sidecars exist only because Pi and OpenCode are JS SDKs. In a native app the same job is a ~1-2k line C++ agent loop that talks the four streaming HTTP protocols directly, which removes the Node/Bun download, the 10 s hello, process supervision, NDJSON, stall/restart machinery and the component packaging. The existing in-process `meeting/agent/openrouter_direct.py` (629 lines, the "Direct" core) is the behavioral reference for that loop, and this area's tool/charter/progress/retry behavior is the contract it must satisfy. Recommendation: port the behavior, not the processes.

Suggested decomposition (Qt-free core in `src/engine`-style plain C++ where possible, Qt only for networking):
1. `agent_tools` (Qt-free): the five tool definitions as JSON Schema, verbatim descriptions, the `OpCounters` tally rules, bridge-result-to-text formatting. Straight port of tools.ts (~250 lines).
2. `text_protocol` (Qt-free): `protocolConfig` and OpenCode `providerConfig` rules (base URL fixups, budgets, reasoning/thinking body fields, compat flags, header handling) (~250 lines). Golden-vector testable.
3. `agent_loop` (Qt network): per protocol request builder + SSE parser + tool-call accumulator + assistant-history replay (reasoning_content, encrypted reasoning items, Anthropic thinking blocks, Gemini thought parts) + stop-reason/error detection (A27-19, A27-24) + bounded retry with Retry-After (A27-26: 3 retries, 10 s cap, only transient classes 429/5xx/dropped stream; 400/401 fail once) + abort via `QNetworkReply::abort` (~900-1,400 lines).
4. `agent_session` seam mirroring `HarnessSession` (`runTurn/isBusy/abort/dispose`), with the one-pass-at-a-time chain, pre-cancel set, request-scoped authority token ("Meeting request is no longer active"), 2 s progress throttle and the event vocabulary (A27-21/25) that the meeting UI maps to activity strings.
5. If a child-process mode is kept for parity: `QProcess` NDJSON endpoint (~250 lines) plus a supervisor; otherwise skip rpc/runner/build/packaging entirely.

Order: 2 and 1 first (pure, testable), then 3 against a local fake SSE server copied from the TS tests, then 4, then wire into the meeting host area.

Risks:
- Faithfully reproducing provider quirks currently hidden inside the SDKs (OpenRouter signed reasoning, DeepSeek V4 `reasoning_content` replay, Responses encrypted reasoning, Gemini thought signatures, tool-call argument streaming). The test suite pins several; others (Anthropic thinking replay) are unpinned.
- Behavior differences between Pi and OpenCode (retry counts, system prompt handling) must collapse into one; the tests show Pi retries via its own settings while OpenCode copies "Pi's three retries".
- Prompt-injection stance must survive: tool outputs and knowledge-folder text are data; tools have no filesystem/shell/network authority.
- Credentials: never log request bodies or provider error bodies (OpenCode deliberately returns only status code).
- If the sidecar mode is retained, versions are pinned (Pi 0.84.1, SDK 2.0.18, Bun 1.3.14) and the Python self-describing hello checks must be mirrored.
- Pi `TODO(pi-api)` items mean some Pi behavior is inferred, not documented.

Rough C++ size: native loop plus tools and provider rules about 1,800-2,600 lines; with an optional child-process bridge add about 500. The TypeScript being replaced is 2,675 lines (about 1,500 excluding tests).

Native advantages: no 10 s cold start or per-meeting Node spawn, no tens of MB bundle plus runtime download, direct in-process cancel (abort the QNetworkReply) removing the cancel/stall/ping/restart state machine, tool calls become direct function calls instead of 30 s-timeout RPC round trips, and no env-var credential hand-off. Note the project rule that engine code is Qt-free; this agent loop is an app-layer service (needs Qt Network), not part of `src/engine`.
