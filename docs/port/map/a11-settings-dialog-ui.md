# Settings dialog: shell, Home, search, binder, API keys, microphones, backup pages

Area `a11-settings-dialog-ui`. Source root `D:\coding\whisper_local`; all paths below are relative to it. Line numbers refer to the checkout read on 2026-11-14 (8178 lines in the area). `SD` = `ui_qt/dialogs/settings_dialog.py`.

Scope note. `settings_dialog.py` is the shell for all 28 destinations. Several destinations build their own content in modules owned by other areas (models, downloads, remote engine, MCP/actions/hooks, dictionary/snippets/styles/commands, cleanup rules, fast judgments, meeting-after, hotkey capture widgets, `NavRail`, tiles, etc.). This map covers the shell and every page that `SD` builds inline (General, Walkthroughs, Recording, Appearance, AI cleanup, Learned-rules and Profiles hosting, Meeting Intelligence extras, Meeting Dashboard, API keys, Hotkeys, Developer options, Downloads' policy combo) plus Home, search, binder, API keys, microphones, backup pages and the backup calendar. Contracts with the other areas are in "Dependencies on other areas".

---

## What the user gets

One non-modal "Settings" window (object `settingsDialog`, default client size 1315x850, minimum 940x520). Layout: a header bar (app icon, "OpenWhisper" brand, "Settings" label, a wide search button showing `Ctrl+K`), then a horizontal splitter with a 258 px navigation rail on the left and the page area on the right. Footer: "Changes save automatically", a shared message line, and a "Done" button.

- Opens on **Home**: a "what stays on this computer vs. what leaves it" strip, five cards (Dictation, Personalize, Meetings, App, Storage) of the everyday settings, and a footer line of API-key / runtime / missing-model-policy status. A dismissible "New in OpenWhisper" note sits on top until dismissed.
- The rail has Home plus six collapsible chapters (Dictation, Personalize, Automate, Meeting Mode, Models & storage, App) with 28 pages in total. Every page shows a one-line live value under its name ("Auto-paste on", "3 of 7 set", "Medium · gpt-test").
- **Search** (`Ctrl+K` or `Ctrl+F`): a command palette over the window that finds settings, models/components and help notes across every page (even unbuilt ones), opens the page, scrolls to the control, tints its card and focuses it.
- Narrow windows (< 800 px at 100% text) fold the rail into a "page menu" button in the header.
- Settings save the moment a control changes (no Apply). Destructive changes (retention shrink, removing a key/custom prompt, resetting hotkeys, restoring a backup) ask first.
- **API keys** page: choose a credential, paste a key, Save/Test/Remove; keys go to the OS credential store, never to settings or logs; status shows where the active key comes from (saved / environment / .env) masked to the last 4 chars.
- **Recording** page: preferred microphone with ordered backups (failover list), Refresh, retention (keep all / by count / by folder size with a confirm-before-delete), live preview switch.
- **Backup & restore** page: create a `.owbackup`, inspect and stage a restore, schedule automatic backups (off/daily/weekly, destination, keep-N) with a month calendar showing the last backup and planned dates.
- Hotkeys, General (paste/clipboard/tray/updates), Appearance (theme, font size, recording overlay look/parts, live-preview layout/size), Walkthroughs, AI cleanup, Meeting dashboard, Developer options pages (all inline in `SD`).

## Porting notes

### Suggested C++ decomposition
Qt-free core (testable with a compiler only; do **not** put Qt in `src/engine`, but this core belongs in a new `src/core` or inside `src/app` non-widget files):
1. `settings_destinations` (enum + alias table).
2. `search_index`: `SearchEntry`, `matchEntries`, `snippet`, `highlight` (plain-string pure functions; port golden vectors).
3. `mic_priority`: token encode/decode, rail summary, priority reorder rules (move/remove/add/choose), label construction given a device list.
4. `api_keys_model`: entry list builder, status text selection by `CredentialSource`, uses-caption builder, `validate_api_key`, `mask_key`.
5. `retention_policy`: compare limits, build confirm text.
6. `rail_values`: general / meeting-after / dashboard / backup captions.
7. `backup_dates`: `planned(day, next_due, interval)`, `monthCounts`, `dateLabel`, destination validation.
8. `window_fit`: `fitToScreen`, `onScreenPosition`.

Qt layer (`src/app`): `SettingsDialog` (shell, page registry, lazy build with std::function factories and a `buildStep` generator replaced by a vector of closures), `SettingsPage` (tile grid reflow), `SettingsBinder` (templates over `QAbstractButton`, `QComboBox`, `QSpinBox`, `QLineEdit`, `QPlainTextEdit`), `HomePage`+`HomeCard`+`StorageBar`, `SearchPalette`, `ApiKeysSection`, `MicrophoneSection`, `BackupSettingsPage`, `BackupCalendar`+`BackupMonthGrid`, inline pages as small classes (`GeneralPage`, `RecordingPage`, `AppearancePage`, `HotkeysPage`, `CleanupPage`, `WalkthroughsPage`, `DashboardPage`, `AdvancedPage`) each implementing the page-module protocol (`build/load/refresh/railValue/homeRows/cancelCapture/saveDrafts`). Replace Python's `__getattr__` auto-build with an explicit `controlFor(name)` map built from `CONTROL_DESTINATIONS`. Replace class-level callback attributes with Qt signals on a `SettingsHost` interface.

Settings storage: OpenWhisper_CPP should keep the same JSON key names so existing OpenWhisper installs and `owbackup` archives keep working; reuse the settings service from a10 (typed `Setting<T>` with default + clamp + choices), and implement `SettingsKey.X.read(settings)` as constexpr descriptors.

### Order of work
1. Foundation widgets from a02 (tile family, switch, segmented bar, nav rail, eliding combo/spin, wrapped label, QSS + palette tokens + font-scale scaler). Nothing here can match the look without them.
2. Shell: header, splitter, rail, stack, page registry with lazy build and `_loading` guard, `_persist/_persist_many`, rail value refresh coalescing, search palette, narrow/page menu, screen fitting.
3. Binder + General + Appearance + Recording (with retention) + Advanced pages (small, high value).
4. Microphones (after audio device enumeration exists).
5. API keys (after credential store).
6. Home page (needs the models/downloads summary providers, so stub them first).
7. Hotkeys page (after a06 capture widgets).
8. Backup page + calendar (after BackupCoordinator and the History calendar widgets).
9. Cleanup/Walkthroughs/Meeting pages as their areas land.
10. Staged build + controller scheduling; search metadata table last (derive from page copy to avoid drift).

### Risks
- **Visual fidelity**: ~600 QSS rules depend on object names and dynamic properties; QSS `@token` substitution and `scale_qss_fonts` live outside this area but are a prerequisite. Qt C++ QSS behaves identically to PyQt, so reusing `theme.qss` as-is is the lowest-risk route.
- **Layout reflow logic** (tile grids, Home cards, backup rows) is measured in the current font; port the arithmetic literally (`300*scale`, `400*scale`, `430*scale`, `560/700/720/800*scale`).
- **Lazy page build semantics** (`_loading`, `_initial_binding_start`, nested builds) are subtle: a page built from inside another page's build must load only its bindings and must not write.
- **Search index** depends on walking widget trees by class and objectName (`TileBase`, `modelManagerFieldGroup`, `textModelFootnote`, property `settingsSearch`); keep the same names, or index from explicit registration instead.
- **Focus preservation** in the mic list and rail click-through geometry (tests at 100/115/130%) are fragile with `QListWidget::setItemWidget`.
- **Threads**: three worker patterns (enumeration, usage, key verify). In C++ ensure workers never capture the window (use guarded `QPointer`/relay object); the Python suite has a regression test for exactly this crash.
- **Credential store**: Linux Secret Service had timeouts (4 s normal, 120 s when a prompt appears) and "never fall back to a file" policy; Qt6Keychain does not provide those timeouts, so wrap calls in a worker with a timeout.
- **Retention deletion safety**: keep confirm-before-delete and the debounce; wrong behavior deletes user audio.
- **Calendar painting** reuses the History `MonthGrid` internals (`_paint_cell`, `_number_rect`, `_px`, `_font`); port a09's widget before this one.
- **Hotkey capture on Wayland vs. native hooks** differ by backend; Windows is the primary target here.

### Rough C++ size
Shell + page registry + inline pages (general, recording, appearance, hotkeys glue, cleanup glue, walkthroughs, dashboard, advanced): ~4,000 lines. Home: ~1,100. Search (palette + index + highlight): ~800. Binder: ~200. Metadata tables: ~450. API keys: ~650. Microphones: ~700. Backup page: ~800. Backup calendar: ~500 (excluding reused History `MonthGrid`). Core logic and tests glue: ~600. Total about 9,800 lines plus ~1,500 lines of tests (the core pieces are ideal for fast pure tests; the widgets for offscreen Qt Test).

### Where native code can do better
- **Startup/latency**: the Python build exists in pieces so Settings can open without a hitch (staged build, lazy pages, deferred microphone read). - **Search**: building the index from live widgets on every open is fine in C++ (microseconds); could cache and invalidate on page build.
- **No import-thread guard** needed (no Python runtime imports), removing the `faster_whisper/torch` main-thread test.
- **Microphone listing** in-process with Qt Multimedia avoids the PortAudio "refresh only when nothing records" workaround, but keep the "in use" guard if a backend still needs re-init.
- **Credential store timeouts** can be enforced with a single worker queue instead of ad-hoc thread-with-timeout.
- **Memory**: one `SettingsDialog` kept alive and pages built once, as now; no extra work.
- **Gains to surface** (user said gains are welcome): dependency on the NeMo runtime makes a "Runtime" page show real CPU/GPU build, VRAM and load state instead of Whisper device/quantization combos; Home's Storage card can show Parakeet model + runtime sizes accurately and offline.
