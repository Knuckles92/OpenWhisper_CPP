Area `a15-models-downloads-ui`. All paths are relative to `D:\coding\whisper_local` unless absolute. 17 files, 7745 lines, every file read in full. Pure-logic service modules these pages sit on (`services/hf_access.py`, `model_catalog.py`, `components.py`, `component_catalog.py`, `local_asr/catalog.py`, `local_asr/cache.py`, `local_asr/models.json`, `whisper_sources.py`, `format_utils.py`, `dictation_language.py`) are NOT in this area (they belong to a14 and a10); I read the parts needed to state the contract and pin strings, and summarise them under "Dependencies on other areas" and "Data and formats". `ui_qt/styles/theme.qss` (a02) holds the QSS for the object names listed here; the relevant rules are quoted in "Look" notes so the porter does not have to hunt.

## What the user gets

Settings -> **Downloads** (rail page under Models & storage), the **Voice model** page (engine, model, device, language), a handful of modal dialogs, and the Remote-engine widgets that appear on the record/upload tabs.

- **Downloads, "Speech models" tab**: a searchable, filterable, sortable list of every downloadable speech model (one card per model: name, language/summary line, size, status badge, Download / Delete). Tick several and download them as a queue after a confirmation dialog; "Download all..." queues everything missing; "Stop after current" ends the queue. A 300 px side **inspector** shows the selected model's bundled technical profile (description, 15 fact rows, best-for, tradeoffs, links) and docks beside the list when the page is wide enough, otherwise floats over its right edge. A banner explains when `HF_HUB_OFFLINE` blocks downloads. A policy combo ("When a model is missing from this computer": Ask / Always allow / Never connect) lives on the row under the header (owned by the settings dialog, area a11, mounted here through `add_policy_control`).
- **Downloads, "Components" tab**: one card per optional runtime/add-on (state badge, size, Install / Update / Repair / Reinstall, Cancel while installing, Remove with confirm, live progress bar). Clicking a card opens a profile popup. Tab titles carry counts ("Speech models . 2 of 9 downloaded", "Components . 3 of 8 installed . 1 update").
- **Voice model page** (Dictation -> Voice model): "Recording engine" combo (alphabetical), caption, model picker, Model/Device/Quant/Language field row (`LocalEngineControls`), "Languages I dictate in" chips with an Add menu, an "On this computer" inventory line ("N of M Parakeet models on this computer . NVIDIA Speech CPU installed.") with a "Get models and runtimes" button that opens Downloads filtered to that engine, and a footnote about live preview.
- **One-shot dialogs**: Hugging Face download consent (Cancel is the safe default), "Required speech runtime" (model downloaded but runtime missing), "Choose a speech runtime" (GPU vs CPU offer for an NVIDIA card), batch download confirmation, component profile, "Use this GPU" (faster-whisper only), "Add custom Whisper models" (faster-whisper only), "Models on <host>" (remote engine).
- **Remote engine widgets** reused on the record/upload tabs: Device/Quant/Language combos driven only by the paired host's capabilities, the animated "this computer - wire - host" link glyph, and the "Manage host models" link with a download glyph.
- **Also in `settings_models.py`** (the `ModelAssignments` controller): Meeting Mode "Voice & speakers" page, the Cleanup model and Insights model tiles (text-LLM endpoint picker, agent picker, thinking levels), text-endpoint add/edit/delete, Runtime page (Local Whisper device/quantization), rail summary strings the host shows (voice_summary, meeting_text_summary, ...).

## Porting notes

**Suggested C++ decomposition**
- Qt-free core (`src/core/` or `src/engine/` extension, namespace `fv`, no Qt): `format_size`, `ModelCatalog` (parse `models.json`-style spec: key, repo, revision, files with url/sha256/size; display metadata), `ModelStore` (model dir layout, `is_cached` via `installed.json` + size checks, staging/`.previous` swap, delete, inventory), `ComponentCatalog`/`ComponentStore` (manifest, state computation = NOT_INSTALLED/EXTERNAL/INSTALLED/UPDATE_AVAILABLE/INCOMPATIBLE/BROKEN, describe), `DownloadQueue` state machine (single slot, batch queue, done/failed counters, stop-after-current, message text generation), `DownloadPolicy` (ask/always/never + HF_HUB_OFFLINE + one-time grants, `evaluate_access`), `selection/filter/sort` pure functions, `ConsentText` builder. These are all unit-testable with Catch2 and golden vectors; keep UI strings generated here so tests pin them.
- Qt layer (`src/app/`): `DownloadsPage`, `ModelRow`, `ComponentRow`, `DownloadRowBase` (+ a QSS generator mirroring `row_style`), `BatchDownloadDialog`, `ConsentDialog`, `RequiredRuntimeDialog`, `GpuRuntimeDialog`, `ComponentDetailsDialog`, `VoiceModelPage` (engine combo, model/device/language `EngineFieldRow`, `DictationLanguagesField` with `FlowLayout`), `StatusDot`/`StatusFieldCombo`, optional `RemoteLinkGlyph`/`RemoteModelNotice`/`RemoteEngineControls`/`RemoteModelsDialog` behind the remote decision.
- Lifecycle: a `DownloadService` (QObject on a worker thread) owns network + hashing and emits `progress/finished/failed`; `DownloadsPage` holds only callbacks/signals like the Python `on_*` hooks. Keep the `refresh(scan)` + generation-token pattern.

**Order of work**
1. a02 foundation widgets and theme tokens/QSS port (this area is almost all QSS-keyed).
2. Core: format, catalog (3 models + NeMo components), store, policy; tests.
3. `ModelRow`/`ComponentRow` + `DownloadsPage` (without inspector), then inspector + docking, then batch/queue, then components tab.
4. Consent/runtime/GPU/batch/component dialogs.
5. Voice model page pieces (engine combo, model/device/language row, languages chips, inventory row).
6. Remote widgets only if remote engine is kept; meeting/cleanup tiles ride with a13/a29/a31.

**Risks**
- The Python UI hard-codes OpenWhisper's QSS (slate tokens, 40+ object names); matching pixel metrics needs the a02 theme in place first. The row stylesheet is parameterised per row name; replicate as a function, not copy-pasted QSS.
- `Downloads` currently shows the HF cache dir; OpenWhisper_CPP needs the speech-models dir. Decide whether OpenWhisper_CPP shares `%LOCALAPPDATA%\OpenWhisper\speech-models` and `components` with OpenWhisper (README currently says an installed OpenWhisper already provides both), or uses its own `OpenWhisper_CPP` dir with an import step. Sharing means both apps' `installed.json` spec equality check and sentinel/manifest formats must stay byte-compatible, and the Python NVIDIA component also contains a Python embed the C++ app ignores.
- FreeLibrary on NeMo-Speech.cpp 0.1.0 crashes: the CPU/GPU runtime choice can't be swapped live; the Device combo must either restart the engine process or load by explicit path once per process. This changes what the "Device" field and the runtime-install flow mean.
- One-download-at-a-time + resume + cancel + SHA-256 over multi-GB files: copy `_download_verified` semantics from a14 (resume, `.partial`, size and hash check, atomic swap with `.previous` rollback). A cancel must stop mid-chunk.
- Several flows use modal `exec()` from non-GUI-initiated places (consent comes from the controller thread via a blocking call in Python). In C++, route consent through a queued signal and a promise so the worker never blocks the GUI thread.
- Dynamic-property styling (`selected`, `active`, `tone`, `muted`, `overlay`, `dot`, `available`) needs `unpolish/polish` after each change (`repolish`).
- The inspector docking math depends on `minimumSizeHint` of rows; re-check at large font scales (the Python app has a font scale setting, a02).

**Rough C++ size**: core ~1,400 lines; Qt layer: downloads page + rows + inspector ~2,100, dialogs (batch, consent, runtime, GPU, component) ~900, voice model page + engine fields + languages ~1,000, StatusDot/combos ~250; remote widgets/dialog (if kept) ~1,300; tests ~1,500.
