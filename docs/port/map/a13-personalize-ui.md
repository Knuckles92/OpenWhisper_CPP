## What the user gets

Everything under Settings -> Personalize (rail pages Dictionary, Snippets, Apps & styles, Learned rules, Profiles, Commands) plus the text-model picker used by the AI cleanup and Meeting intelligence pages, and a few dialogs and one-shot prompts.

- **Dictionary**: add names/jargon with optional "Sounds like" spellings (comma/semicolon/newline separated). Words are saved the instant they are added (no Save step). Rows have a star (starred words are sent to the speech model first), badges (Learned, New, Kept as said), Edit, Remove (Undo for new learned words). Search box appears at 9+ words. Banners: "New from your corrections" with Keep all, "Spellings in Learned rules" with Move here. Two switches: Steer the speech model, Learn from my corrections. Honest per-engine explanatory copy (what the dictionary does with the engine in use, whether only Sounds like spellings fix words while AI cleanup is off).
- **Snippets**: spoken trigger phrase -> exact text (optionally light Markdown, pasted as rich text). Master switch, library list + editor, live hint line ("Say "x" -> inserts N characters"), trigger notes (duplicate / overlaps / sounds close / single word), empty-state starter triggers, draft protection when switching.
- **Apps & styles**: app awareness switch, read-text-near-cursor switch (Windows only), never-read-from app list, "match tone to each app" switch, four category cards (Email / Work messages / Personal messages / Other) each with a Formal/Casual/Very casual segmented bar and a live example sentence, and per-app style overrides.
- **Learned rules**: type or dictate an instruction; the AI cleanup model polishes it into one rule; a review dialog offers polished vs as-typed/as-said; library list (max 50) with edit/delete, glow on the new row; animated live strip showing Listening / Transcribing / Polishing with a mic-level trace and a 60 s auto-stop clock.
- **Profiles** (cleanup profiles): named output formats with instructions, optional recording shortcut, "also apply my learned rules". Library + editor, starters (Support ticket, Email), duplicate/delete, unsaved-draft prompts.
- **Commands**: Command Mode shortcut field (capture + Clear), "write new text when nothing is selected" switch, **Transforms** (saved rewrites with optional shortcuts; starters Polish, Make concise, Fix grammar, Prompt engineer), summary of profile shortcuts, gate tile when no AI model is ready.
- **Text model picker**: endpoint combo (OpenAI, OpenRouter, local servers with "Running" marker, Groq, OpenCode, custom endpoints, "Custom..." action), credential status line, Edit/Delete endpoint, model combo (searchable, assigned the moment picked, "Active" badge), catalog sort (OpenRouter only), Refresh.
- **Dialogs**: Edit Cleanup Prompt, Review/Edit learned rule, New write-up style (Walkthrough tab), text endpoint add/edit (custom endpoint or local-server preset), speech server editor (API backend), one-time "use Claude Code/Codex for AI cleanup?" question.
- Shared copy tables: cleanup level segments Light/Medium/High/Custom with notes (also used by guided setup, Home, Settings), engine picker labels (Mac MLX annotations).

## Data and formats

All of this is stored in the one settings JSON (shared with every other area); key defaults come from `services/settings.py`.

Settings keys (name, type, default, where used):
- `dictation_dictionary` list of `{id, term, starred, heard[], learned, new[, protected]}`, default []. Newest first. Max 500 terms, term/variant max 64 chars, max 5 heard variants, whitespace collapsed, case-insensitive dedupe keeping first, missing id -> `"t" + sha1(term.casefold())[:11]`. Learned terms never keep `heard`. New ids `uuid4().hex[:12]`. (services/dictionary.py)
- `dictionary_learn_enabled` bool true; `dictionary_steer_recognition` bool true. Engine hint budget 50 phrases (`config.MAX_RECOGNITION_PHRASES`), prompt block max 200 terms / 2400 chars / 50 protected.
- `dictation_snippets` list of `{id, trigger, text, formatted}`, max 200; trigger 2..60 chars, text max 10,000; `snippets_enabled` bool true.
- `text_transforms` list of `{id, name, instruction, hotkey}` or ABSENT (absent means starters Polish, Make concise, Fix grammar, Prompt engineer; an empty list means none); max 50, name <= 80; `command_mode_insert_without_selection` bool true; hotkeys map `hotkeys["command_mode"]`.
- `transcript_cleanup_profiles` raw list of `{id, name, instructions, hotkey, use_learned_rules}` or ABSENT (starters Support ticket, Email); `quick_record_profile` str "" (cleared when that profile is deleted).
- `transcript_cleanup_rules` list[str] (max 50, stripped, blank dropped); `transcript_cleanup_provider`, `transcript_cleanup_model`, `transcript_cleanup_reasoning`, `transcript_cleanup_model_sort`, `transcript_cleanup_level`, `transcript_cleanup_prompt` (custom prompt; a copy of a built-in prompt counts as none), `transcribe`-side toggles `transcript_cleanup_enabled`.
- `app_context_enabled` true; `app_context_read_text` false; `app_context_excluded_apps` list[str] (<=100 here); `app_styles_enabled` true; `app_style_tones` dict `{email, work, personal, other} -> formal|casual|very_casual` or absent (= all Formal; brand-new installs are seeded email formal, work casual, personal casual, other formal); `app_style_overrides` list of `{match, category}` (max `catalog.MAX_OVERRIDES`, match <= `catalog.MAX_MATCH_CHARS`).
- `text_llm_profiles` list of `{id ("custom_"+8 hex), name, base_url, api_key_env, protocol ("chat"|"responses")}`, max 50 custom; per-local-server `"<id>_base_url"` and `"<id>_api_key_env"` for ollama, lm_studio, vllm, llama_cpp, localai (defaults http://localhost:11434/v1, http://127.0.0.1:1234/v1, http://127.0.0.1:8000/v1, http://127.0.0.1:9931/v1, http://127.0.0.1:8080/v1).

Risks:
- Pixel/behavior parity depends on shared tile widgets (`InfoTile`, `SettingTile`, `SegmentedBar`, `Reflow`) and the 6k-line `theme.qss` token system, which live in other areas. QSS blocks for this area: theme.qss lines 494-665 (text model picker, endpoint dialog), 1561-1593 (profiles), 2410-2698 (learned rules, strip, empty state, rule dialog), 4574-4608 (styles), 4610-4646 (cleanup level note/prompt editor), 4648-4715 (commands/transforms), 4717-4823 (dictionary), 4825-4923 (snippets); the QSS reuses `qproperty-icon: url(ui_qt/assets/tabler/...@icon-suffix.svg)` (per-theme icon suffix) which needs the same asset loader.
- Responsive re-flow logic (resizeEvent flipping layouts, constant size hints to avoid flip-flop, focus preservation when rebuilding rows, tab order rechaining) is subtle and pinned by tests at large font scales; port with their tests (`QTest` with offscreen platform).
- Thread/lifetime crashes documented in `settings_cleanup_rules._Relay` and `speech_server_controls._CatalogRelay`; in C++ use `QPointer` + queued connections to long-lived objects.
- Python `difflib` ratio is not an edit-distance ratio; `trigger_note` thresholds (0.85) must be validated against a reimplementation.
- Regex behaviour for snippets/Markdown (`\w`, lookbehind, `(?<!\w)`) differs subtly between Python `re` and QRegularExpression/PCRE2; run golden vectors with Unicode text.
- `casefold()` vs `QString::toCaseFolded()`/`toLower()`: German ss etc.; use `toCaseFolded()` consistently.
- Dictionary/engine copy depends on which backends are kept (see Engine-specific); an in-process Parakeet may or may not accept hints.
- Rule dictation needs the app's recorder with a "short file" mode and a transcription entry point the engine thread can serve (`transcriber()` callback); must run through `EngineWorker` queued signals, never calling `Recognizer` from the GUI thread.
- Copy says "OpenWhisper" in several user-visible strings (SUBTITLE of Dictionary, snippet limit message, privacy note, endpoint dialogs, temp filename); decide the FioriVoce product name and substitute centrally.

Rough C++ size: core logic (dictionary, snippets incl. Markdown, transforms, profiles, styles, endpoints, validators, copy functions) about 2,200 lines; Qt UI about 6,500 lines (dictionary 700, snippets 600, styles 650, rules + strip + glow + dialog 1,100, profiles 400, commands/transforms 650, text picker + endpoint dialog 800, agent offer 150, small dialogs 300, level copy 60, speech server pieces 350 if kept). Total about 8,500-9,000, or about 8,000 if cloud speech servers and the MLX picker are dropped. If the services are already planned in other areas, the area-owned portion is ~6,500.

Native improvements:
- Dictionary replacement/search/learning diff and snippet planning run on a single pass in C++ with no regex recompilation (the Python recompiles per call); precompile per settings snapshot and reuse for live dictation (lower per-utterance latency).
- `LevelTrace` and the glow can paint from one shared timer at 60 Hz with no per-bar allocations (Python builds a list per tick); the ring buffer can be a fixed array.
- Lazy page construction is currently done by `__getattr__` tricks and import-time deferral for startup; in C++ pages can be created on first show with `QStackedWidget` and startup cost is already low.
- The activity strip can reuse the main recorder's level meter directly instead of emitting 16 ms tick signals across threads (atomic float read on each tick).
- Native QCompleter-based searchable combo for the model picker (large OpenRouter catalogs of 300+ models) with a `QSortFilterProxyModel` is faster than rebuilding items.
