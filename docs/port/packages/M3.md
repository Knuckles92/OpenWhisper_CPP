# M3 Data safety and release: work packages

Binding scope of packages M3.1 to M3.11 (architecture amendment 7). Names of targets,
directories, classes and headers come from `docs/port/ARCHITECTURE.md` and are not changed here,
except where "Changes to the cut" says so. Python paths are relative to `D:\coding\whisper_local`
(OpenWhisper 2.8.92, commit `768b559edd93`). Area maps are in `docs/port/map/`. M0 and M1 are
assumed complete as `M0.md` and `M1.md` describe them, and M2 as `M2.md` (M2.1 to M2.28)
describes it; every M2 contract this file relies on is listed under "What M3 assumes of M2" with
the M2 package that provides it.

## Overview

M3 makes FioriVoce safe to run on real data and installable. It ports the rest of a10 (portable
backups: create, inspect, stage, apply with journal and rollback, the automatic schedule, the
startup restore gate and the restart-after-restore contract, exit code 73), the one-time import of
an OpenWhisper install (settings, database, recordings and other owned data through the restore
pipeline, API keys from the Credential Manager, and the already-downloaded runtime and models
through M1.11's adoption), a09's legacy JSON history import, the a16 update check, update notice,
update dialog and the setup-exe update path, and a34's Windows installer (Inno Setup), signing
script, third-party notices, release qualification, component pin tool and CI workflows.

**Demo (section 11):** "Install with the Inno setup, import an OpenWhisper data folder, back up
and restore, update to a newer build." Concretely, on this machine:

1. `powershell -File packaging\windows\build-installer.ps1 -Clean` builds RelWithDebInfo, stages
   the install tree, generates the notices, runs `fiorivoce-cli --self-test --installed` on the
   stage and compiles `out\installer\FioriVoce-Setup-0.1.0.exe` with the local `ISCC.exe`
   (unsigned: no signing variables are set). Running the setup installs per user into
   `%LOCALAPPDATA%\Programs\FioriVoce` without UAC, adds the Start menu entry and starts FioriVoce.
2. On the first run the guided setup's Welcome page offers "Bring over your OpenWhisper data"
   because `%LOCALAPPDATA%\OpenWhisper` exists. The import dialog lists what it found (settings,
   history entries, recordings size, the NeMo runtime and the Parakeet model); with OpenWhisper
   running it says to close it; otherwise "Import and restart" stages the data, copies the API
   keys (when ticked), adopts the runtime and model by hard link, restarts with exit code 73 and
   applies the stage before settings or SQLite open. History shows OpenWhisper's entries, Settings
   shows its choices, the keys are in Credential Manager under `FioriVoce`, and
   `fiorivoce_settings.json` records `fv_import`.
3. Settings > Backup creates `FioriVoce-backup.fvbackup`, inspects it, and "Restore and restart"
   brings it back; the previous data stays in `.fiorivoce-restore\previous-*` and is shown on the
   page. A daily schedule saves `FioriVoce-auto-*.fvbackup` files and the calendar shows them.
4. `build-installer.ps1 -Version 0.1.1` builds a second setup;
   `py -3.12 tools\release\serve_update_feed.py --setup out\installer\FioriVoce-Setup-0.1.1.exe
   --version 0.1.1` serves it on loopback; the installed 0.1.0 started with
   `FIORIVOCE_UPDATE_FEED_URL=http://127.0.0.1:<port>/releases/latest` shows "Update to 0.1.1"
   in the title bar and the tray; "Download and install" verifies the setup's SHA-256, runs it
   silently, FioriVoce exits and the setup relaunches 0.1.1; Help > About reads "Update status: Up
   to date".

Nothing in M3 pushes, publishes, uploads or creates a release, and nothing contacts a network
service of OpenWhisper's: FioriVoce has no release feed yet, so its update source defaults to
none, and the demo's update comes from the loopback feed.

**Rules that apply to every package below** (M0.md's and M1.md's rules, unchanged):

- A package changes only what its `Owns` line lists, plus its own `tests/<dir>/PARITY.json`, its
  case files `tools/parity/cases/<python.module>.py`, its builder file and its
  `tests/golden/<python.module>.json` and `tests/reference/<widget>/` entries.
- Function-level PARITY: a package lists the functions its section names (`ported`, `golden`,
  `dropped`, `other-platform`, or at most 10 % of its own scope `pending` with a reason and a
  finishing package) plus the functions this spec marks `pending` for a later milestone.
- Qt-free code keeps Python's names in snake_case; Qt classes use camelCase (section 8.3). Every
  class states its affinity. User-visible strings are copied verbatim from the cited Python line;
  "OpenWhisper" in copy becomes `identity().product`; `lint.brand` allows the literal only in
  `base/identity.cpp`, `backup/import*`, `remote/wire.h` and tests.
- Code that takes over the desktop (named mutex gates against a real Inno setup, starting a
  detached setup, message boxes) is proven through fakes; the real-API test is tagged
  `[interactive]`, written and not run (amendment 14). File, registry-under-a-test-key,
  Credential-Manager-under-a-test-service and child-process tests are `[platform]` and run.
- No test, vector generator or tool contacts the network beyond 127.0.0.1. Vectors of
  `services.app_update` are generated only from functions that do no I/O.
- Format with `wsl clang-format --dry-run -Werror` (amendment 3). PowerShell, Inno and YAML files
  are not clang-formatted; Python under `tools/` follows the existing tools' style.

## Changes to the cut

Section 11 gives M3 no package table; these choices are this spec's.

1. **The Settings Backup page is M3's** (A11-79 to A11-84, A11-101 to A11-103) although section 11
   lists a11 pages only under M2 and M4: the demo backs up and restores through it, and section
   2.3 places it in `fv_ui_settings`. The backup-busy lock itself (A11-20) is M2.11's
   `SettingsDialog::setBackupBusy`; M3.9 registers its page through `SettingsPageRegistry` (with
   its rail value) and drives the lock, and edits no M2 file.
2. **Phase 1 of a34's update plan, not the native updater.** M3 updates by downloading the verified
   Inno setup and running it silently (a34 section 6.6 phase 1). The transactional updater, the
   update archive, the setup helper protocol (`--setup-action`), the data snapshot, the health
   launch and the update-in-progress refusal are M10, as section 11 says. The installer removes
   stale files with an `[InstallDelete]` list instead of the helper (a34 6.3).
3. **No update source by default.** The release identity (`src/update/data/release_identity.json`)
   names the update source; it is `{"kind": "none"}` until the lead records a FioriVoce
   repository. With no source, automatic checks never run and a manual check reports "This build
   of FioriVoce has no update source." without touching the network. `FIORIVOCE_UPDATE_FEED_URL`
   (loopback only, A16-07) still works, which is how tests and the demo update. OpenWhisper's
   repository constant is never ported.
4. **`src/process` gets `process/detached.h` in M3** (M3.5): the restart after restore and the
   setup hand-off need a detached child, and `fv_process`'s launcher is M5's. M5 keeps the file.
5. **`src/download` is extended by M3.5** (M1.7's directory) with a route switch and per-caller
   messages for the update download (A16-14).
6. **`--workflow-smoke` lives in `fiorivoce-cli`** (Qt-free), not in the GUI executable, which
   prints nothing to a console; `fiorivoce.exe --workflow-smoke` is refused with the usage line.
7. **Import is offered on the guided setup's Welcome page and on the Backup page**, not by a
   separate startup prompt: M3.7 edits M2's `GuidedSetupDialog` (new variant of the Welcome page
   only when OpenWhisper data is found).
8. **Install staging is a script** (`packaging/windows/stage.ps1`: copy from the build tree,
   `windeployqt`, app-local CRT), not CMake `install()` rules (a34 6.2), because those would edit
   the frozen `cmake/` folder. See lead decision 7.
9. **Code-change restart prompt** (A16-30, A03-83) is ported for the installed executable only;
   the git-checkout identity is dropped (FioriVoce never runs from a Python source tree).
10. **`qualify-release.yml` is deferred to M10.** It uploads to a draft release; M3 writes
    `ci.yml` and `release-build.yml` only (build and test, workflow artifacts), which are not run
    and not pushed.
11. **MCP event subscriptions are not imported** (`mcp_event_subscriptions.json` is outside the
    restore pipeline's owned names), so their secrets are not copied either; section 7.5 step 4
    listed them. Webhook, action, MCP-token, API-token, remote-engine-token and API keys are
    copied.

### Traps

- `create_backup` order is load-bearing (`backup.py:766-843`): snapshot DB, merge legacy
  history, sanitize DB, collect files, read settings under a file signature, sanitize settings,
  size and free-space checks (`_FREE_SPACE_MARGIN` 32 MiB), write to a temporary
  `.owbackup-build-*` beside the destination, run the full inspection on the temporary archive,
  re-check every source signature, then replace. Name the build folder after
  `identity().backup_extension`.
- `_archive_file` (`backup.py:690-716`) re-stats the opened file and compares (dev, ino, size);
  on Windows use `GetFileInformationByHandle` (volume serial, file index) for dev and ino, as
  `os.stat` does. "Data changed during backup: <name>".
- Audio suffixes `.wav .mp3 .flac .ogg .m4a .mp4` are stored, everything else deflated
  (`backup.py:697-699`); every entry is written with Zip64 extra fields (`force_zip64=True`), so
  the reader must accept Zip64 records on small members (Python-made fixtures have them).
- `_scrub` drops any dict key containing a secret word case-insensitively ("header" and
  "cookie" included, `backup.py:270-273`) and keeps URLs below `dictation_snippets` at any
  depth; a URL that `urlsplit` rejects becomes "" only when it starts with http(s)
  (`backup.py:288-289`).
- Link actions keep `params.template` unscrubbed; webhook, program and agent actions come back
  `enabled: false`; rows the loader drops are dropped (`backup.py:298-319`).
- `_snapshot_database` refuses "End the live meeting before creating a backup" when a
  `meeting_sessions.status` is `active` or `paused`; it uses the read-only URI, 256 pages per
  step and 50 ms sleeps, checking cancel per step (`backup.py:394-431`).
- Validation rules are security-relevant (zip-slip, case-fold duplicates, ratio bombs
  `MAX_RATIO` 10,000, symlink mode bits, manifest list equal to members): port
  `backup.py:852-1062` line by line; error texts verbatim (map "Errors worth keeping").
- `BackupError` texts that name the product ("Backup file must end in .owbackup") take the
  extension from `identity()`; the reader's refusal for an unknown format id stays "Unsupported
  backup format".
