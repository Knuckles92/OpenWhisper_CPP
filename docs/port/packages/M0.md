# M0 Foundation: work packages

Binding scope of packages M0.1 to M0.12 (architecture amendment 7). Names of targets,
directories, classes and headers come from `docs/port/ARCHITECTURE.md` and are not changed here,
except where "Changes to the cut" says so. Python paths are relative to `D:\coding\whisper_local`
(OpenWhisper 2.8.92, commit `768b559edd93`). Area maps are in `docs/port/map/`.

## Overview

M0 lays the ground every later package stands on: the Qt-free base (identity, paths, executors,
cancellation, signals, log facade, atomic writes, data lease), Python semantics (`fv_pyport`),
the parity harness (golden vectors and reference screenshots), logging and diagnostics, the
settings store with its generated key table, credentials, the theme pipeline, the Qt bridge and
feature registry, the leaf widgets, and the application shell.

**Demo at the end of M0.** `openwhisper-cpp.exe` shows the painted splash, then the themed frameless main
window: custom title bar with File, View and Help menus and painted window buttons, four tabs
(Quick Record, Upload File, Walkthrough, Meeting Mode; placeholders except Upload File), the footer
(Minimize to Tray, Stats, Settings, Quit), a tray icon with OpenWhisper's menu, close-to-tray,
and a second launch that raises the first window. Settings and logs live in
`%LOCALAPPDATA%\OpenWhisper_CPP` (or `OPENWHISPER_CPP_DATA_DIR`). The Upload File tab hosts today's bench,
which still transcribes a WAV through `EngineWorker`. `openwhisper-cpp-cli --version` and
`openwhisper-cpp-cli --diagnostics out.json` work. The title bar, the footer and `EmptyState` pass
screenshot parity against PyQt6 references.

**Rules that apply to every package below.**

- A package changes only what its `Owns` line lists, plus its own `tests/<dir>/PARITY.json`,
  its case files `tools/parity/cases/<python.module>.py`, its builder file and its
  `tests/golden/<python.module>.json` and `tests/reference/<widget>/` entries.
- `PARITY.json` lists every function of every OpenWhisper test file the package's section names.
  Functions whose subject this spec assigns to a later package are `pending` with that package
  or milestone; the 10 % pending cap of architecture 9.5 applies only to functions whose subject
  is in the package's own scope.
- Run the app and widget tests through `ctest`, never by starting a test executable directly.
- Format with `wsl clang-format --dry-run -Werror` on every added or changed C++ file
  (amendment 3).
- A contract header from M0.1 that turns out wrong is reported, not edited: the lead fixes it in
  an interface-fix package at the wave boundary (architecture 10.1). Members may be added.

**Contract gaps found in review** (each now has an owner below; none needs an interface fix):

1. `base/env.h` and a process-environment `EnvReader` were consumed (M0.5, M0.6, M0.7, M0.11)
   but neither section 3 nor any package provided an implementation: M0.2 adds `system_env()`.
2. `golden::rebrand` (M0.4) was specified over `identity()`, which M0.2 implements in the same
   wave: M0.4 keeps a literal map and M0.11 cross-checks it against `identity()`.
3. `process/Shell` (section 3.9) is header-only until M5: no M0 or M1 package consumes it;
   reveal and open-folder go through M0.10's `revealInFileManager` and
   `openFolderInFileManager`.
4. `log::ReportInputs::nvidia_gpu` and the catalog allowlist are filled by M1.16 (M1.md change
   17), the first package that owns both executables' `ReportInputs` lines after M1.11 exists.

## Changes to the cut

1. **Test fakes for base move into `src/base/testing/`.** `FakeClock`, `ManualExecutor` and
   `MapEnvReader` are owned by M0.2, not by `fv_testkit` (architecture 3.2 put them in testkit).
   M0.2's own tests need them in wave 2, while M0.4 builds `tests/support/` in the same wave;
   with the fakes in testkit, M0.2 would depend on a same-wave package. `fv_testkit` links
   `fv_base` and re-exports them.
2. **`fv_testkit` is split in two targets:** `fv_testkit` (Qt-free: temporary data root,
   `RealtimeGuard`, golden paths) and `fv_testkit_qt` (Catch2 main with the pinned offscreen
   `QApplication`). Core test executables must build on `linux-core` without Qt, which a single
   testkit with a `QApplication` main would prevent.
3. **M0.3 makes its own vectors.** pyport's vectors are of Python builtins and need no OpenWhisper
   import, so M0.3 writes them with `tools/gen/pyport_vectors.py` in the harness JSON format and
   replays them with a 100-line reader in `tests/pyport`, instead of waiting for M0.4's
   `golden_vectors.py` and `fv_golden` in the same wave.
4. **Hidden dependencies added:** M0.5, M0.6 and M0.8 depend on M0.4 (they generate vectors with
   the harness; M0.6's key generator imports OpenWhisper through `tools/parity/ow_isolation.py`).
   M0.5 depends on M0.3 (`fromisoformat` revalidation and Python `json.dumps` spacing in the
   diagnostics files), so `fv_log` declares `DEPS fv_base fv_pyport` (architecture 2.3 lists base
   only). M0.10 depends on M0.6 (`TabbedContentWidget` persists `last_tab_index` through
   `SettingsStore`). M0.11 lists M0.8 explicitly. None of these moves a package to another wave.
5. **M0.11 also owns `src/uimath/window_geometry.{h,cpp}`** (pure clamp and restored-width maths
   extracted from `MainWindow`, architecture 8.3) in wave 5, when no other package owns
   `src/uimath`, plus `tools/parity/builders/a01.py`.
6. **Leaf versus composite widgets** (architecture 8.2 names the split, not its content): M0.10
   ports the leaf widgets and the main-window pieces M0.11 needs (`TabbedContentWidget`,
   `UpdateNoticeButton`, `DragToMove`, `revealInFileManager`). `FieldHelp`, `FlowLayout`,
   `ButtonRow`, `Reflow`, `StudioSplit`/`Stage`, `ScrollingBody`, `SearchableComboBox`,
   `SegmentedBar`, the tile family and `NavRail` go to the M2 composite-widgets package, with
   their maths in `src/uimath`.
7. **Markdown rendering (`render_markdown`, `MarkdownStyle`) goes into `fv_ui_theme`** (M0.8): it
   is palette-driven typography over `QTextDocument`, and M1.9's transcript pane needs it.
8. **`openwhisper-cpp-cli` is split from M0.11 into M0.12 cli** (`src/cli`, `tests/cli`, wave 4).
   M0.11 was about 3,300 source and 1,400 test lines, over one worker's budget; the CLI is
   Qt-free, needs only M0.5 and M0.6, and shares no file with the shell, so it moves to wave 4
   beside M0.10. M0.11 keeps the GUI executable (`src/app`) and its early CLI.
9. **One owner per feature ID.** Where several packages contribute to one ID, the coverage row
   names the owner first (its acceptance covers the ID) and every other package cites the ID in
   its Scope as "part of A0x-nn". A script counting Scope ownership skips IDs prefixed
   "part of". IDs M0 defers to M1 are owned by the M1 package `M1.md` names; M1.md adds M1.21
   main-window for the main-window behaviour that M0.11 leaves to M1.

## Waves

| Wave | Packages | Starts when |
|---|---|---|
| 1 | M0.1 | now |
| 2 | M0.2 base, M0.3 pyport, M0.4 parity-harness | M0.1 merged |
| 3 | M0.5 log, M0.6 settings, M0.7 credentials, M0.8 ui-theme, M0.9 appkit | wave 2 merged |
| 4 | M0.10 widgets-leaf, M0.12 cli | wave 3 merged |
| 5 | M0.11 shell-and-cli | M0.10 merged |

Directory ownership per wave is disjoint: wave 2 owns `src/base`, `src/pyport`, `tools/parity`,
`tests/support`; wave 3 owns `src/log`, `src/settings`, `src/credentials`, `src/ui_theme`,
`src/uimath`, `src/appkit` (and their `tests/<dir>`); wave 4 owns `src/ui_widgets` (M0.10) and
`src/cli` (M0.12); M0.11 owns `src/uimath/window_geometry.*` only in wave 5. Every dependency
points to an earlier wave.

architecture's milestone table; the package is named where `M1.md` fixes it (M1.md repeats every

several M0 packages, the first is the owner (change 9). Checked by script: 215 IDs (a01 79, a02
66, a10 49, a34 21; a33 has no inventory IDs, so its ten top features are numbered A33-H1 to
A33-H10 here), each owned by exactly one package or deferred to a named milestone or dropped.

  `ordered_json` directly; duplicate keys keep the last value in the first key's position as
  Python's `dict` does.
- `ensure_ascii=True` (Python's default, used by the settings file) writes non-BMP characters as
  a surrogate pair `\ud83d\ude00`, lower-case hex.
- `py_int` on a float truncates toward zero; on `"3.7"` fails; on `True` gives 1; on a value

  (`setting_types.py:175`).
- `casefold` is full folding (`ß` -> `ss`, `ﬁ` -> `fi`); `QString::toCaseFolded` is not.

### Traps

- Startup order (A01-77, `main.py:300-416`, `bootstrap.py:250-400`): early CLI (no Qt, no NeMo)
  -> shared data lease (failure: stderr and a critical box "Could not safely open application
  data: <exc> ...", exit 1) -> logging -> single-instance check (hand-off creates no
  `QApplication` or widget) -> `QApplication` -> splash -> settings migrations
  (`seed_new_install_settings`, `keep_unchosen_engine`) -> features -> splash destroyed ->
  main window shown -> activation callback attached -> keyring warning -> `startup_to_window_s`
  metric -> profiler summary -> "Application initialization complete" -> "Starting event loop".
  Profiler marks keep Python's names (`main_entered` .. `main_window_shown`).
- Instance release happens in `finally` before the shutdown steps, so a new launch can take over
  during cleanup (`bootstrap.py:395-453`); each cleanup failure is logged and never aborts the
  rest.
- `instanceKey` = SHA-256 of `normcase(realpath(abspath(data_root)))` UTF-8, first 16 hex
  (`ui_instance.py:30-33`); on Windows `normcase` lower-cases and turns `/` into `\`. Server name
  `<identity().instance_key_prefix>-<key>`; client writes `show\n` with a 0.4 s connect timeout,
  retries every 50 ms for 2.0 s. A holder of the lock that never answers still blocks a second
  copy (`test_lock_holder_without_a_socket_blocks_a_second_copy`): never remove a lock whose
  owner process is alive; `QLockFile::setStaleLockTime(0)`.
- A show request arriving before `attach_activate` is replayed on attach (`ui_instance.py:82-89`).
- Title bar (`main_window.py:165-348`): set its stylesheet before creating children (avoids
  "Could not parse stylesheet"); height `max(32, menu bar sizeHint + frame)` re-synced on every
  `LayoutRequest`; buttons 46 px wide; glyphs are painted, 10 px box at whole pixel + 0.5,
  1.0 px flat-cap pen; maximize toggles keep `_normal_geometry` and call `showNormal()` before
  `setGeometry`; accessible names "Minimize window", "Maximize window"/"Restore window",
  "Close window".
- Menus: Qt rewrites an action named "Settings" to "Preferences" unless its role is `NoRole`
  (`main_window.py:963-965`); Windows says "Exit" with Ctrl+Q; the native `menuBar()` is hidden.
- Footer (`main_window.py:893-957`): fixed height 48, margins 16,7,16,7, buttons 34 high,
  10 px gaps, `trayButton` is an a02 `Button` (minimum 140), the others plain `QPushButton`s with
  widget-local token sheets through `setLocalStyleSheet`; Quit carries
  `HotkeyHintFilter(quit, "Ctrl+Q")`.
- Close: hide to tray when `minimize_tray` reads true (true on a read error) and a tray exists,
  else quit; flush the tab bar's pending save first (`main_window.py:2077-2102`).
- Geometry: save debounced 500 ms, never before the first show, never while maximized or
  minimized; restore accepts any screen intersecting the saved rect (primary first) and clamps;
  widths up to 680 and legacy expanded widths normalize to 680 (`main_window.py:2275-2406`);
  fallback screen 1280x800.
- Edge resize: 8 px margin, left and top edges clamp to min and max so the window does not slide
  (`main_window.py:2128-2247`); dragging an edge of a maximized window leaves maximized in place.
- Splash: 450x300, frameless, stay-on-top tool window, translucent; phase from the wall clock
  (`elapsed * 4.5`) on a 33 ms `Qt::PreciseTimer`; text "OpenWhisper_CPP" from `identity().product`.
- `restore_from_tray`: clear minimized, set active, `showNormal`/`show`, sync the title bar's
  maximize state, raise, activate (`main_window.py:1758-1783`).
- The bench keeps CLAUDE.md's rule: the `Recognizer` is touched only on `EngineWorker`'s thread
  through queued signals. Its runtime directory reads and writes `fv_runtime_dir`; model path and
  device default from `OPENWHISPER_CPP_MODEL` and the CPU; QSettings `engine/*` is no longer used
  (architecture 7.2).
- `--diagnostics` with a missing path prints usage and exits 2; with an existing file it fails
  (a friendly message is an allowed gain, A01-68).
- Never call `FreeLibrary` on the runtime at exit (CLAUDE.md); the bench's thread is stopped and
  joined, the runtime stays loaded.
