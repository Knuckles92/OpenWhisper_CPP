## Overview

M2 makes FioriVoce an everyday dictation app around the M1 chain. Dictation gains a live preview
(windowed Parakeet decodes of the active recording, shown in the overlay and in Quick Record) and
incremental decoding of long recordings, so a 3-minute dictation pastes about as fast as a
10-second one. The Upload File tab transcribes one file or a queue, locally or through a cloud
speech endpoint (OpenAI, Groq or an OpenAI-compatible server the user runs), with a progress
panel, a reading window and per-file results. History grows a calendar, an exporter and the Stats
window. Settings arrives: the shell with its rail, search palette and Home, and the General,
Recording, Appearance, Hotkeys, API keys, Developer options, Voice model and Downloads pages.
Downloads installs the CUDA runtime and speech models with consent, verification and progress.
The overlay gets its other nine looks, the live-preview header and footer layouts and the
language chip; hotkeys gain mouse side buttons and capture fields; the Scratchpad, the
microphone check and the first-run guided setup complete the milestone.

**Demo (architecture section 11):** live preview while dictating; long incremental dictation;
batch upload locally and through Groq; calendar, export and Stats; download the CUDA runtime and
a model from Downloads; first-run guided setup.

## Rules for every M2 package

The rules of `M1.md` ("Rules for every M1 package") apply unchanged: binding names, verbatim
user-visible strings with "OpenWhisper" in copy replaced by `identity().product`,
function-level `PARITY.json` entries (only the functions a package's section names, plus its
`dropped` ones; at most 10 % of in-scope functions `pending`), one case file per Python module
(`tools/parity/cases/<python.module>.py`; a package that extends a case file another package
created appends cases, never rewrites them), one builder per area
(`tools/parity/builders/aNN.py`, extended, never rewritten), tree-only references for frames that
depend on Python's `random`, events through `base/events.h`, WSL clang-format, section 9.5 gates.
In addition:

- **Settings pages are registered, never hard-wired.** Every page goes through
  `ctx.settingsPages().addPage(...)` with the destination key of `appkit/destinations.h`; the
  shell lists only registered pages, in the rail order of `destinations::rail`, and hides a
  chapter with no registered page. M2 registers Home, Recording, Voice model, Downloads, General,
  Appearance, Hotkeys, API keys and Developer options; later milestones add theirs the same way.
- **Feature presenters live in their features.** Architecture 8.5's presenters are built by the
  feature that owns the widgets (`UploadPresenter` in `fv_ui_record`, `DownloadsPresenter` in
  `fv_ui_downloads`, the guided-setup offer in `fv_ui_setup`, the Stats links in
  `fv_ui_history`, the Settings opener in `fv_ui_settings`). They reach runtimes with
  `ctx.service<T>()` in `install()`; the runtimes are constructed in
  `ControllerFeature::provide` (M1.16, extended by M2.28). A presenter's tests construct the
  runtime over fakes directly.
- **Workers never hold a widget** (architecture 4 rule 3). Every background read in a page or
  dialog (device lists, model scans, key checks, file previews, calendar months, stats, exports,
  scratchpad saves) delivers through `qt::TokenGate` or `qt::post` with a generation, and each
  such Python test ("closed mid-scan is not held by the worker") is ported.
- **Dropped engines stay dropped.** Every Whisper, Moonshine, Qwen, MLX, Parakeet Unified and
  Nemotron branch is left out and its tests recorded `dropped` with the reason; copy that lists
  engines names only Parakeet (and the API and Remote backends where Python names them).
- **Interactive tests** (mouse hook, global capture, microphone check on a real device, overlay
  clicks on the real window) are tagged `[interactive]`, written and not run (amendment 14); the
  package proves the behaviour through `FakeMouseHook`, `FakeKeyboardHook`, `audio::FakeBackend`
  and offscreen widgets. Clipboard writes are desktop takeovers too: the Copy actions of the
  Upload tab, the reading window and the Scratchpad reach M1.16's clipboard service, and their
  tests run it over `focus/testing/fake_clipboard.h` (`ClipboardPort`), never the real clipboard.
  Hotkey capture in widget tests goes through M2.6's `hotkeys/testing/fake_capture.h`; the
  real-hook capture test is M2.6's `[interactive]` one.

## Changes to the cut

Section 11 has no M2 table; the cut below is new. What it changes against the architecture and
earlier specs:

1. **28 packages in 5 waves.** Directories with more than one M2 owner change owner between
   waves only: `src/speech` (M2.4 wave 1, M2.9 wave 2), `src/models` (M2.5, M2.10),
   `src/dictation` (M2.3 wave 1, M2.16 wave 2, M2.18 wave 3), `src/ui_widgets` (M2.1, M2.15),
   `src/ui_settings` (M2.11, M2.19, M2.24), `src/ui_downloads` (M2.13, M2.20, M2.23),
   `src/ui_record` (M2.14, M2.21, M2.25), `src/ui_history` (M2.22, M2.27).
2. **The Hotkeys page is built in `fv_ui_hotkeys`** (M2.17, wave 2) behind its own
   `HotkeysPageHost` interface, and registered by `fv_ui_settings` (M2.19). Section 2.3 lists
   only "Hotkeys page rows" there; the page needs nothing of the shell beyond a message line and
   a capture-suspend call, and building it in wave 2 lets Home (wave 4) project into it.
3. **a11's pure logic is in `fv_appcore`** (M2.2) as section 2.4 says; the composite widgets'
   layout maths (button rows, segmented bars, flow layout) stay as Qt-free functions in
   `fv_ui_widgets` (`ui_widgets/layout_math.h`) because `src/uimath` belongs to M2.7 in wave 1.
4. **`audio_processor.py` is split:** the file preview goes to `fv_audio` (M2.3, used by Upload),
   the silence-aware splitter to `fv_speech` (M2.4, used only by `CloudSpeechBackend`).
5. **The cloud endpoints come early.** a12's `speech_endpoints.py` (A12-46, A12-78) and a13's
   `SpeechServerControls`, `SpeechServerDialog` and backend labels (A13-52, A13-53, A13-54) are
   ported with the cloud backend (M2.4, M2.15), ahead of the rest of a12 and a13 (M4).
6. **The staged Settings build is dropped** (A11-10, A03-62, six tests of
   `test_settings_unified.py`): architecture 8.5 keeps pages lazy and drops the idle builder.
7. **Feature presenters move out of `fv_ui_controller`** (rule above); M2.28 keeps the
   `OverlayRouter` branches, the `ApplicationController` construction, the backend table entry
   `api` and the Settings bindings.
8. **Scratchpad transforms (A08-56, A08-70) wait for M4** with the rest of the transforms
   (section 11 puts transforms in M4); M2.25 builds the "Transform" button and a menu-fill hook
   that shows "No transforms yet".
9. **Home rows that belong to later pages are contributed by those pages.** Python builds the
   cleanup rows of the Dictation card and the Meetings card inline in `settings_home.py`; here
   the AI cleanup page (M4) and the meeting pages (M7) contribute them through the `HomeRows`
   hook M2.24 defines, the way Personalize modules already do (`home_rows`).
10. **Guided setup's Clean up step is partial in M2** (lead decision 6): the switch, the level
    tiles and the example write `transcript_cleanup_enabled` and `transcript_cleanup_level`
    through a `CleanupChoices` port; the provider row and privacy text arrive with M4.
11. **The API keys page lists the speech-endpoint credentials only** until M4 adds the text-LLM
    owners and M8 the TypeSafe row; its "Test" button checks a speech-endpoint key with M2.4's
    `verify_endpoint_key` (lead decision 5).
12. **No Runtime page** (A15-41 dropped, lead decision 3): the `runtime` destination is not
    registered, so the rail shows Downloads alone under "Models & storage" until M3 adds Backup.

No lead-owned frozen file needs a change for M2: every settings key M2 reads is already in
`settings/keys.inc` (including `guided_setup_state`, `whats_new_seen`, `streaming_overlay_*`,
`recording_overlay_*`, `api_transcription_*`, `transcript_batch_*`, `scratchpad_*`,
`hf_access_policy`, `developer_mode`, `recording_hands_free_latch`), every destination is in
`appkit/destinations.h`, every menu and tray position in `appkit/order.h`, and every dynamic
property the theme keys on (`searchHit`, `iconTone`, `stepState`, `framed`, `scratchpadAction`,
`headed`, `available`, `dot`, `capturing`, `tone`, `kind`, `selected`, `active`, `muted`,
`overlay`, `checked`, `nested`, `group`, `backupCard`) in `ui_theme/style_props.h`.

### Traps

- `FieldHelp` opens after 450 ms hover or Space/Enter, closes when the pointer is outside caption
  and card plus 8 px slop (200 ms poll), on Esc and on card deactivation; the card needs the
  double `move()` on Windows (`field_help.py:118-120`); width `min(round(360*scale), max(160,
  screen width))`, flips above when it would pass the screen bottom.
- `ButtonRow` relayouts on a 0 ms single shot after LayoutRequest/FontChange/StyleChange and
  caches the shape; buttons are reparented at construction; size policy Ignored x Preferred.
- `SegmentedBar`: `cell = max(natural widths)`, `fits = max(1, min(n, room // (cell + gap)))`,
  balanced columns `ceil(n / ceil(n / fits))`; `activated` only from a person's click, never from
  `setCurrentIndex` (Settings relies on it so loading never saves).
- `SearchableComboBox` routes keys through event filters on the line edit, the popup container
  and the list view, installed the first time the popup shows; the first keystroke after opening
  replaces the text; Ctrl+A/C/V/X/Y/Z and editing keys go to the editor
  (`searchable_combo.py:209-221` for the platform activation difference).
- `NavRail` overrides `updateGeometries`/`scrollContentsBy` so row widgets follow scrolling
  (zero deltas passed to the base); a closed chapter's row grows when its first value arrives
  (invalidate, activate, `setSizeHint`); dragging never selects a heading.
- Tiles: icon 20 px, body indented 32 px (icon + 12), margins (14,12,14,12), spacing 10;
  `kind` and `checked` are dynamic properties set only through `setStyleProperty`.

  +1 sample look-ahead avoids an overlap-only tail, memory bounded to one window
  (`audio_processor.py:216-294`); cancel raises "Transcription canceled".
- `decode()` blocks `fv-speech` while it waits for the uploads, as Python blocked its job; the
  uploads themselves never run on `fv-speech` or the GUI thread.

  (`_dismiss_streaming_preview_for_waveform`).
- An upload job's overlay states go to the Upload card and the overlay stays out of them, except
  `NONE`, which the card receives and the shared teardown still runs (`ui_controller.py:937-959`).
- A Settings toggle of live preview refreshes both tabs first, then reconfigures streaming; the
  tab toggle reconfigures directly; `clear_transcription_stats` must not build the Upload screen.
- The font-scale change redraws the Markdown of Quick Record, Upload and the reading window; a
  theme change redraws only when `ThemeManager` reports a change.
- Construction order follows Python (`application_controller.py:165-275`): runtimes before
  callbacks, the backend table before the first load; the `api` backend never loads a local model
  and readiness says "The selected API transcription engine needs a valid API key" when no key
  resolves.
- Runtime objects are Qt-free UI actors; nothing here calls a `Recognizer` or blocks the GUI

## Risks

- `src/ui_settings` passes through three packages in three waves; the shell's contract
  (M2.11) must be right first time, or M2.19 and M2.24 report differences instead of fixing them.
- Home's projection into other pages depends on control names registered by four packages; a
  missing name shows as a Home row that does nothing. M2.24's tests cover every projected row.
- Bit-exact incremental decoding needs the live tape path and the file path to share
  `Resampler16k` and `WindowSplitter`; any divergence silently falls back to the file decode
  (correct but slow). M2.9's decode test compares windows, not only texts.
- The preview lane and the final pass share one `Recognizer`; on CPU-only machines previews may
  fall behind. Coalescing keeps only the newest window; M2.18 never waits for a preview at stop.
- Python's `random` streams (fish, Fizz, sample voice) cannot be reproduced; those looks are
  tree-only and tested by thresholds.
- `test_upload_file_tab.py` (120 functions) and `test_settings_downloads.py` (86) are the largest
  ports of the milestone; their fixtures (fake runtimes, fake previews) must stay faithful or the
  tests pass for the wrong reasons.
- Cloud tests run against recorded replies only; the `[platform]` Groq test needs a key the lead
  provides.
- Downloads of the CUDA runtime stage a switch that applies at the next start (architecture 5.7);
  the demo must restart FioriVoce to show the GPU runtime loaded.
