# M7 Meetings: package specs

## Overview

Architecture section 11: **M7 Meetings**, areas a24 (meeting engine), a25 (microphone and WASAPI
loopback capture, meeting ASR, diarization), a28 (meeting state, persistence, exports), a30 (the
dashboard server; the React webui is reused), a31 (the meeting Qt UI), the meeting runtime of a04,
and the transcript-only parts of a29.

**Demo.** Start a meeting from the Meeting Mode tab: the microphone is "Me", system audio
(native WASAPI loopback) is "Others". The browser opens the live dashboard (OpenWhisper's React
bundle served by `openwhisper-cpp.exe` on 127.0.0.1); with "Share on local network" a guest's phone
opens the guest link, enters a name and sees live captions (decoded Parakeet windows) and the
transcript. Others are split into "Speaker 1..N" by WeSpeaker embeddings and online clustering.
End: the finalization card runs Audio Re-transcription (when on) and State Finalization; the
meeting exports to Markdown, JSON and TXT. Kill the process during a meeting: the next start
offers Recover Interrupted Meetings; Finalize transcribes the spooled audio. Past Meetings lists,
searches, copies, deletes and re-opens meetings in the archive dashboard.

Meetings are **transcript-only in M7**. The meeting AI (live insights, polish, the final report,
custom reports, insight review, live signals, voice commands, the backup agent) is M8's native
in-process agent loop. M7 leaves these seams for it, all with null implementations in M7:
`meeting::IntelligenceProvider` (agent cores, polish, consolidation, re-run insights),
`meeting_web::DashboardExtensions` (the report, review, note and cloud routes), the AI panel of
the tab (`MeetingModeTab::setAiInsightsAvailable(false)` in M7), and the consent step of the
runtime (`MeetingRuntime::set_consent_gate`). A meeting started in M7 is saved with
`cloud_enabled` false and its finalization reads "AI insights are off for this meeting."

The workers prove every step with `audio::FakeBackend`, `speech::FakeBackend`, a fake embedding
model and servers bound to 127.0.0.1 on an ephemeral port. Opening a real microphone or loopback
endpoint, playing sound, showing windows on the owner's screen, opening the browser and serving
on a non-loopback address are `[interactive]` tests: written, never run by a worker (lead
amendment 14). The demo is run by the owner.

### How the dashboard bundle reaches the tree and the installer

OpenWhisper's checkout commits the built dashboard: `webui/dist/` (`index.html`,
`assets/index-BqkSL9Ir.js` 361 KB, `assets/index--F1caWmT.css` 158 KB, 12 DM Sans and Instrument
Serif `woff`/`woff2` files, `licenses/` with two OFL texts; `.gitignore:85` says "webui/dist IS
committed — OpenWhisper.spec bundles it"). The source (`webui/src`, 818 KB of TSX and CSS,
`package.json`, `package-lock.json`, `vite.config.ts`, `tsconfig.json`, `index.html`,
`public/licenses`, `tests/*.cjs` (22 node tests), `scripts/*.cjs`) needs Node, npm and the npm
registry (`npm ci`, then `tsc --noEmit && vite build`) to rebuild. Node 24.15 is installed on this
machine, but `npm ci` downloads packages, which no worker does.

The built bundle carries OpenWhisper's name in four places: the page title
`OpenWhisper · Meeting` (`index.html`), the header brand (`OpenWhisper`, `OpenWhisper <em>M…`),
the storage keys `openwhisper.meeting.theme`, `openwhisper.meeting.design`,
`openwhisper.pocketTab`, and two help strings naming `openwhisper.log` and
`%LOCALAPPDATA%\OpenWhisper`. The keys `ow_meeting_guest_id` and `ow_report_view` are not brand
words and stay.

M7.6 vendors the source and the built bundle and rebrands **both by a deterministic text
substitution** (`tools/webui/rebrand.py`, a fixed map of exact literals, applied to the source
files and to the built `dist` files, refusing to run when any literal is missing or matches more
than the expected count). No Node runs at build time or at run time. `webui/dist.sha256` records
the hash of every served file; M7.16's test fails when `dist` drifts from it. Rebuilding the
bundle from the rebranded source with Node is an optional owner step (lead decision 1), after
which `rebrand.py --manifest` rewrites the hash list. The root build copies `webui/dist` next to
the executables and M3's staging script copies it into the install folder (lead decision 1,
frozen-file change).

### The request (default_transcribe, cloud_pass.py:301-325)

`POST {base}/audio/transcriptions` with `Authorization: Bearer <key>`, `Accept: application/json`
and `User-Agent` as `OpenAiCompatClient` sends it. The multipart fields go in this order (the SDK's
body order with the file extracted, `array_format="brackets"`, files after data): `model`
(`gpt-4o-transcribe-diarize`), `chunking_strategy` (`auto`), `known_speaker_names[]` once per
name, `known_speaker_references[]` once per clip, `response_format` (`diarized_json`), then `file`
with filename `loopback.<ext>` and the format's content type. Empty strings are dropped from the
two known-speaker lists first. The lists are sent only when both are non-empty and of equal
length. The pass passes `names or None`, so an empty list is the same as none.

Timeouts and retries are the SDK's defaults (`OpenAI(api_key=...)`, `DiarizeLimits`): connect 5 s,
600 s for each wait, and 2 retries. A retry follows a connection failure, a timeout, 408, 409,
429 and 5xx, or whatever `x-should-retry` says. It waits `retry-after-ms`/`retry-after` when that
is up to 120 s, else min(0.5 * 2^n, 8) s times 1 - 0.25 * random. Error texts are the SDK's
(`ApiError::what()`): "Error code: {status} - {repr of the JSON body}", "Connection error.",
"Request timed out.". The answer is parsed by `parse_diarized_result`. A new client is built for
each window, as Python builds one.

### What differs from OpenWhisper, and why

1. **Upload encoding (lead amendment 19).** OpenWhisper uploads MP3 (libmp3lame, 32 kb/s,
   `loopback.mp3`, `audio/mpeg`, clips `data:audio/mpeg;base64,`). OpenWhisper_CPP's FFmpeg has no MP3
   encoder and no library may be added. The upload is therefore AAC-LC, mono, at the session's
   16 kHz and 32 kb/s, in M4A (the `ipod` muxer): `loopback.m4a`, `audio/mp4`, clips
   `data:audio/mp4;base64,`. When `upload_format()` finds no AAC encoder or M4A muxer, it is FLAC
   (`loopback.flac`, `audio/flac`, `data:audio/flac;base64,`), and windows are planned with
   16 × rate b/s, so a window holds about 10.4 min instead of 83 min. With neither, the pass fails
   with `kNoUploadEncoderMessage`, the only new sentence. That cannot happen with the vcpkg
   FFmpeg, whose portfile disables no native encoder.
2. **The key is not part of the gate** (M7.9's contract, forced). The gate asks whether a key is
   present, and the pass reads the key again when it runs, on its worker. If the key is removed
   in between, the pass becomes a skipped refusal with "No OpenAI API key is configured.", where
   Python would upload with the key it read first.
3. **Key lookups never on the GUI thread** (amendment 15, forced). The desktop retry's speaker
   refusal check is posted to the `meeting` strand between the backup check and the claim. What
   the user sees is Python's: the reason on the status line, and no retry.
4. **The request** inherits `OpenAiCompatClient`'s recorded differences (open items): no
   `OPENAI_BASE_URL`, organisation or project variables, no `X-Stainless-*` headers or idempotency
   key, and `OpenWhisper_CPP/<version>` as the User-Agent.
5. **Shutdown** cancels a request in flight through the engine's token (Python's daemon thread
   dies with the process). The step's "canceled" is replaced by the interrupted finalization
   M7.17 writes at shutdown.
6. **An injected decoder that answers something other than an array** (only a test fake can) makes
   `turns_on_meeting_clock` throw `std::invalid_argument("diarize answer is not a list")`. Python
   raises whatever indexing `None` or a dict raises there (`TypeError`, `KeyError: 0`). Both escape
   the pass and `run_speaker_pass` reports them; only the text differs.

### Traps

- Python dict order is behaviour. `speaker_segments`, `all_assignments`, the mappings and
  `named_map` are insertion-ordered: use vectors of pairs, not `std::map`.
  - `all_assignments` is overwritten by a later window, but the earlier speaker keeps the segment
    in `speaker_segments`.
  - `next_references` votes with duplicates (`list(ids)`), the final map without them
    (`dict.fromkeys`).
  - The final map uses the last window's `named_map`, anchors included (cloud_pass.py:533-545).
- `resolve_speaker_participants`: the winner is `max((count, pid))`, so a tie goes to the larger
  id. Pending speakers sort by `(-count, -len(ids), speaker)`.
- Anchors (`_anchor_clips_from_window`):
  - The duration of a speaker sums `_row_duration` over `dict(speaker_segments)`, which keeps
    duplicate ids, so a segment counts once per window that assigned it (cloud_pass.py:389-395,
    754).
  - Anchors sort `(duration, speaker)` descending and are capped at 4 there, before
    `_merge_anchor_references` caps the total at 4.
  - `_longest_row` keeps the first of equal durations. `_longest_reference_row` takes Python's
    `max` (the first maximal) over unpinned rows, and over all rows when every one is pinned.
- `turns_on_meeting_clock` has two paths (cloud_pass.py:447-464):
  - An empty array gives `[]`.
  - When the first item is not an object, the array goes through
    `parse_diarized_result({segments: raw})`, where `str(speaker)` is Python's repr (`0`, `1.0`,
    `True`) and a null field skips the item.
  - When the first item is an object, every object item is taken as is and non-object items are
    skipped. Its speaker is `py_str(speaker or "")` stripped, so a numeric 0 or `false` becomes
    "" and `_usable_turns` drops it later. Its `start`/`end` follow `float()`
    (`py::py_float`): a missing key, null or non-numeric text skips the turn; numeric text and
    booleans convert.
- `round()` is half-to-even (`fv_pyport`) in `plan_windows` and `clip_sample_range`, while `int()`
  truncates in the estimate.
- `known_clips = named_refs[:len(known_names)]`, and a clip that fails to encode drops its slug
  (cloud_pass.py:684-698). A segment with a non-numeric time is skipped, not an error.
- Numbering new participants (`_create_missing_participants`, cloud_pass.py:625-644):
  1. `existing` is the participants' display names from `with_state`, in the store's insertion
     order.
  2. `n` starts at 1 and skips taken names once, before the loop.
  3. For each unmapped speaker in map order, create "Speaker {n}". On success, add the name to
     `existing` and do `n += 1` with no further skip, so a later number may repeat an existing
     name. On failure (an `upsert_participant` result without `ok` or without an effect), log
     "Cloud speaker pass could not create {name}" and keep `n`.
- AAC:
  - The native `aac` encoder takes `fltp` (convert s16 / 32768) in frames of 1,024 samples. The
    last frame is padded with silence only through the encoder's flush.
  - Set `AV_CODEC_FLAG_GLOBAL_HEADER` for the muxer. The muxer's edit list keeps the
    1,024-sample priming out of the timeline.
  - The `ipod` and `flac` muxers seek back to patch sizes, so the in-memory `AVIOContext` needs
    write and seek callbacks over a growable buffer.
  - Free every FFmpeg object on every path.
- A decoder that throws is not retried by the pass; only the HTTP layer retries, as the SDK
  does. `llm::RequestCanceled` is a failure like any other (`what()` "canceled").
- `CredentialStore` asserts it is off the GUI thread, so `key_check()` and `run()` never run on
  `ctx.ui()` or in a widget. The page's consent read is a settings read, not a key read.
- The Speakers combo is filled once per page build. On the shutdown day the OpenAI item is gone
  and a stored `openai` shows On-device (the resolver), as in Python.
