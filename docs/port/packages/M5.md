# M5 Automation, agents and MCP: work packages

Binding scope of packages M5.1 to M5.22 (architecture amendment 7). Names of targets,
directories, classes and headers come from `docs/port/ARCHITECTURE.md` and the tree; where this
spec places something elsewhere, "Changes to the cut" says so and why. Python paths are relative
to `D:\coding\whisper_local` (OpenWhisper 2.8.92, commit `768b559edd93`). Area maps are in
`docs/port/map/`. M0, M1, M2, M3 and M4 are assumed complete as their spec files describe them
(`M4.md`: fv_text, fv_llm, text AI, personalization, Command Mode); "What M5 needs from M4"
lists every M4 contract a package here consumes and the M4 package that provides it. Where a merged header
differs from what this spec names, the package follows the header and says so in its report
(amendment 12).

## Overview

M5 ports a19 (actions, Route by voice, the event bus, signed webhooks, program hooks, text
filters, the live HTTP API with server-sent events, the Claude Code channel), a20 (the headless
History API, the in-app MCP server with its tools, permissions and agent controls, MCP Events,
installed coding agents and process-tree ownership) and a21 (the Actions, Hooks and API & MCP
Settings pages and the agent picker). It also implements three contract libraries that M0 left as
headers: `fv_process` (child processes owned by a job object, the user's environment for
children, links and terminals), `fv_net` (the one HTTP server, with SSE) and the `--api` and
`--channel` modes of `openwhisper-cpp-cli`. Route by voice cannot work without a judge, so the Fast
judgments judge of a12 and its Settings page move here from M8 (change 6).

**Demo (section 11):** "Route by voice to a webhook; hooks; live API with SSE; Claude Code reads
history over MCP and the channel; `openwhisper-cpp-cli --api`." Concretely, run by the owner on this
machine (it signs in to Claude Code and may spend the owner's credit, so no worker runs it):

1. `py -3.12 tools\automation\demo_webhook_receiver.py --port 8899 --secret-file
   out\demo\secret.txt` listens on 127.0.0.1 and prints every request whose Standard Webhooks
   signature verifies (M5.22). In Settings > Automate > Actions, "Add action" > "Webhook" with
   address `http://127.0.0.1:8899/hook`, spoken name "Home", saved; "Copy secret" is pasted into
   the secret file. Settings > Meeting Mode > Fast judgments: "Your text model" with a local
   server, or TypeSafe with the owner's key; Actions: Route by voice on, a Route by voice shortcut
   set. Pressing the shortcut and saying "Home, turn on the porch light" prints a signed
   `{"v":1,"action":{"id":...,"name":"Webhook"},"text":"Turn on the porch light",...}`; the
   status reads "Webhook · working…" then "Sent to Webhook — nothing came back".
2. Settings > Automate > Hooks: a webhook for "Finished dictations" receives
   `transcription.completed`; a program hook (`openwhisper-cpp-cli --version` stands in) shows
   "Exit 0 · N ms" after "Run test"; a text filter on `http://127.0.0.1:8899/filter` rewrites
   dictated words.
3. Settings > Automate > API & MCP: Enable MCP shows "Running · Keep OpenWhisper_CPP open."; "Copy a
   curl example" gives `curl -N -H "Authorization: Bearer <token>"
   http://127.0.0.1:8767/v1/events`, which prints `retry: 2000`, then `id:/event:/data:` frames
   for each dictation and `: ping` every 15 s.
4. The "Claude Code" setup command adds the MCP server; Claude Code lists OpenWhisper_CPP's 22 tools
   and answers "what did I dictate about the porch light?" through `search_history`. The ".mcp.json
   entry" and "claude --dangerously-load-development-channels server:openwhisper-cpp" start a channel
   session; a "Tell my Claude Code session" action delivers dictated words as
   `<channel source="openwhisper-cpp" origin="dictated" ...>`, and Claude's `reply` tool shows a notice
   near the pointer.
5. `set OPENWHISPER_CPP_API_TOKEN=<32+ chars>` and `openwhisper-cpp-cli --api --port 8766` serve the
   read-only History API with the app closed; `curl -H "Authorization: Bearer ..."
   http://127.0.0.1:8766/v1/transcriptions` lists the dictations.

**Rules that apply to every package below** (M0.md's to M3.md's rules, unchanged, plus these):

- A package changes only what its `Owns` line lists, plus its own `tests/<dir>/PARITY.json`
  entries, its case files `tools/parity/cases/<python.module>.py`, its transcript scenario files
  `tools/parity/transcripts/<name>.py`, its builder file and its `tests/golden/`,
  `tests/fixtures/transcripts/` and `tests/reference/<widget>/` entries.
- Function-level PARITY as in M1.md: each package lists the functions its "Tests to port" names
  (`ported`, `golden`, `dropped`, `other-platform`, or at most 10 % of its own scope `pending`
  with a reason and a finishing package).
- Qt-free code keeps Python's names in snake_case; Qt classes use camelCase (section 8.3); every
  class states its affinity. User-visible strings are copied verbatim from the cited Python line;
  "OpenWhisper" in copy becomes `identity().product`. Qt code writes `Q_SIGNALS`, `Q_SLOTS` and
  `Q_EMIT` (amendment 17).
- **Naming on the wire** (lead decision 2): paths, methods, query and body fields, JSON shapes and
  key order, status codes, error codes, JSON-RPC methods and error numbers, MCP tool names and
  schemas, event types and payloads, SSE framing and Standard Webhooks signing are OpenWhisper's,
  byte for byte, so existing clients and MCP configurations work after the executable name
  changes. Product names inside them come from `identity()`: the MCP `serverInfo`, the OpenAPI
  title, `User-Agent: OpenWhisper_CPP/<version>` (`http::user_agent()`), copy. Environment variables and
  credential names use `identity().env_prefix` (`OPENWHISPER_CPP_API_TOKEN`, `OPENWHISPER_CPP_URL`,
  `OPENWHISPER_CPP_TOKEN`, `OPENWHISPER_CPP_MCP_TOKEN`, `OPENWHISPER_CPP_ACTION_SECRET_<id>`,
  `OPENWHISPER_CPP_WEBHOOK_SECRET_<id>`, `OPENWHISPER_CPP_MCP_EVENT_SECRET_<id>`), matching M3's import, which
  renames `OPENWHISPER_` credentials to `OPENWHISPER_CPP_`. Where a user's own script or launcher reads
  or sets a variable (`--api`'s token, the channel's URL and token, program hooks' and program
  actions' `*_EVENT_*` and `*_ACTION_*` variables), the legacy name built from
  `legacy_identity().env_prefix` is also honoured (read as a fallback, or set beside the new
  one). The header `X-OpenWhisper_CPP-Client` is sent; `X-OpenWhisper-Client` (built from
  `legacy_identity().product`) is accepted too. No C++ string literal spells "openwhisper"
  (`lint.brand`).
- **Nothing a test does reaches beyond this machine or spends the owner's credit.** Servers in
  tests bind `127.0.0.1` on an ephemeral port (`Listen{.port = 0}`); HTTP goes to a loopback
  server the test starts; agent CLIs, `tailscale` and terminals are fake executables the test
  builds (`tests/process/child/`, `tests/agents/fake_agent/`) and puts first on a temporary
  `PATH`; `HOME`/`USERPROFILE`, `APPDATA`, `LOCALAPPDATA`, `CLAUDE_CONFIG_DIR`, `CODEX_HOME` and
  `XDG_CONFIG_HOME` point into the test's temporary folder, so no test reads or writes the
  owner's real Claude Code, Codex or OpenCode configuration. Opening a link through Explorer,
  opening a terminal, registering a URL scheme, writing the real clipboard and anything else that
  takes over the desktop is `[interactive]`, written and not run (amendment 14); child-process,
  file, loopback-socket and Credential-Manager-under-a-test-service tests are `[platform]` and
  run.
- **Protocol vectors.** HTTP and JSON-RPC parity is pinned by transcripts recorded from
  OpenWhisper's own FastAPI apps and channel server through `tools/parity/record_transcripts.py`
  (M5.5 writes it): each scenario file `tools/parity/transcripts/<name>.py` builds the Python app
  in-process under `ow_isolation.py` against a fixture database and fakes, sends requests through
  Starlette's `TestClient` (no socket) and writes `tests/fixtures/transcripts/<name>.json`
  (`[{request: {method, path, query, headers, body}, response: {status, headers, body}}]`, with
  volatile values named in a `"normalize"` list). The C++ replay feeds each request to the pure
  handler and compares after the rebrand map of `fv_golden`.
- Format with `wsl clang-format --dry-run -Werror` (amendment 3); Python under `tools/` follows the
  existing tools' style.

## Changes to the cut

Section 11 gives M5 no package table; these choices are this spec's.

1. **`fv_process` holds launching as well as the launcher.** `services/actions/launch.py` (links,
   URL handlers, terminals), `programs.run_once`, `services/process_env.py` and
   `services/agent_process.py` go to `src/process` (M5.1): both `fv_agents` (handoff, probes) and
   `fv_automation` (programs, link actions) need them, and `fv_agents` cannot depend on
   `fv_automation`.
2. **Agent actions live in `fv_agents`.** `services/actions/agents.py` (handoff and the headless
   "ask") is `agents/agent_actions.*` (M5.7), beside the installed-agent scanner and a26's ACP
   client (`meeting/agent/installed/acp.py`, ported here for the OpenCode ask and model lists;
   M8 reuses it).
3. **The live API and AppControl marshalling live in `fv_agentapi`.** `services/automation/api.py`
   and the Qt-free half of `app_control.py` are `agentapi/live_api.*` and `agentapi/app_control.*`
   (M5.16): the live router is served only by the in-app MCP listener (a20 map), and keeping them
   out of `src/automation` lets one package per wave own that directory across five waves.
4. **The channel bridge library stays in `fv_automation`** as section 2.3 says (M5.20);
   `openwhisper-cpp-cli --channel` and `--api` call it and `fv_agentapi`. `openwhisper-cpp.exe --api` and
   `--channel` start `openwhisper-cpp-cli.exe` from the same folder with the same arguments and
   inherited standard handles, and return its exit code (lead decision 6).
5. **`AgentPicker` and `AgentMark` live in `fv_ui_widgets`**, not `fv_ui_automation`: the picker
   is embedded by the AI cleanup page (M4's `fv_ui_personalize`, from M8) and the Meeting
   Intelligence page (M8's `fv_ui_meeting`), which should not have to link the Automate pages to
   get it (feature libraries may depend on each other, section 2.2, but these have no reason
   to). `AgentMark` lands with the action widgets (M5.10), the rest of the
   picker in M5.18.
6. **Fast judgments move from M8 to M5.** Route by voice is M5's demo and asks the Fast judgments
   judge: `services/typesafe.py` and `services/text_judge.py` (A12-40 to A12-45, A12-71 to
   A12-75) are ported in `fv_llm` by M5.4, and the Fast judgments Settings page (A31-44, A31-49
   to A31-51) and the TypeSafe credential owner of the API keys page by M5.19 in `fv_ui_settings`.
   The meeting features those pages switch on, `typesafe_meeting_runtime` and the A10-26 gates stay
   M8 (lead decision 1).
7. **`fv_automation` depends on `fv_dictation`**, because the action runtime, filters and catalog
   read `DictationJob`, `paste_target` and `history_fields`. `fv_dictation` therefore reaches
   automation only through a port it declares, `dictation/automation_port.h` (M5.14), which
   `fv_automation` implements (`automation::DictationAutomation`, M5.15). The open item
   "`RecordingAction` is a stand-in for `actions::Action`" closes this way: `RecordingAction` stays
   the pipeline's view of an action, filled by `automation::to_recording_action` (M5.3).
8. **catalog.py's job builders live in `fv_dictation`** (`dictation/event_payloads.*`, written by
   M5.3 in wave 1, wired by M5.14), so the runtime publishes `recording.*`, `transcription.*` and
   `history.saved` with catalog payloads without depending on `fv_automation`.
9. **Tailscale before M9.** The MCP server's Tailscale listener (A20-20) needs a17's
   `services/remote_asr/tailscale.py:1-222`: the pure part (address range, status parsing) is
   `net/tailscale.*` (M5.2), the CLI probe `agentapi/tailscale_probe.*` (M5.9). M9 reuses both.
10. **`fv_net` is implemented for HTTP and SSE only** (M5.2). `HttpServer::websocket`,
    `Responder::send_file`, TLS listeners, `ws_connect` and `generate_self_signed_p256` throw
    `std::logic_error` naming the milestone that implements them (WebSocket server and ranged
    files M7, WebSocket client and TLS M9).
11. **Paired-computer parts wait for M9:** federation (A20-16), `HostMcpControl` (A20-39), the
    host tab and history-sharing tile of the MCP page (A21-58, A21-80).
12. **A demo receiver** `tools/automation/demo_webhook_receiver.py` (M5.22) verifies Standard
    Webhooks signatures on 127.0.0.1 so the owner can watch step 1 and 2 of the demo.

### Traps

- Create suspended with `CREATE_SUSPENDED | CREATE_NO_WINDOW`, assign the job, then resume the
  primary thread (the handle `CreateProcessW` returns; Python had to find it with Toolhelp,
  `agent_process.py:51-94`). Any failure closes the job, which kills the child.
- Pass only the three pipe ends to the child (`STARTUPINFOEX` with
  `PROC_THREAD_ATTRIBUTE_HANDLE_LIST`); every other handle stays non-inheritable, or a second
  concurrent launch leaks its pipes into this child and a reader never sees EOF.
- After a clean exit `_disown` clears the job's limit with
  `SetInformationJobObject(JobObjectExtendedLimitInformation, zeroed)` so apps the program opened
  stay open (`programs.py:342-371`); after a timeout or cancel the tree is killed. Pipes then get
  1 s (clean exit) or 2 s (killed) before `CancelSynchronousIo`, retried until the reader leaves
  (`programs.py:290-313`), because a helper may hold an inherited handle forever.
- `run_once` keeps at most 1 MiB of stdout and discards stderr; stdin is written by its own
  thread so a program that never reads it cannot block (`test_run_once_survives_a_program_that_
  ignores_a_large_stdin`); the cwd defaults to the home folder; the timeout floor is 0.05 s;
  cancel is polled every 50 ms ("Canceled"). Start errors: "The program wasn't found.", "The
  program isn't allowed to run (permission denied).", "Windows can't run that file directly.
  Choose a program (.exe)." for error 193 (`programs.py:97-107`).
- Quote arguments exactly as `subprocess.list2cmdline` does; the Windows command line is limited
  to 32,000 characters for terminals ("That's too long to open in a terminal. Try a shorter
  request.").
- `external_env` matches names case-insensitively on Windows and drops a variable whose current
  value equals `.env`'s for that name, whatever case the file writes it in
  (`test_a_dotenv_key_is_dropped_whatever_case_the_file_writes_it_in`); OpenWhisper_CPP never loads
  `.env` into its own environment (M0.7), so `adopt_dotenv` runs once at startup and records the
  names whose value came from the file.
- Explorer-hosted ShellExecute runs on its own STA thread, serialized by a lock with no queue: a
  link that arrives while Explorer has not answered fails at once instead of opening twice later
  (`launch.py:233`, `273-302`); `AllowSetForegroundWindow(explorer pid)` first; a `NoAnswer` is
  never retried with the fallback (`os.startfile`) because the first call may still open it.
- Handler lookup asks `ASSOCSTR_DELEGATEEXECUTE` first, then `COMMAND`, then `EXECUTABLE`; the
  HRESULTs `0x80070483`, `0x80070490` and `CO_E_APPNOTFOUND` mean no handler; results are cached
  60 s on a monotonic clock (`launch.py:118-217`).
- `open_in_terminal` on Windows starts only an `.exe` in a new console and refuses `.cmd`,
  `.bat` and `.ps1` with "{name} is a script, and Windows would read your words as commands on
  the way in. ..." (`launch.py:448-473`).

### Traps

- Handlers run on the reactor and must not block it; `RouteOptions::run_on` posts the handler to
  an executor (the libraries pass their `io` strand), which is how Python's sync FastAPI handlers
  ran in a thread pool. A `Responder` may complete from that executor: post the write back to the
  connection's strand.
- SSE responses send headers at once, use chunked transfer, set `TCP_NODELAY`, and never wait for
  a buffer to fill; the live API's `: ping` every 15 s is the handler's, not the server's.
- On Windows bind with `SO_EXCLUSIVEADDRUSE` and never `SO_REUSEADDR` (a second process could
  otherwise share the MCP port, `runtime.py:99-116`); close every socket bound so far when a
  later `listen` of the same start fails (`test_tailscale_bind_failure_releases_loopback_socket`).
- `stop` must not wait on a handler blocked on the GUI thread (the AppControl waits up to 4 s):
  close the sockets, then let `grace` expire.
- `unmap_v4` and `strip_scope` before classifying a peer (`::ffff:127.0.0.1` and `fe80::1%3` are
  what Asio reports); `is_global` follows Python's `ipaddress.is_global`.

### Traps

- Matching is `lower(col) LIKE lower('%q%') ESCAPE '/'` with `%`, `_` and `/` escaped and the
  excerpt from `instr(lower(col), lower(q))`: ASCII-only folding, so "ÉTÉ" matches only itself

  stored timestamps are UTC; since/before must carry a timezone.
- Cursors: base64url with padding of `json.dumps({"scope": sha256(json.dumps(scope,

  number (`store.py:97-145`). Use `pyport` JSON for the exact bytes.
- Segment ranges compare each segment's `start_s` only (`start_s >= :start_s AND start_s <

  agent_endpoint_json, ...) are never selected (`_columns`); models drop unknown snapshot keys.

  constant time with a case-insensitive scheme; every response, errors included, carries
  `Cache-Control: no-store` and `X-Content-Type-Options: nosniff`; token in query or cookie is
  never accepted.
- FastAPI's 422 bodies are replaced by the custom envelope ("Invalid request parameters. See

### Traps

- One FIFO lane per webhook with its own worker, ending after 30 s idle; at most 500 queued
  (oldest dropped and recorded "Dropped: too many deliveries were waiting."); retries go back to
  the front with `not_before`, keeping order; `configure` drops lanes of removed or disabled hooks
  and queued items no longer wanted; `stop` waits at most 1 s for lanes (`webhooks.py:569-749`).
- One bus subscription for the union of enabled hooks' types, re-subscribed new-before-old on a
  change, de-duplicated by `seq > last_seq`.
- The secret is created on first delivery and never re-created for a deleted webhook; a damaged
  secret is "The signing secret is damaged. Make a new one in Settings."; the last 50 records per
  webhook live in memory only.
- Private addresses bypass proxies and are not flagged; replies are read up to 1 MiB ("The reply
  was too large"); extra headers never override the signature or content type; `User-Agent:` is
  `http::user_agent()`.
- Program hooks: one run at a time per program, queue 20 (oldest dropped "Dropped: too many events
  were waiting."), tests jump the queue but wait for the running event; event JSON plus `\n` on
  stdin; environment `OPENWHISPER_CPP_EVENT_TYPE`, `_ID`, `_SEQ` and the legacy-prefixed names beside
  them (lead decision 2); items re-resolve the program at start (`programs.py:393-644`).
- Filters: request `{"v":1,"stage","job_id","mode","action_id","text","language","app"}`; reply
  `{"text"}` replaces, `{}` or 204 keeps, `{"cancel": true}` or empty text delivers nothing;
  anything else keeps the text and publishes `filter.failed` (reason at most 200, never text);
  a filter is not started with less than 50 ms left ("Skipped: this stage's 3 s for filters ran
  out"); a cancel wins over an answer that arrived with it and returns the original text
  (`filters.py:301-336`, `512-575`); leases skip action jobs whose action refuses program words.
- Lease rules: loopback hosts only, stage valid, `timeout_ms` 100 to 5000 (a float with an integer
  value accepted, bools refused), modes a subset of dictation and action, TTL 60 s on a monotonic
  clock while `expires_at` is Unix seconds, at most 10 ("10 filters are already registered.
  Remove one first."), id `flt_` + 16 hex.

## Lead decisions

1. **Fast judgments move from M8 to M5 (change 6).** Route by voice is M5's demo and cannot run
   without a judge. M5.4 ports `typesafe.py` and `text_judge.py` into `fv_llm`; M5.19 ports the Fast
   judgments page and the TypeSafe credential row into `fv_ui_settings`. The meeting features, the

   the demo's routing only through `llm::FakeJudge` in the end-to-end test, with Route by voice
   showing "Route by voice needs Fast judgments" in the real app until M8.
2. **Naming on the wire** (the rule in "Rules that apply to every package"): wire shapes stay
   OpenWhisper's; product names, environment variables and credential names become OpenWhisper_CPP's
   through `identity()`; the legacy names built from `legacy_identity()` are honoured as fallbacks
   for `--api`'s token, the channel's URL and token, and are set beside the new ones for program
   hooks' and program actions' variables; `X-OpenWhisper-Client` is accepted beside
   `X-OpenWhisper_CPP-Client`; the MCP server key in the setup snippets and `.mcp.json` becomes
   `openwhisper-cpp`; the MCP Events principal becomes `openwhisper-cpp-mcp-token` (subscriptions are not
   imported, M3 change 11). Confirm, or name the strings that must keep OpenWhisper's spelling
   (each would need a constant in `base/identity.h`'s legacy block).
3. **Base64 and HMAC in `fv_base` before wave 1** (not a frozen file, but two wave-1 packages need
   it): add `base/base64.{h,cpp}` with `b64encode(std::span<const std::byte>, bool urlsafe = false,
   bool pad = true)`, `std::optional<std::vector<std::byte>> b64decode(std::string_view, bool
   urlsafe = false)` (strict as Python's `validate=True`), and `base/hmac.{h,cpp}` with
   `std::array<std::uint8_t, 32> hmac_sha256(std::span<const std::byte> key, std::string_view
   message)` and `bool constant_time_equal(std::string_view, std::string_view)`, about 150 lines
   with tests. This spec gives those new files to M5.3 (wave 1) and makes M5.5 follow M5.3;
   if the lead adds them before wave 1 instead, M5.3 drops them from its scope and M5.5 no
   longer needs to follow it.
4. **The agent picker's built-in id.** OpenWhisper's picker emits `BUILTIN = "openwhisper"`
   (`agent_picker.py:79`); if any host stores it, `lint.brand` needs
   `inline constexpr std::string_view legacy_builtin_agent_id = "openwhisper";` in a legacy block
   of `base/identity.h` before wave 4. Otherwise M5.18 uses `"builtin"`, which is never stored.
5. **Placement changes (changes 1 to 5, 7 to 9):** live API and the UI-thread `AppControl` in
   `fv_agentapi`; launch, `run_once`, `ProcessEnv` and agent probes in `fv_process`; agent actions
   and the ACP client in `fv_agents`; `AgentPicker` in `fv_ui_widgets`; the Fast judgments page in
   `fv_ui_settings`; `fv_automation` depending on `fv_dictation`. Section 2.3's text would need the
   matching edits.
6. **`openwhisper-cpp.exe --api` and `--channel` forward to `openwhisper-cpp-cli.exe`** beside them, so a
   configuration that named the GUI executable keeps working after the rename (change 4). The
   alternative is to refuse them with the usage line, as M3 does for `--workflow-smoke`.
7. **Default ports stay OpenWhisper's** (MCP 8767, History API 8766), so existing MCP
