# M9 Remote engine: package specs

## Overview

Architecture section 11: **M9 Remote engine**, areas a17 (remote engine services: host, client,
pairing, TLS, discovery, records and direct history), a18 (the Remote engine Settings page, the
pair-request dialog and the Host Mode dashboard) and Host Mode in a01 (the main window's View →
Host Mode). It also takes every row earlier specs left to M9 in a03, a04, a08, a09, a11, a13,
a14, a15, a20, a21, a24, a25, a28 and a31, and the fv_net work M5.2 and M7.1 left stubbed (TLS
listeners, the WebSocket client, self-signed identities).

**Owner decision (lead note 2):** the remote engine is wire-compatible with OpenWhisper in both
directions. A OpenWhisper_CPP client dictates through an OpenWhisper host and an OpenWhisper client
dictates through a OpenWhisper_CPP host, with pairing, discovery, TLS and every message unchanged on the
wire. The section "The OpenWhisper remote-engine wire" below is normative for every package: a
worker implements it from that section, the Python lines it cites, and the vectors and transcripts
M9.2 and M9.3 record from OpenWhisper's own code through the harness.

**Demo.** On computer A (OpenWhisper 2.8.92, sharing its engine) and computer B (OpenWhisper_CPP):
B's Settings → Remote engine → Use another computer finds A by its UDP discovery answer, "Connect"
asks A's owner to allow it, both screens show the same six digits, A allows; B's "Use for
dictation" selects the Remote computer engine, the Quick Record engine card shows the link glyph
"Connected to A · local network · 12 ms", and pressing the dictation hotkey on B pastes text that
A's Parakeet decoded. Then the roles swap: B turns on "Share this computer's engine", View → Host
Mode shows the dashboard, A pairs with B by code, A dictates, and B's dashboard shows A connected,
the transcription count rising and the beacon rippling. The real demo runs on the owner's two
computers (it serves on a non-loopback address, advertises on the owner's network and opens a
firewall prompt: lead amendment 14 and lead note 4). Workers prove every step on 127.0.0.1 with
ephemeral ports, a fake discovery transport, `speech::FakeBackend` decoders, and, where the
OpenWhisper interpreter is configured, OpenWhisper's own host and client as a child process
(M9.3's `remote_peer.py`, lead decision 3).

`fv_dictation` and `fv_appcore` do not depend on any remote library: the dictation runtime reaches
the remote engine through `dictation/remote_engine_port.h` (M9.19), which the composition (M9.20)
implements over `RemoteRuntime` and `RemoteSpeechBackend`.

Architecture 2.3 names one library, `fv_remote`, for all of a17 (host, client, pairing, discovery,
records). This spec splits it along Python's own package boundaries (`services/remote_asr/host.py`
and `service.py`; `client.py` and `discovery.py`; `services/remote_records/`) so that the host,
the client and the records work can run in parallel waves (one owner per directory per wave);
otherwise a17 alone would take seven sequential waves. `remote/wire.h` stays in `fv_remote`, the
only file `lint.brand` lets spell the OpenWhisper wire constants. Change 1 and lead decision 1.

**Rules that apply to every package below** (M0.md to M8's rules, unchanged, plus these):

- A package changes only what its `Owns` line lists, plus its own `tests/<dir>/PARITY.json`
  entries, its case files `tools/parity/cases/<python.module>.py`, its transcript scenario files
  `tools/parity/transcripts/<name>.py`, its builder file and its `tests/golden/`,
  `tests/fixtures/transcripts/` and `tests/reference/<widget>/` entries.
- Function-level PARITY as in M1.md; at most 10 % of a package's own functions `pending`.
- Qt-free code keeps Python's names in snake_case; Qt code camelCase with `Q_SIGNALS`,
  `Q_SLOTS`, `Q_EMIT` (amendment 17). Every class states its affinity.
- **Nothing a test does reaches beyond this machine.** Servers bind `127.0.0.1` on port 0;
  discovery runs over `remote::testing::FakeDiscoveryBus` or a responder bound to `127.0.0.1` on
  port 0; `tailscale` is a fake executable on a temporary `PATH` or `FakeTailscaleCli`;
  `GetNetConnectionProfile` is behind an interface. Binding `0.0.0.0`, broadcasting on real
  network cards, serving on a LAN or Tailscale address, opening a firewall prompt, launching
  `ms-settings:` links, writing the clipboard and showing a window on the owner's screen are
  `[interactive]`: written, never run by a worker (amendment 14). No worker changes firewall or
  network settings.
- **Blocking calls never run on the GUI thread or the reactor.** Everything that waits on the
  network (`RemoteConnection`, probe, pair, scans, service calls) asserts `assert_not_gui_thread()`;
  pages and the dashboard reach them through `ctx.io()` (or their own strand) and get results
  back with `qt::post` and a `TokenGate`, which replace OpenWhisper's `_SectionRelay`,
  `_PageRelay`, `_PromptRelay` and `_RequestRelay` (architecture 3.11).
- **Wire bytes are OpenWhisper's.** Every constant, field name, key order, separator style, close
  code and error code below is reproduced byte for byte; product names in copy come from
  `identity()` (lead decision 2). `remote/wire.h` is the only C++ file that spells
  "openwhisper".
- Format with `wsl clang-format --dry-run -Werror` (amendment 3).
- **`DEPS` lines.** A package that adds source files to `src/<dir>/` also owns that module's
  `DEPS` line for the libraries those files include (the libraries named in its section: for
  example `fv_remote` for every widget library that takes `remote::RemoteLink`,
  `RemoteEngineControl` or `RecordSyncControl`), and a package that adds test files to
  `tests/<dir>/` owns that directory's `fv_test(... DEPS ...)` for the test support and the
  libraries its tests construct (`fv_remote_wire_testkit`, `fv_remote_host` for tests that run
  M9.6's `SpeechHost` on loopback, `Boost::asio OpenSSL::SSL OpenSSL::Crypto` for loopback
  servers). No addition may create a cycle or break a module's kind rule (`lint.layering`).
- **Services are looked up, not assumed.** `RemoteFeature::provide()` (M9.20, phase 1 of
  `appkit/feature.h`) provides `remote::RemoteEngineControl`, `remote::RecordSyncControl` and
  `remote_host::RemoteRuntime`; until M9.20 merges, and in every test without them, nothing does.
  Pages, panels and dialogs call `ctx.find<T>()` in `install` or later (when they are built or
  refreshed; never in another feature's `provide`, whose order is not RemoteFeature's, and never
  `ctx.service<T>()`, which throws) and show their unbound state on null.
- **No link leaves the app in a test.** Reachability notes (`ms-settings:` pages, the Tailscale
  download page) and help links open through an injected URL opener; tests record the URL.

## The OpenWhisper remote-engine wire

This section is the protocol, taken from `services/remote_asr/protocol.py` (whose docstring, lines
1-131, M9.2 keeps as the header comment of `remote/protocol.h`), `host.py`, `client.py`,
`discovery.py`, `tls.py`, `settings.py` and `services/remote_history/`. Line numbers are of the
pinned checkout. Where a value is "Python repr", `pyport::float_repr` writes it.

### Transport and TLS

| Item | Value | Source |
|---|---|---|
| URL | `wss://<format_address(host, port)>/openwhisper/v1/engine` (IPv6 hosts in brackets) | client.py:129-130 |
| Default TCP port | 47821 (`remote_host_port`, 1..65535; the page's spin box allows 1024..65535) | protocol.py:143 |
| Upgrade path check | the request path up to `?` must equal `/openwhisper/v1/engine`; anything else is answered `HTTP 404` with body `Not an OpenWhisper remote engine endpoint\n` (text/plain) and no upgrade | host.py:707-711 |
| WebSocket | RFC 6455, no subprotocol, **no permessage-deflate**, max message 8 MiB on both sides (`max(MAX_REQUEST_BYTES, MAX_REPLY_BYTES)` = 8,388,608 on the host, `MAX_REPLY_BYTES` on the client) | host.py:456-469, client.py:140-152 |
| Host WebSocket opening handshake timeout | 10 s (`open_timeout`) | host.py:465 |
| Host keepalive | the host pings every 20 s and closes when a pong takes longer than 20 s | host.py:466-467 |
| Client keepalive | the library keepalive is off; the client pings at once after `ready`, then every 20 s, timing each pong with a steady clock; no pong in 20 s marks the connection closed | client.py:639-668 |
| Inbound queue | the host reads at most 2 queued frames per connection ahead of the one it handles (`max_queue=2`): it stops reading the socket meanwhile | host.py:54, 463 |
| Client close timeout | 2 s | client.py:144 |
| TLS server | TLS 1.2 minimum, certificate and key from the identity files, **TLS 1.3 session tickets off** (`num_tickets = 0`, `SSL_CTX_set_num_tickets(ctx, 0)`) | tls.py:97-107 |
| TLS client | TLS 1.2 minimum, no CA verification, no hostname check; the peer certificate's DER SHA-256 is compared by the caller before any secret is sent | tls.py:110-126 |
| Fingerprint | uppercase hex SHA-256 of the certificate DER (64 characters); `short_fingerprint`: the alphanumerics uppercased, first 5 groups of 4 joined by `-` | protocol.py:255-267 |

### Host identity files

`ensure_host_identity(data_root)` (tls.py:34-44): `remote_engine_host_cert.pem` and
`remote_engine_host_key.pem` in the data root (OpenWhisper_CPP's own, never OpenWhisper's). Both present
and the certificate readable: reuse. Otherwise (missing, or unreadable: warn "Remote engine
certificate is unreadable; creating a new one") generate: EC P-256 key; subject and issuer one
CommonName `"<identity().product> host <hostname>"` cut to 64 characters (OpenWhisper writes
`OpenWhisper host <hostname>`; lead decision 2); serial a random positive integer below 2^159
(`x509.random_serial_number`); not before now − 1 day, not after now + 7,300 days (UTC); signed
with SHA-256; X.509 v3 with **no extensions**. Key file: PKCS#8 PEM, unencrypted
(`-----BEGIN PRIVATE KEY-----`), written first with `O_CREAT|O_TRUNC` mode 0600 (on Windows the
per-user profile's ACL); certificate PEM second. Log "Created the remote engine host certificate".
`own_fingerprint(dir)`: the certificate's fingerprint, or "" when it does not exist or cannot be
read. Regenerating changes the fingerprint and orphans every pairing (clients then see the
"different certificate" error), as in OpenWhisper.

### JSON serializers (byte-exact)

Two serializations are on the wire, both Python `json.dumps` with `ensure_ascii=True`
(non-ASCII as `\uXXXX`, astral characters as surrogate pairs) and insertion order:

| Style | Separators | Used for |
|---|---|---|
| compact | `","` and `":"` | every text frame the **host** sends (`SpeechHost._send`, host.py:721-723), every binary request header (protocol.py:197), every discovery reply (discovery.py:125) |
| default | `", "` and `": "` | every text frame the **client** sends (`json.dumps(...)` in client.py: probe, pair, pair_request, pair_nonce, pair_cancel, hello); the host's direct-history frames `ready` and `history_query` (channel.py:57-65, 141-143) and the client's `history_result` (remote_history/client.py:236-248) |

`pyport::dumps` with `DumpOptions{.item_sep = ",", .key_sep = ":"}` or the defaults writes both.
Numbers: integers as integers, floats as Python repr (`host_ms` `12.3`, segment times `0.0`).
Parsing uses `pyport::loads` (Python semantics, `NaN` accepted). Field checks follow Python's
truthiness and `isinstance` exactly: the host's `message.get("protocol") != 1` is Python
equality, so `1`, `1.0` and `true` all pass (compare with `py::py_equal`, host.py:757); `is True`
checks require JSON `true`; `isinstance(x, int)` checks that must refuse booleans say so in
Python (`not isinstance(port, bool)`, discovery.py:146) and are ported exactly.

### Binary request frames

`pack_request(header, audio | payload)` (protocol.py:195-204): 4-byte big-endian unsigned length
of the header, the compact JSON header (UTF-8, at most 65,536 bytes, else
`ProtocolError("Request header is too large")`), then the payload. For `transcribe` and `stream`
the payload is 16 kHz mono **signed 16-bit little-endian PCM**: `clip(rint(x * 32768.0), -32768,
32767)` per float32 sample (round half to even), and back `int16 / 32768.0` as float32 (architecture
5.1 says float32 frames; the wire is PCM16, change 6). For `records_put` the payload is file bytes;
every other request has an empty payload.

`unpack_frame` refusals (protocol.py:236-252), each a `ProtocolError` whose text is the reply's
`error`: text frame "Requests must be binary frames"; fewer than 4 bytes "Request frame is
truncated"; length over 65,536 or past the end "Request header length is invalid"; not JSON
"Request header is not JSON"; not an object "Request header must be an object". Audio payloads:
over 3,840,000 bytes (120 s) "Request audio is too long"; odd length "Audio payload has an odd byte
count". The host answers a frame it cannot unpack with `{"id":null,"error":"<text>","code":"bad_request"}`.

### First message and connection states

Every connection starts in a **handshake slot** (12; host.py:45). Over the limit the host sends
`{"type":"error","code":"busy","message":"The host is busy. Try again shortly.","retry_after_ms":1000}`
and closes 4429 "host busy" (host.py:725-732); the client reads the queued reply even when the
send of its own hello failed (client.py:608-613). The first frame must arrive within 10 s (else
close 4408 "handshake timeout"), must be a text frame holding a JSON object (else close 4400
"expected hello"), and is dispatched by `type`:

| First message (client → host, default separators) | Host behaviour |
|---|---|
| `{"type": "probe", "protocol": 1}` | answered **before** the version check: `{"type":"probe","protocol":1,"host":{"name":<host_name>},"engine":{"label":…,"device":…,"available":…,"family":…},"tailscale_pairing":<bool: a trusted Tailscale owner exists>,"approval":true}`, then close 1000 |
| any other type with `protocol` not equal to 1 | `{"type":"error","code":"protocol","message":"This host speaks remote engine protocol 1; update <product> on both computers."}` and close 4400 "protocol version" |
| `{"type": "pair", "protocol": 1, "device_name": <name>, "code": "<digits>"}` | code pairing |
| `{"type": "pair", "protocol": 1, "device_name": <name>, "tailscale": true}` | Tailscale pairing (`tailscale` is inserted after `device_name`) |
| `{"type": "pair_request", "protocol": 1, "device_name": <name>}` | approval pairing |
| `{"type": "hello", "protocol": 1, "token": <token>, "capabilities": {"recording_activity": true}}` | a paired computer's speech connection (`capabilities` only from a backend that reports recordings: the dictation backend and the meeting backend; one-shot management, record-sync connections send no `capabilities`) |
| `{"type": "hello", "protocol": 1, "token": <token>, "purpose": "history", "history_enabled": <bool>}` | the direct-history connection |
| anything else | close 4400 "expected hello" |

`device_name` is this computer's host name (`socket.gethostname()`: Winsock `gethostname`).

### Pairing

**Code** (host.py:525-549, 883-947; client.py:266-301). `open_pairing(ttl=300)`: six digits
`randbelow(10**6)` zero-padded, one successful pairing, emits `pairing{open:true}`. The client strips
non-digits from the code it sends; an empty code raises "Enter the pairing code shown on the host."
before connecting. Host outcomes, each sent as `{"type":"error","code":…,"message":…}` and closed
4401 with the code as reason:

| Code | Message |
|---|---|
| `pairing_closed` | `Pairing isn't open on the host. Click "Show a pairing code" there and enter the code it shows.` (also when the code expired) |
| `bad_code` | `That code doesn't match the one on the host.`; the 5th wrong code closes pairing (emits `pairing{open:false}`) and says `Too many wrong codes. Start pairing again on the host.` |

The code is compared with `hmac.compare_digest` after `str(code).strip()`. Success: the registry
adds the device and the host sends `{"type":"paired","token":<token_urlsafe(32)>,"device_id":<uuid4 hex>,"host":{"name":…,"fingerprint":…,"addresses":[…]}}`
and closes 1000, records activity `paired`, emits `paired{name}` then `devices`.

**Tailscale** (host.py:897-916). Allowed only when the trusted owner is non-empty (setting
`remote_host_tailscale_trust` on, Tailscale running with an owner) and `own_device(remote_ip,
local_ip, owner)` holds: both socket addresses in 100.64.0.0/10 or fd7a:115c:a1e0::/48 (IPv4-mapped
unwrapped) and `tailscale whois --json <remote>` names the same untagged login. Refusal code
`tailscale_refused`, message "This host only lets its owner's own Tailscale computers pair without a
code. Enter the pairing code shown there instead." (owner set) or "This host doesn't pair over
Tailscale without a code. Enter the pairing code shown there instead." (no owner); close 4401
"tailscale_refused". The device name defaults to the whois node name. `via` is `tailscale`.

**Approval with a short authentication string** (protocol.py:281-308; host.py:949-1055;
client.py:304-388):

1. Admission (`_admit_request`): sender must pass `allowed_sender` (private, link-local, loopback,
   or IPv4 in 100.64.0.0/10; never multicast or unspecified) else `approval_refused` "This host only
   takes pairing requests from its own network. Enter the pairing code shown there instead."; at
   most 4 requests per address per 600 s else `approval_limited` "Too many pairing requests from
   this computer. Wait a few minutes, or enter the pairing code shown on the host."; one request at
   a time else `approval_busy` "<host_name> is already asking about another computer. Try again in a
   minute.". Each refusal closes 4401 with its code. The request gets id `uuid4().hex[:12]` and
   expires 10 s + 120 s from now.
2. Host → `{"type":"pair_commit","commit":<sha256("openwhisper-pair-commit-v1" + host_nonce) lowercase hex>,"timeout_s":120}`
   with a fresh 32-byte nonce.
3. Client → `{"type": "pair_nonce", "nonce": <32 random bytes, lowercase hex>}` within 10 s; a
   missing, malformed or wrong-length nonce closes 4400 "expected pair_nonce".
4. Host → `{"type":"pair_reveal","nonce":<host nonce hex>}`; the request now expires 120 s from
   here, gets its SAS and is shown (`pair_request{name,address}` event).
5. Client checks the reveal: type, 32 bytes, `compare_digest(commitment(host_nonce), commit)`, else
   "The host's pairing answer didn't check out. Pairing was stopped; try again on a network you
   trust."; then both compute `pairing_sas(host_nonce, client_nonce, fingerprint)` =
   `int.from_bytes(sha256("openwhisper-pair-sas-v1" + host_nonce + client_nonce +
   fingerprint.upper() as ASCII with "replace")[:8], "big") % 10**6`, six digits zero-padded,
   shown as `123 456` (`format_sas`). The client uses the fingerprint its socket saw; the host its
   own.
6. The host waits (polling every 0.2 s) for: the owner's `answer_request(id, allow)`; the socket
   closing (the client canceled: no message); expiry; or sharing stopping. Outcomes: allowed →
   `paired` as for a code (`via` `approval`); denied → `pair_denied` "<host_name> declined the
   request."; stopped → `pair_closed` "<host_name> stopped sharing its engine."; timeout →
   `pair_timeout` "Nobody answered on <host_name>. Try again while someone is at it, or pair with a
   code."; each closed 4401. The client waits at most 150 s ("The host didn't answer in time. Try
   again."), polling 0.2 s for its cancel flag; on cancel it sends `{"type": "pair_cancel"}`
   (ignored by the host, which notices the close) and raises `PairingCanceled("Pairing canceled.")`.
   A close before an answer is "The host closed the connection before answering."
7. `stop()` while a request waits marks it stopped and waits up to 2 s for its handler to send
   `pair_closed` before closing sockets.

**MITM check on every pairing reply** (client.py:237-263): an `error` reply raises its `message`
(or "The host refused to pair."); a reply that is not `paired` with a non-empty string token raises
"The host sent a pairing reply this version can't read."; a non-empty `host.fingerprint` that
differs (`compare_digest` on the uppercased value) from the certificate the socket saw raises "The
host's certificate didn't match what it reported. Pairing was stopped; try again on a network you
trust.". The result keeps `alternates` = the listed addresses that are strings, non-empty and not
the address dialled, de-duplicated in order.

### Hello and ready

`hello` (host.py:1057-1164): the token is authenticated against every registry entry with a
constant-time compare of `sha256(token)` hex (no early exit); unknown →
`{"type":"error","code":"unauthorized","message":"This computer isn't paired with the host anymore. Pair it again."}`
and close 4401 "unauthorized". Then the handshake slot is traded for a **connection slot** (32;
over the limit the busy refusal and 4429). `purpose == "history"` goes to the history channel
below. Otherwise the client is registered (connection id `uuid4().hex[:8]`), sharing having
stopped meanwhile closes 1001 "host stopped sharing", the engine identity is checked again (changed
→ close 4409 "engine changed" without a `ready`), and the host sends:

```
{"type":"ready",
 "host":{"name":…,"fingerprint":…,"addresses":[<best LAN address when its kind is lan>, <Tailscale IPv4 when running>]},
 "device":{"id":…,"name":…},
 "engine":<describe()>,
 "models":[{"family":…,"model":…,"label":…}, …],
 "runtime":<runtime_state(describe())>,
 "capabilities":{"model_management":B,"runtime_installation":B,"engine_controls":B,"recognition_hints":B,"recording_activity":true[,"mcp_control":B][,"records":B]}
 [,"records":{"dictation":{"count":n,"bytes":n},"meeting":{"count":n,"bytes":n}}]}
```

`describe()` of a OpenWhisper_CPP host (key order of `SpeechWorkerEngine.describe`, engines.py:81-94):

### Requests and replies

After `ready`, every client request is one binary frame `{"id":<serial int>,"op":<op>,…}`; every
reply one compact text frame with the same `id`. Before each frame the host re-authenticates the
token (removed device → close 4401 "device removed"). Reply envelopes and their key orders:

| Case | Reply |
|---|---|
| success | `{"id":n,"result":{…},"host_ms":<round(ms since the frame arrived, queue wait included, 1)>}` |
| engine error, unknown op, failed switch | `{"id":n,"error":"<str(exc) or exception class name>"}` |
| bad frame | `{"id":null,"error":"<ProtocolError text>","code":"bad_request"}` |
| update hold on a costly op or `recording_begin` | `{"id":n,"code":"engine_reloading","error":"The host is preparing a <product> update. Try again shortly."}` |
| work pool full or wait over | `{"id":n,"code":"busy","error":"The host is busy. Try again shortly.","retry_after_ms":1000}` |
| engine not settled (`transcribe`, `stream`) | `{"id":n,"code":"engine_reloading","error":"The host is loading its speech engine."}` |
| engine identity changed since `ready` | `{"id":n,"code":"engine_changed","error":"The host switched speech engines. Reconnecting."}`, then close 4409 "engine changed" |
| records busy (`RecordsBusy`) | `{"id":n,"code":"busy","retry_after_ms":1000,"error":"<text>"}` |
| records `LookupError` | `{"id":n,"code":"not_found","error":"<text or 'No such record.'>"}` |
| records or MCP `ValueError` | `{"id":n,"code":"bad_request","error":…}`; an MCP `ValueError("code: text")` becomes `{"id":n,"code":"<code>","error":"<text>"}` |
| permission off | `{"id":n,"code":"forbidden","error":…}` (texts in the op table) |
| no such feature on this host | `{"id":n,"code":"unsupported","error":…}` |

Costly ops (`transcribe`, `stream`, `select_model`, `configure_runtime`, `model_catalog`,
`download_model`, `install_runtime`) pass a FIFO **work admission**: 2 active, 4 queued, 30 s
longest wait, a waiter dropped when its client disconnects or sharing stops; records and MCP ops
and `recording_*` skip it (host.py:269-308, 1196-1232).

| Op | Header fields (besides `id`, `op`) | Result |
|---|---|---|
| `transcribe` | `language` (string or null), optional `phrases` (≤ 50 strings, each whitespace-collapsed 1..64 chars; dropped unless the engine takes hints) + PCM16 payload | `{"text":…,"segments":[{"text":…,"start":f,"end":f},…]}` (Parakeet: `segments_from_words`, words not sent) |
| `stream`, `cancel_stream` | `session` (non-empty string, else "A stream needs a session id"), `language`, `finish` | Parakeet has no native stream: `stream` fails "The host's engine has no live stream"; `cancel_stream` → `{}`; sessions are scoped `remote-<conn id>-<session>` and cancelled on disconnect |
| `describe` | — | `describe()` |
| `select_model` | `family`, `model`, optional `device` (`auto`/`cpu`/`cuda`, needs model management: "Model management is disabled on the host."; extra fields or another device: "Invalid model device request.") | `{"engine":…,"models":[…]}` once loaded (≤ 240 s); errors "Choose a model to switch to", "<host_name> doesn't let paired computers change its model.", and the service's texts (M9.12) |
| `configure_runtime` | `family`, `model`, `settings` (object of `device`, `compute_type`, `language`); no other fields ("Invalid runtime request.", code `bad_request`) | `{"engine":…,"runtime":…}`; no callback: "Update <product> on the host to change its runtime." |
| `model_catalog` | none other | catalog (M9.12) |
| `download_model` | `family`, `model` (non-empty strings) | job acknowledgement |
| `install_runtime` | `family`, `model`, `device` in `auto`/`cpu`/`cuda` | job acknowledgement |

| `recording_begin`, `recording_end` | `recording_id` (32 lowercase hex), empty payload, else `bad_request` "Invalid recording ID"; connection without `recording_activity` → `bad_request` "Recording activity is disabled" | `{}` |
| `records_stat`, `records_begin`, `records_put`, `records_commit`, `records_abort`, `records_list`, `records_open`, `records_fetch`, `records_delete`, `records_clear` | see a17 map "Wire protocol summary" and M9.8 | see M9.8; writes (`begin`, `put`, `commit`) need `remote_host_keep_records`: `forbidden` "<host_name> isn't keeping records for other computers. Turn on "Keep records for paired computers" in Settings → Remote engine there."; no store: `unsupported` "Update <product> on the host to keep records there." |
| `mcp_state`, `mcp_configure` | `settings` object for `mcp_configure`, nothing else ("Invalid MCP request.") | `HostMcpControl.state()`; no control: `unsupported` "Update <product> on the host to manage its MCP server."; off: `forbidden` "<host_name> isn't letting paired computers manage its MCP server. Turn on "Allow paired computers to manage MCP" in Settings → Remote engine there." |
| anything else | — | `{"id":n,"error":"Unknown operation: '<op>'"}` (Python `repr`) |

Host events (`on_event(kind, detail)`): `state`, `pairing{open}`, `pair_request{name,address}` and
`{}`, `paired{name}`, `devices`, `clients`, `activity{name,busy}`, `engine{family,model,by}` or
`{by}`, `mcp{by}`, `records{device,op}` (after `records_commit`, `records_delete`,
`records_clear`).

**Engine change push** (host.py:644-666): when this computer's engine finishes loading, every
connected client whose `ready` named another engine identity and that is not inside a request is
closed 4409 "engine changed" (on a worker thread; each close waits for its handshake).

**Recording reservations and the update hold** (host.py:584-628, 1166-1250): `recording_begin`
stores the id on the connection (refused with `engine_reloading` during a hold); a disconnect with a
reservation keeps `(device, id)` "reconnecting" for 15 s; the same id on reconnect reclaims it.
`prepare_update()` → `{"token":<token_hex(16)>,"expires_in":60.0}` or `{"reason":…}` ("The speech
host is starting or reloading", "Another update already reserved the host", "A paired client is
recording or using the speech host", "A connected client cannot report its recording state");
`cancel_update(token)`; `update_status()`. On Windows nothing calls `prepare_update` (its caller
is Omarchy's Linux updater), so the hold never starts; the API and its tests are ported.

**Stop** (host.py:484-521): history broker removed, discovery stopped, pairing closed, a waiting
request told "stopped" (2 s grace), server shut down (closes every connection), every remaining
client closed 1001 "host stopped sharing", event `state`.

### Direct history channel

Separate paired connection (`hello` with `purpose: "history"`). The host (broker,
remote_history/channel.py) replaces an existing peer of the same device (old one closed 1001
"history connection replaced"), refuses when not accepting (1001 "host stopped sharing"), sends
`{"type": "ready", "capabilities": {"client_history": true}}` (default separators), and for each
query sends `{"type": "history_query", "id": <uuid4 hex>, "operation": <op>, "params": {…}}`
(default separators); at most 8 pending per peer (else `unavailable`), 5 s each (else
`unavailable`), `sharing_disabled` when the client's hello said `history_enabled` false. It reads
only text frames ≤ 8 MiB of type `history_result`; anything else ends the session; the token is
re-authenticated per frame; on removal peers close 1001 "history connection closed". The client
(remote_history/client.py) answers `{"result": …, "type": "history_result", "id": …}` or
`{"error": "<code>", "type": "history_result", "id": …}` (default separators; key order: the
reader's key first), replaced by `{"type": "history_result", "id": …, "error": "unavailable"}`
when over 8 MiB; it ignores queries over 64 KiB or not of type `history_query` by ending the
session. A host without `client_history` in `ready` is asked again after 60 s; otherwise the client
reconnects every 10 s. Operations, fields and validation: a17 map A17-52 and A17-62 (`_Query`,
`_FIELDS`, `_REQUIRED`, `_query_values`, `_dates_to_utc`). Error codes and texts are
`ClientUnavailable`'s (channel.py:15-36).

### Discovery and sweep

UDP on port 47821 regardless of the TCP port (discovery.py:45-66; service.py:663).

| Item | Value |
|---|---|
| Query | `OWHISPER?1` + 16-byte nonce, zero-padded to 512 bytes; shorter datagrams or another magic are ignored |
| Reply | `OWHISPER!1` + compact JSON `{"n":<nonce hex>,"name":<≤60>,"port":<int>,"fp":<fingerprint>,"protocol":1,"approval":<bool>,"engine":{"label","device","available","family"}}`, never over 512 bytes: if too long, `engine` becomes `{"available":…}`, then `name` is cut to 16; if still too long, no reply |
| Responder | answers only `allowed_sender` addresses; at most 20 answers per sender and 200 in all per 10 s; sender map pruned of empty entries past 1,024; socket timeout 0.5 s; Windows ICMP "port unreachable" errors on `recvfrom` are ignored (`SIO_UDP_CONNRESET` off); bind failure leaves sharing running with `discovery.error` = "UDP port <port> is in use (<strerror>)" |
| Search | an **unbound** socket with `SO_BROADCAST` (no firewall prompt); targets: each private LAN card's broadcast address (prefix 8..30), then 255.255.255.255; sends at 0, 0.3 and 0.7 s; listens 1.2 s; replies validated (`n` equals the nonce, `fp` 64 hex, `port` an int 1..65535 not a bool, printable name ≤ 60 or the sender address); one entry per fingerprint (uppercased) |
| `find_host(fp)` | a search that stops at the first answer with that fingerprint |
| Sweep | every other host address of the first two private LAN networks with prefix clamped to ≥ 24; TCP connect 0.4 s, 64 at a time; answerers then probed (12 at a time) on 47821 |

### Client connection behaviour

`RemoteConnection(host, port, token, fingerprint, alternates, history_enabled, reports_recording)`
(client.py:395-807): candidates are the last address that worked for this fingerprint (process-wide)
first, then `host` and `alternates` in order; each but the last gets min(6 s, 2.5 s), the last 6 s.
At each: open (error translation below), compare the certificate (`_WrongPlace` "<where> presented a
different certificate than when this computer paired with it. If <product> was reinstalled there,
pair again; otherwise something is intercepting the connection."), send `hello`, read the reply
within 10 s (`error` with code `busy` → `RemoteHostBusy(retry_after_ms)`, other error → its message
or "The host refused the connection.", not `ready` → "The host sent a reply this version can't
read."). When every candidate fails: a LAN rediscovery by fingerprint at most every 30 s per
fingerprint (process-wide); a host found at an address not tried (or another port) is tried with 6 s
and, on success, appended to the candidates. Otherwise the error of the **first** (paired) address
is raised. On success the route is remembered when there was more than one candidate, and the
pairing follows `ready.host.addresses` (`remember_host_addresses`; failure logs only the exception
type). A connection closed meanwhile raises "Transcription canceled".

Open errors (client.py:133-172): HTTP status other than 101 → "<where> answered, but it isn't an
<product> remote engine (HTTP <n>)."; other WebSocket handshake failure → "<where> isn't an
<product> remote engine."; DNS → `RemoteUnreachable("Couldn't find a computer named <host>.")`;
connection refused → `RemoteUnreachable(refused=True, "Couldn't reach <where>: nothing there is
accepting connections on that port. Check that the host is sharing its engine, on that port.")`;
anything else (timeout, TLS, reset) → `RemoteUnreachable("Couldn't reach <where>. Check that the
host is on, sharing its engine, and allowed through its firewall.")`. Reads: timeout "The host didn't
answer in time.", close "The host closed the connection.", unparsable "The host sent a reply this
version can't read.".

Requests: one at a time per connection; serials from 1; the reply wait polls every 50 ms for an
abandon (`abandon()` keeps the connection, marks every current serial abandoned; late replies are
skipped by id) or a close from another thread ("Transcription canceled"); a request past its timeout
(default 180 s; the backend uses 300 s) closes the connection: "The remote engine on <where> timed
out; the connection was closed."; a send failure is `RemoteConnectionLost(sent=False, "Lost the
connection to <where>.")`, a receive failure `sent=True`; a reply with `code` `engine_changed`
closes and raises `RemoteConnectionLost(sent=True, <error>)`; any reply holding `error` raises
`RemoteRequestError(error, code, retry_after_ms)` (`retryable` when the code is `busy`).
`recording_activity(op, id)` waits at most 0.75 s for the request lock ("The remote speech connection
is busy. Try again shortly.") and 0.75 s for the reply. `alive` = socket open; `latency` = last
keepalive round trip; `beats` = pongs; `via_tailscale` by the peer IP; `closed_for_engine_change`
= close code 4409.

### How parity is proven

- **Golden vectors** (M9.2, M9.5, M9.6, M9.7, M9.12, M9.14, M9.10, M9.15): every pure function of
  `protocol`, `discovery` (codec), `settings` (pairing model), `tailscale` (whois parsing),
  `reachability`, `activity` (fake clock), `host_store` names, `kinds` coercion, history
  `_query_values`, and the a18 text helpers, generated with `tools/parity/golden_vectors.py`.
  Deterministic frames (probe and error replies with fixed inputs, `pack_request` of fixed headers
  and audio, discovery queries and replies for a fixed nonce) are byte-exact vectors.
- **Recorded two-sided exchanges** (M9.3): OpenWhisper's `SpeechHost`, `HistoryBroker`, client
  functions and `RemoteConnection` run in one isolated process on 127.0.0.1 with fakes; a frame tap
  records every frame both ways as `tests/fixtures/transcripts/remote_<scenario>.json`. The C++
  host replays the client half and must produce the host half; a C++ scripted TLS server replays
  the host half to the C++ client, which must produce the client half; volatile values (tokens,
  device ids, nonces, commitments, fingerprints, `host_ms`, timestamps, connection ids, query ids)
  are compared through the transcript's `normalize` list and checked for shape (length, alphabet)
  and consistency (the same token in `paired` and the next `hello`).
- **Live interop** (M9.12, M9.20, lead decision 3): `tools/parity/remote_peer.py` runs
  OpenWhisper's host or client under `ow_isolation.py` on 127.0.0.1 as a child process; `[platform]`
  tests drive it against the C++ client and host and skip with a message when `OPENWHISPER_CPP_OW_ROOT` or
  `OPENWHISPER_CPP_OW_PYTHON` is unset.

namespace fv::net {
struct WsHandlers {                      // added
    std::chrono::milliseconds open_timeout{10'000};   // TCP accept to upgrade done (TLS included)
    std::chrono::milliseconds ping_interval{0};       // 0: no server pings (remote host: 20 s)
    std::chrono::milliseconds ping_timeout{0};        // pong deadline; missed -> close 1011
    std::size_t max_queued_messages = 0;  // 0: read freely; n: stop reading while n delivered
                                          // messages are not released
};
class WsConnection {                     // added, with defaults for the client
public:
    virtual Peer local_endpoint() const { return {}; }
    virtual Peer remote_endpoint() const { return {}; }
    virtual void release_message() {}    // one delivered message handled (max_queued_messages)
    virtual bool is_open() const { return true; }
};
struct WsConnectFailure {
    enum class Kind { Dns, Refused, Unreachable, Timeout, Tls, HttpStatus, Handshake, Cancelled };
    Kind kind; int http_status = 0; std::string detail;
};
struct WsClientOptions {                 // added
    std::function<void(const WsConnectFailure&)> on_connect_failed; // before on_open; else on_close
    std::size_t max_message_bytes = 8u << 20;
    std::chrono::milliseconds close_timeout{2'000};
};
class WsClientConnection : public WsConnection {   // added
public:
    // Sends a ping; done gets the round trip (steady clock) or nullopt when no pong came within
    // timeout or the socket closed. Runs on the reactor.
    virtual void ping(std::chrono::milliseconds timeout,
                      std::function<void(std::optional<std::chrono::nanoseconds>)> done) = 0;
    virtual std::optional<std::uint16_t> close_code() const = 0;  // the peer's, once closed
};

std::string certificate_sha256_from_pem(std::string_view pem);         // throws on bad PEM

### Traps

- Python's server sends no TLS 1.3 tickets because a websockets client stalled on Windows
  (tls.py:100-105); OpenSSL 3 sends two by default: call `SSL_CTX_set_num_tickets(ctx, 0)`.
- The client must not verify the chain or the host name (self-signed, reached by IP, name or
  tailnet address alike), and must expose the leaf certificate's DER for pinning.
- A refused connection and an unreachable host must be told apart (`ECONNREFUSED`/`WSAECONNREFUSED`
  → `Refused`), because the client's wording differs and the page blames the firewall only for the
  latter (A18-09).
- On Windows a UDP `recvfrom` after a `sendto` to a closed port fails with `WSAECONNRESET`; disable
  it with `WSAIoctl(SIO_UDP_CONNRESET, FALSE)` and treat any remaining one as "no datagram", as
  Python's loops do (discovery.py:246-253, 378-381).
- The unbound broadcast socket must never `bind` (a bound socket makes Windows ask about the
  firewall; discovery.py:324-327).
- `max_queued_messages` pacing must stop reading the TCP socket, not drop frames.

### Traps

- `pack_request` uses compact separators and `ensure_ascii=True` (protocol.py:197); the client's
  text frames use default separators (client.py:215, 297, 328, 340, 609). Both through `pyport`.
- `encode_audio` is `np.rint` (half to even) of `float32 * 32768.0` computed in float32, then
  clipped: `0.5 / 32768` rounds to 0 and `1.0` clips to 32767 (protocol.py:181-185).
- `parse_address`: `raw.count(":") == 1` decides `host:port`; an unbracketed IPv6 address is a
  bare host (protocol.py:336-341); a scheme is stripped case-insensitively but the host keeps its
  case; whitespace inside the host is an error.
- `clean_name` uses Python's `str.isprintable` (Unicode categories, spaces count as printable) and
  `strip()` then cuts to 60 code points, not bytes (`pyport`).
- `pairing_sas` encodes the fingerprint with `encode("ascii", "replace")`: a non-ASCII character
  becomes `?` (protocol.py:299-302).
- `encode_reply` caps `name` at 60 before measuring and at 16 in the last stage; `port` is
  `int(info.get("port") or 0)`.
- `ClientPairing` equality ignores host, port, host name, alternates and `paired_name`
  (settings.py:36-60); the alternates of a loaded pairing drop the host itself.
- `remember_host_addresses` holds one process-wide lock for read-modify-write (settings.py:226-249)
  and returns nullopt when nothing changed (no write).
- `token_credential` compares `normcase(realpath(...))` of the data root and the per-user directory
  (lowercase, backslashes on Windows; symlinks resolved) and hashes the UTF-8 of the normalized
  data root.
- The Tailscale CLI on Windows is `tailscale` on `PATH`, else `%ProgramFiles%\Tailscale\tailscale.exe`
  then `%ProgramFiles(x86)%\…`; its runs have no window and a closed stdin; the first stderr line is
  the error text, else "Tailscale isn't running" (tailscale.py:100-154).

  live in a weak map and must not leak (`test_a_finished_upload_leaves_no_record_lock_behind`).
- `begin` re-stages when the declared files or bytes changed, prunes staging older than 7 days
  except the current one, and checks free space with a 1 GiB margin: "Not enough free space on
  the host to keep this record (N MB needed)." (host_store.py:319-347).
- The meeting import swaps the spool through `.deleting-<id>-<hex>` tombstones with rollback
  (kinds.py:858-916) and skips `*.pcm`, `*.recovery.json`, `*.orphan`, `*.tmp`, `playback.wav`,
  `playback.json`; only `ended` and `failed` meetings are records; new host and guest tokens are
  minted on import.
- Coercion is as strict as `_row_from_json` (kinds.py:110-154): JSON `true` is not an integer, an
  integer is not a float unless the column is a float, text over 2 MiB is refused.
- Upload state goes to `upload.json` atomically (temporary file and replace).

## Changes from section 11 and earlier specs

1. **Three remote libraries instead of one.** `fv_remote` (wire, client, backend, client history),
   `fv_remote_host` (registry, activity, host, service, broker, runtime glue) and
   `fv_remote_records` (record store, kinds, sync), split where Python splits
   (`services/remote_asr/host.py` + `service.py`, `client.py` + `discovery.py`,
   `services/remote_records/`). With one directory, one owner per wave would serialize a17 over
   seven waves. `remote/wire.h` stays in `fv_remote` (lead decision 1).
2. **Contracts first.** `remote/control.h`, `remote/record_sync_control.h`,
   `remote/client_history_source.h` and `remote/link.h` land in wave 1 with fakes, so the Settings
   page, the engine card, federation and the record views are built in waves 2 and 3 against them.
3. **Placements.** `HostMcpControl`, federation and the client MCP link (`mcp_link.py`) live in
   `fv_agentapi`, beside `McpServerControl` (which `HostMcpServer` implements); `fv_agentapi` gains
   `DEPS fv_remote`. The direct-history reader sits in `fv_remote` over an injected query function
   bound to `agentapi::HistoryStore`, so `fv_remote` never depends on `fv_agentapi`. The meeting
   backend lives in `fv_meeting_capture`. `RemoteModelsDialog` (a15) lives in `fv_ui_downloads`;
   `RemoteLinkGlyph`, `RemoteModelNotice` and `RemoteEngineControls` in `fv_ui_widgets` (the engine
   card and the dashboard share them). The a18 text helpers are Qt-free files of `fv_ui_remote`
   (`remote_text`, `host_text`), not `fv_uimath` (they need `history/format_utils.h`) and not
   `fv_remote` (it is owned by the transport packages in every wave).
4. **A second Tailscale CLI runner.** `fv_remote` ports `find_cli`, `_run_json`, `status` and adds
   `whois` (tailscale.py:100-254) over `fv_process`, because M5.9's probe lives in `fv_agentapi`,
   which `fv_remote` must not depend on. Status parsing stays M5.2's `net::parse_status`. M10 may
   make agentapi's probe call `remote::TailscaleCli`.
5. **Reachability without PowerShell.** Windows network profiles come from `INetworkListManager`
   (COM through wil) instead of `Get-NetConnectionProfile` (a17 map's native gain); `parse_profiles`
   is still ported for its vectors and as the parser of a recorded fixture.
6. **The wire carries PCM16.** Architecture 5.1 says `RemoteSpeechBackend` "sends the same 16 kHz
   windows as float32 frames"; OpenWhisper's wire is 16-bit little-endian PCM (protocol.py:105-110,
   181-192), which this spec keeps.
7. **Remote runtime installation is kept** for the NeMo CPU and CUDA runtime components (A17-30,
   lead decision 4); a request that would change the loaded runtime reports `restart_required`
   (one runtime per process, architecture 5.7). Other families' branches are dropped.
8. **Interop with a live OpenWhisper** through `tools/parity/remote_peer.py` as a child process
   under `ow_isolation.py`, `[platform]`, skipped without the OpenWhisper interpreter (lead
   decision 3). Earlier milestones replayed transcripts only.
9. **The update hold is ported without a Windows caller.** `prepare_update` is only called by
   OpenWhisper's Omarchy controls on Linux; the host API, its wire refusals and the dictation
   runtime's `prepare_host_update` are ported with their tests so the host behaves the same, and no
   OpenWhisper_CPP updater calls them.
10. **Discovery behind a transport seam.** `remote::DiscoveryTransport` (real UDP and a fake bus)
    lets every discovery test run without a network card, as lead note 4 requires; Python's tests
    used port 0 on the real stack.
11. **The host's thread model.** One OS thread per connection (Python) becomes per-connection
    strands on an 8-thread pool with an asynchronous FIFO work admission; behaviour (limits, FIFO
    order, 30 s wait, disconnect release) is unchanged.
12. **Sizes.** M9.6 (4,100 lines) is accepted above the usual size; splitting the host's single
    state machine would cost more than it saves.
13. **Order fixes from review.** M9.3 follows M9.1 in wave 1 (its `ScriptedPeer` needs M9.1's TLS
    listener) and adds its test-support directory through one line of `tests/support/CMakeLists.txt`;
    M9.2 declares `DiscoveryTransport` with its own `Datagram` and M9.7 implements `udp_discovery()`
    over `net::UdpSocket` (M9.2 and M9.1 share wave 1), so the real-UDP `[interactive]` responder
    test moves from M9.6 to M9.12, and M9.1 checks fingerprints against a fixed SHA-256 instead of
    M9.2's vectors;
    the remote branch of `speech/preview_status` moves from M9.13 (wave 3) to M9.11 (wave 2),
