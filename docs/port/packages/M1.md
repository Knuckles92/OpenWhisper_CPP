# M1 Dictation: work packages

Binding scope for the M1 packages (Lead amendment 7 of `docs/port/ARCHITECTURE.md`). Read with
the architecture (sections 2 to 11 are binding for names), the area maps under `docs/port/map`
(a03, a04, a05, a06, a07, a08, a09, a14, plus the a01, a02, a10 and a34 rows that

## Overview

M1 turns the M0 shell into a dictation app. A Windows low-level keyboard hook sees `kp *` in
any application; the hotkey runtime starts the recorder on the ranked microphone; the Bars
overlay opens by the pointer and moves with the voice; the second press stops capture after
the adaptive post-roll, saves `recorded_audio.wav`, decodes it window by window through
`speech::SpeechService` on the NeMo-Speech.cpp Parakeet runtime, stages the text on the
clipboard, synthesizes Ctrl+V into the focused app, restores the user's clipboard, shows the
text in the Quick Record tab, saves the entry (and a copy of the WAV) to History, and the
History sidebar lists the card, which plays the recording back. The runtime and the model are
either adopted from an OpenWhisper install (hard links, section 7.6) or picked once in a setup
dialog. `EngineWorker` and the dev bench in `src/ui_shell/dev/` are retired.

**Demo (section 11):** press `kp *` in Notepad, speak, the Bars overlay reacts, press again:
Parakeet text is pasted, appears in Quick Record and the History sidebar and plays back;
runtime and model adopted from an OpenWhisper install or picked once.

## Rules for every M1 package

- **Names.** Targets, directories and the classes named in section 2.3 are binding. Qt-free
  code keeps Python names in snake_case; Qt classes use camelCase methods and signals
  (section 8.3). Every class states its affinity in a header comment (section 4 rule 1).
- **User-visible strings** are copied verbatim from the Python line cited in the scope rows.
  "OpenWhisper" in copy becomes `identity().product` ("FioriVoce"); `lint.brand` rejects the
  literal. The log file name in messages comes from `identity().log_file`.
- **Function-level PARITY.** A Python test file can span several milestones (for example
  `test_application_controller.py`). A package lists in its `tests/<dir>/PARITY.json` only the
  functions its scope covers (as `ported`, `golden` or, at most 10 % of them, `pending` with a
  reason and the finishing package) plus the functions this spec marks `dropped` for it. The
  functions this spec assigns to a later milestone are not listed by M1 packages; the later
  package lists them. Each package section names its functions or counts per file.
- **Golden vectors** come from `tools/parity/golden_vectors.py` with one case file per Python
  module, `tools/parity/cases/<python.module>.py`, written by the package that ports that
  module; output to `tests/golden/<python.module>.json`. Where M0.4 seeded a file
  (`services.format_utils`, `services.titles`), the owning package extends it.
- **Screenshots** follow section 9.3: builders in `tools/parity/builders/aNN.py` (one per area,
  owned below), references in `tests/reference/<widget>/<variant>.{png,json}`. Frames that
  depend on Python's `random` (particles, confetti, bubbles, fish) cannot be matched pixel for
  pixel; those widgets get tree comparisons only, and the spec says which.
- **Events.** Runtime events of a04 (`recording.started`, `transcription.completed`, ...) are
  published through `base/events.h` `EventSink` with Python's payload fields; the bus and its
  consumers arrive in M5.
- **Shared fixtures** live in a per-package subfolder of `tests/fixtures/` named in "Owns".
- **Formatting and lints:** amendment 3 (WSL clang-format) and section 9.5 apply unchanged.

## Changes to the cut of section 11.2

1. **M1.6 is split.** M1.6 keeps `src/focus`; the new **M1.17 clipboard** owns `src/clipboard`
   in wave 2. `TemporaryClipboard` implements `ClipboardPort`, which section 2.3 places in
   `fv_focus`, so the two could not be built in the same wave, and together they are about
   4,000 lines with their 79 tests.
2. **M1.8 is split.** The new **M1.18 overlay-math** owns the overlay maths in `src/uimath`
   (wave 1); M1.8 keeps `src/ui_overlay` and moves to wave 2 because the widget is built on
   those maths. Together they were about 5,000 lines with tests.
3. **M1.14 is split.** The new **M1.19 dictation-core** (wave 2) owns the job model, the
   pipeline stages that M1 needs, `JobSlot`, the status builders and `HotkeyRuntime`; M1.14
   keeps `TranscriptionRuntime` (wave 3). Both own `src/dictation`, in different waves.
   Together they were about 5,000 lines with tests.
4. **M1.9 moves from wave 1 to wave 3.** It needs `appcore::OverlayState` (M1.1, same wave),
   `history/format_utils.h` (M1.13) for the stats strip and `models/speech_catalog.h` (M1.11) for the
   model field: hidden dependencies inside wave 1.
5. **M1.12 also depends on M1.3** and `fv_speech` declares `fv_audio` in its `DEPS`: decode
   windows are made with `audio::AudioFileDecoder` and `audio::Resampler16k` (section 5.2), and
   M2's `IncrementalSession` needs the same. Section 2.3 lists only engine, dsp, http, settings.
6. **M1.3 does not depend on `fv_dsp`** (section 2.3 lists it): dsp lands in the same wave and
   no M1 audio code needs it. A later package may add the dependency.
7. **New M1.20 runtime-setup** (`src/ui_setup`, wave 3) owns the "adopted from an OpenWhisper
   install or picked once" dialog, split from M1.16 to keep that package finishable.
8. **M1.15 keeps the History entry dialog** as the cut says, although the milestone table lists
   "entry dialog" under M2's a09 rest; M2 does not port it again.
9. **Overlay moments come in M1** (M1.18 maths, M1.8 painting) although the milestone table lists
   them under M2's a07 rest: M1's Cancel, enable/disable hotkey and pointer notices draw them.
10. **M1.9 also ports two widgets of other areas** that the Quick Record engine card cannot do
    without: a15's `StatusDot` / `StatusFieldCombo` / `engine_field` (A15-47) and the Parakeet
    subset of `LocalEngineControls` (A15-37, without `DictationLanguagesField`) as new files in
    `src/ui_widgets`, and a09's `TranscriptionStatsWidget` (A09-40) in `src/ui_record`.
11. **M1.16 owns `src/ui_shell/dev/`** (deletes it) and the lines of `src/ui_shell` that create
    `EngineWorker`, the dev tab and the AppContext services M1 implements (see its Owns), in
    wave 4. Every other M1 change to `src/ui_shell` is M1.21's (change 14).
12. **M1.7 defers** the SSE parser (first consumer `fv_llm`, M4), multipart bodies (first consumer
    `CloudSpeechBackend`, M2) and Zip64 writing (backups, M3).
13. **M1.12 owns `src/engine` edits** (DLL directory registration, word-offset options) although
    section 2.3 calls the engine unchanged; the CLAUDE.md engine rules still apply.
14. **New M1.21 main-window** (`src/ui_shell` except `dev/`, plus `src/uimath/window_fit.*`,
    wave 2). M0.md defers the main-window parts of a01 to M1 (side panel, fit window to page,
    transcript collapse resize, Compact Mode and its geometry, recording state relay, transient
    statuses: A01-47 to A01-49, A01-51 compact part, A01-52, A01-57, A01-58), but no package of
    the original cut owned `MainWindow` in M1: M1.16's Owns allowed only the Bootstrap lines and
    M1.15 a conditional edit, and M1.16 consumed a recording-state relay and a tab lock that
    M0.11's `MainWindow` does not provide. M1.21 provides them as host APIs; M1.15 (wave 3)
    registers its panel through them and no longer edits `src/ui_shell`; M1.16 (wave 4) plugs in
    the compact controller and the Quick Record collapse signal.
15. **M1.18 no longer ports `uimath/loudness.h` and `uimath/overlay_position.h`** or
    `test_overlay_position.py`: M0.8 owns them (M0.md, A02-23, A02-27). The "only if M0.8 did
    not" clauses were a cross-milestone double ownership.
16. **One owner per feature ID.** Where several packages contribute to one ID, the coverage row
    names the owner first (its acceptance covers the ID) and every other package cites the ID in
    its Scope as "part of A0x-nn". A script counting Scope ownership skips IDs prefixed
    "part of".
17. **Diagnostics inputs and the crash offer.** M0.5 defers `ReportInputs::nvidia_gpu`, the
    Parakeet catalog allowlist and "The speech engine crashed" CPU-runtime offer to M1; M1.16
    owns them (the `ReportInputs` lines of `src/app/main.cpp` and `src/cli/main.cpp`, and the
    offer in `ui_controller/engine_setup`).

### Traps

- numpy 2.x computes `rfft` of float32 input in single precision; match the dtype of each call
  site rather than promoting to double, and test against vectors, not intuition.
- The Nyquist rules: truncating to an even length doubles the last bin; growing from an even
  input halves it (streaming_transcriber.py:47-62); the output is scaled by `num_samples / n_in`.
- `split_point` takes the mean of squares per 1600-sample block over [24 s, 30 s) in float32
  and cuts one block after the argmin; `np.argmin` returns the first minimum (audio.py:20-25).
- `WindowSplitter` converts s16 to float by `/ 32768.` and joins pieces only once 30 s are
  pending (audio.py:68-86); a window's start is `offset / 16000` seconds.

   (M1.12) and M2's `IncrementalSession` need `fv_audio` (`AudioFileDecoder`, `Resampler16k`,
   `PcmTape`).
5. **Unspecified speech types.** Section 5.1 uses `BackendConfig`, `Slot`, `JobHandle`,
   `EngineLease`, `BackendFactory`, `RecognitionOptions` and `EngineError` without shapes; M1.12
   defines them (spec above) and `RecognitionOptions` must own its language string (pointer
   lifetime rule).
6. **`ClipboardPort`** is named in section 2.3 (`fv_focus`) but has no section 3 shape; M1.6
   defines it from `TemporaryClipboard`'s public methods.
7. **`base/events.h` `EventSink`** shape is not shown in section 3; M1.14 publishes a04's events
   through it with Python's payload fields.
8. **`RecognitionContext`** is a12's (`fv_text`, M4); M1 uses a minimal `dictation::RecognitionContext`
   (language, phrases) that M4 must adopt or alias.
9. **Settings keys.** M1 needs `fv_runtime_dir` and `fv_speech_runtime` (section 7.2); M0.6
   generates them from `tools/gen/fv_settings_keys.json` (resolved). Packages may not add keys
   (section 9.5 item 8).
10. **`audio::DeviceInfo`** lacks the `label` (MME name repair), `default_api` and `role` fields
    that the OpenWhisper ladder uses; M1.3 adds `audio::InputDevice` beside it.
11. **`Database::close()`** is needed for the shutdown order (close after draining
    `persistence`); M1.4 adds it as a member.
12. **Overlay ownership.** Section 2.3 makes `fv_ui_overlay` a feature while Python's
    `UIController` owns the overlay; M1.8 provides the instance with `ctx.provide<WaveformOverlay>`
    and M1.16 drives it. (Installs use the `components` strand that section 3.2 already lists.)
13. **`process/Shell`** is a section 3.9 header with no implementation before M5. M1 packages
    must not consume it: M1.15 reveals and opens folders through M0.10's `revealInFileManager`
    and `openFolderInFileManager`.
14. **`log::ReportInputs`** (M0.5) leaves `nvidia_gpu` and the catalog allowlist to M1; M1.16
    fills them in `src/app/main.cpp` and `src/cli/main.cpp` (change 17), since no other M1
    package owns those files.

## Risks

- M1.21 extends M0.11's `MainWindow` (members added, nothing changed); if M0.11's window
  diverges from the a01 layout tree (`content_wrapper` holding the tabs and the panel), M1.21
  reshapes it inside `src/ui_shell`, which it owns in wave 2, and M0.11's tests must keep
  passing.
- `test_application_controller.py` is split across M1.14, M1.16 and six later milestones by
  function; the parity report must aggregate function-level entries across `PARITY.json` files.
- Bit parity of `AudioFileDecoder` + `Resampler16k` with PyAV depends on matching FFmpeg
  versions and swresample defaults; a mismatch shows as a golden tolerance in M1.3 and a text
  difference in M1.12's `decode` test.
- The generated `keyboard` name table depends on the keyboard layout of the machine it is
  generated on (US layout recorded in the file); saved hotkeys with layout-specific symbols may
  not match on other layouts.
- The NeMo C ABI cannot abort a decode: cancel latency is up to one 30 s window, and a native
  crash in the runtime takes the process down (no worker isolation).
- Overlay frames that use Python's `random` (Classic particles, confetti, bubbles) cannot be
  compared pixel for pixel; they are tree-only and may hide visual drift.
- The LL keyboard hook must decide inside its callback; any contention with the GUI thread lets
  Windows remove the hook silently (the M1.19 watchdog re-hooks).
- M1.16 is the single integration point of 20 packages; its end-to-end test depends on every
  fake (`audio::FakeBackend`, `FakeKeyboardHook`, `speech::FakeBackend`, fake capture service,
  `FakeSyntheticKeys`) behaving like the real thing.
- Adoption by hard link fails across volumes and falls back to copying 714 MB; OpenWhisper's
  manifest version strings must not make FioriVoce offer an "update" for an adopted runtime.
