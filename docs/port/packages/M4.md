## Overview

M4 adds every text feature that sits between the speech engine and the paste. A12's service
layer arrives as two Qt-free libraries: `fv_text` (personal dictionary, "sounds like"
replacements and learning from corrections, snippets with light Markdown, cleanup levels and
prompts, cleanup profiles, transforms, per-app writing styles, recognition-context helpers and
the copy the Personalize pages show) and `fv_llm` (text-model endpoints: ten built-ins plus up to
50 custom OpenAI-compatible endpoints, the model catalog with its OpenCode route table, thinking
levels, local-server discovery, key verification, model lists, generation over Chat Completions,
Responses, Anthropic Messages and Google `generateContent`, the AI cleanup client with its
wall-clock deadline and cancel, rule polishing and the rewrite engine). `fv_dictation` gains the
real text preparer, AI cleanup of live dictations, uploads and batches, cleanup profiles,
learning from corrections, Command Mode (rewrite the selection or write at the cursor by voice)
and transforms (saved rewrites on a shortcut). The new feature library `fv_ui_personalize` ports
the Personalize chapter of Settings (Dictionary, Snippets, Apps & styles, Learned rules,
Profiles, Commands) and the AI cleanup page with its cleanup-model section; `fv_ui_widgets` gains
the text-model picker and endpoint dialog; Quick Record gets its cleanup-profile card and Command
Mode readiness, the Scratchpad its Transform menu, the API keys page the text-model credentials,
Home its cleanup rows and where-strip items, the Hotkeys page the profile and transform rows,
guided setup its provider row and privacy text, and the controller wires all of it.

**Demo (architecture section 11):** "AI cleanup with profiles and levels, dictionary, snippets,
app styles, Command Mode, transforms, learned rules." Concretely, run by the owner with his own
OpenRouter key or a local Ollama (no worker contacts a provider):

1. Settings > AI cleanup: turn cleanup on at Medium, pick OpenRouter and `openrouter/free` (or
   Ollama, marked "Running"), Thinking level Off; the key shows "OpenRouter API key found".
   Dictating into Notepad "um so the meeting is uh tomorrow at ten" pastes "The meeting is
   tomorrow at 10." and History records cleanup level "medium" and the elapsed cleanup time.
2. Dictionary: add "Ksenia" with "sounds like" "Ksenya"; a dictation of "ksenya" pastes
   "Ksenia" with cleanup off too; editing a pasted word twice the same way adds it as Learned.
3. Snippets: "my sign-off" inserts the saved signature, in a sentence or alone, rich text in
   WordPad.
4. Apps & styles: Work messages "Casual"; a dictation into Slack (or its site in a browser) is
   written casually, into Outlook formally.
5. Profiles: "Email" with a shortcut; dictating with it formats an email ("Formatting ·
   Email..."); Quick Record's profile card shows and selects it.
6. Command Mode: select a paragraph, hold the Command Mode shortcut, say "make it shorter",
   release: the rewrite replaces the selection ("Rewritten"); with nothing selected, "write a
   thank-you note" writes at the cursor.
7. Transforms: select text, press the "Polish" shortcut: it is rewritten in place; the
   Scratchpad's Transform menu applies "Make concise" to its text.
8. Learned rules: dictate "always spell my name Alex Rivera", review the polished rule, save;
   the next cleanup follows it.

**Rules that apply to every package below** (the rules of `M1.md`, `M2.md` and `M3.md`,
unchanged):

- A package changes only what its `Owns` line lists, plus its own `tests/<dir>/PARITY.json`
  entries, its case files `tools/parity/cases/<python.module>.py` (a case file another package
  created is extended, never rewritten), its builder (`tools/parity/builders/aNN.py`, extended,
  never rewritten) and its `tests/golden/<python.module>.json` and `tests/reference/<widget>/`
  entries.
- Function-level PARITY: a package lists the functions its section names (`ported`, `golden`,
  `dropped` with the reason, `other-platform`, or at most 10 % of its own scope `pending` with a
  reason and a finishing package). Functions this spec gives to a later package or milestone are
  not listed by the earlier one.
- Qt-free code keeps Python's names in snake_case; Qt classes use camelCase (section 8.3). Every
  class states its affinity. User-visible strings are copied verbatim from the cited Python line;
  "OpenWhisper" in copy becomes `identity().product`; `lint.brand` rejects the literal.
- **No test contacts the internet or spends the owner's API credit.** Providers are tested with
  `http::FakeHttpClient` (`http/testing/fake_http_client.h`), with the loopback server of
  `tests/http/loopback_server.h` (included as `"../http/loopback_server.h"` with `DEPS ...
  Boost::asio OpenSSL::SSL OpenSSL::Crypto`, as `tests/download` does), and with golden vectors
  made by running OpenWhisper's Python with its HTTP layer faked through the harness: a case file's
  `WRAPPERS` builds the function's fake `openai` client or `httpx` transport, which records the
  request (method, URL path, headers minus `Authorization`, JSON body) and answers a canned
  response; the vector stores both the recorded request and the function's result.
- **Keys are read off the GUI thread.** Every `CredentialStore` call asserts it is off the GUI
  thread (amendment 15): pages and pickers read key status and run checks on the `io` strand and
  deliver through `qt::TokenGate`. Text, selections, prompts, rules, dictionary terms and keys
  never reach a log call; failures log the exception type only.
- **Interactive tests** (a real selection copied with Ctrl+C, a real paste, a real microphone,
  the real clipboard) carry `[interactive]`, are written and not run (amendment 14); the package
  proves the behaviour through `focus::testing` fakes (`fake_clipboard.h`,
  `fake_synthetic_keys.h`, `fake_platform.h`), `hotkeys/testing/fake_keyboard_hook.h`,
  `audio::FakeBackend` and `speech::FakeBackend`.
- Every target compiles with `QT_NO_KEYWORDS` (amendment 17): `Q_SIGNALS:`, `public Q_SLOTS:`,
  `Q_EMIT`.
- Format with `wsl clang-format --dry-run -Werror` (amendment 3); Python under `tools/` follows
  the existing tools' style. Section 9.5's gates apply.

## Changes to the cut

Section 11 gives M4 no package table; these choices are this spec's.

1. **Text-model endpoints live in `fv_llm`, not `fv_text`.** Section 2.3 puts "endpoint tables"
   in `fv_text`; the speech-endpoint table already went to `fv_speech` (M2.4), and the text-model
   profiles need `fv_credentials` (key status, `resolve_api_key`) and `fv_http` (verification,
   model lists), which `fv_text` does not link. `text_llm.py`, `text_model_catalog.py`,
   `thinking_levels.py` and `local_text_servers.py` go to `fv_llm` (M4.2).
2. **`fv_text` also depends on `fv_focus` and `fv_hotkeys`** (section 2.3 lists settings and
   pyport): app styles classify the focused app through `focus::catalog` and
   `focus::is_terminal`, and profiles and transforms check shortcuts through
   `hotkeys::hotkey_conflict` and `normalize_hotkey`. Both are `core` libraries.
3. **The text-model picker, endpoint dialog and thinking-level combo are `fv_ui_widgets` files**
   (M4.6), following M2.15's `SpeechServerControls`: the AI cleanup page uses them now and M8's
   Insights model tile later, and building them in their own directory lets them run in parallel
   with the Personalize pages.
4. **The AI cleanup page, the Learned rules page and the Profiles page are in
   `fv_ui_personalize`**, with the shared cleanup gates (`CleanupGates`) and the cleanup API of
   the Settings window (`CleanupSettings`: `choose_cleanup_level`, `turn_on_cleanup`,
   `refresh_cleanup_gates`, `cleanup_gate_tile`). Python hosts them in `settings_dialog.py` (a11)
   but their content is a13's, and the Dictionary, Styles and Learned rules gates need them;
   `fv_ui_personalize` depends on `fv_ui_settings` (for `SettingsWindow`, `SettingsDialog` and
   `HomeRows`) and `fv_ui_setup` on `fv_ui_personalize`. `fv_ui_settings` keeps the API keys page
   and Home, and changes for M4 only through M4.10.
5. **Cleanup through installed coding agents moves to M8**, with a26's agent drivers: the
   `claude_code`, `codex` and `opencode_cli` runners (A12-17), the first-run offer (A12-48,
   A12-80, A13-49), Codex's per-model thinking levels and the agent card of the Cleanup model
   tile. `_cleanup_with_agent` calls `meeting.agent.installed.core.run_agent_task`, which starts
   a26's `LoopbackMcpServer` and `drivers.make_driver` (`meeting/agent/installed/core.py:324-360`,
   `drivers.py`, 1,263 lines); M5 ports installed-agent discovery (M5.6) and the picker (M5.18)
   but leaves those drivers to M8 (`M5.md`, M5.6 "Not in this package"), so the runner cannot
   land before M8, and the offer would switch users to a provider that cannot run. M4 keeps an
   agent provider id that is already saved and treats it as not ready ("Set up AI cleanup to
   rewrite text"; cleanup returns the raw text with `last_error = "cleanup unavailable"`); lead
   decision 3.
6. **The SSE parser M1.7 deferred to `fv_llm` moves to M8** (a27's streaming tool calls). Nothing
   in M4 streams: `generate` is one request and one answer, as in Python.
7. **Two `fv_dictation` packages in two waves:** M4.9 (wave 3) the text preparer, the cleanup
   stage, profiles and learning; M4.13 (wave 4) Command Mode, transforms, rewrite jobs and the
   profile and transform shortcuts.
8. **Types that M1.19 already put in `fv_dictation` stay there.** `dictation::Snippet`,
   `SnippetPlan` (`pipeline.h`) and `dictation::RecognitionContext` (`job.h`) are not moved:
   `fv_text` cannot include `fv_dictation` headers (`fv_dictation` links `fv_text`). `fv_text` has
   its own `text::Snippet` and `text::SnippetPlan`, and its recognition helpers take the language
   and the phrases as plain arguments; M4.9's preparer maps the snippet types field by field.
9. **`test_personalize_s4_dictionary.py`** (31 tests, classified a28 because meeting corrections
   call `vocabulary.replace_terms`) is ported by M4.1: its subject is `services/dictionary.py`.
   M7 does not take it (lead decision 7).
10. **`test_personalize_fix2_g3_chip_flow.py`** (6 tests of the History card's `_ChipFlow`, which
    M0 deferred to M4) is handled by M4.11 in `tests/ui_history`.
11. **Benchmarks:** `test_personalize_s2_benchmark.py` (8) and the golden-set check of
    `test_personalize_fix2_g4_unknown_app_paragraphs.py` (1) run OpenWhisper's
    `benchmarks/cleanup_levels.py` against a real model; they go to M10 with the other benchmark
    tests (amendment 16; lead decision 5).
12. **One follow inside a wave:** M4.7 starts once M4.4 and M4.6 are reviewed (the wave script's
    `after`). It needs M4.4's code, and it extends `tools/parity/builders/a13.py`, which M4.6
    extends in the same wave, so the two never edit the builder at the same time (lead
    decision 6).

No lead-owned frozen file needs a change for M4. Every settings key M4 reads is in
`settings/keys.inc` (`text_llm_profiles`, `transcript_cleanup_*`, `quick_record_profile`,

are in `appcore/overlay_state.h`.

### Traps

- Full Unicode casefold (`pyport::casefold`, "ß" folds to "ss"), and the origin map: "İ" maps to
  "I" first, a combining dot U+0307 after "i" is dropped, and a match that starts or ends inside a
  character that folded to several is skipped (`vocabulary.py:12-42`). Word boundaries are Python
  `(?<!\w)...(?!\w)` with Unicode `\w`, longest key first, one pass (`vocabulary.py:43-70`).
- `new` and `protected` are C++ keywords: the struct says `is_new` and `is_protected`, the JSON
  keys stay `"new"` and `"protected"`; `protected` is written only when true, `heard` is never
  kept on a learned term, `new` only on learned terms (`dictionary.py:108-160`).
- `_stable_id` is `"t" + sha1(term.casefold())[:11]` and a colliding id is re-derived from
  `id + term` in a loop (`dictionary.py:81-85, 125-126`); new ids are `uuid4().hex[:12]`.
- Limits count code points, not bytes (64-character words, 5 variants, 500 words, 200-term and
  2400-character prompt budget with `len(term) + 2` per term, protected list up to 50 and listed
  even past the vocabulary cap: `dictionary.py:196-220`).
- `parse_heard` splits at commas, semicolons and newlines and collapses whitespace per piece; a
  variant equal to the term, empty or over 64 characters is dropped; more than 5 distinct is an
  error (A12-58).
- Spelling rules: "spell", "spells", "spelled", "spelling" as words; none of except, unless, when,
  whenever, if, only, but; "as" is checked before "not"; straight or curly double quotes
  (`dictionary.py:404-487`).
- Learning tokens strip `.,!?;:"“”'‘’()[]{}<>«»…` at both ends and must fully match
  `[^\W_]+(?:['’-][^\W_]+)*`; alignment is `difflib.SequenceMatcher(autojunk=False)` over
  casefolded tokens; an insert at either end is ignored; exactly one 1-to-1 replace with two
  anchors, three pasted words and a learnable word of three characters or more
  (`dictionary.py:494-560`).
- Snippets: `normalize` turns "’" into "'" and keeps `\w+(?:['’.]\w+)*` words; the placeholder
  regex is `\[\[\s*[Ss]\s*(\d{1,4})\s*\]\]` and text that already holds one gets no plan; words of a
  trigger may be separated only by spaces, commas and dashes (`[\s,\-‐‑‒–—]*`); triggers sort by
  (-words, -characters, list order) (`snippets.py:204-278`).
- HTML: body text is escaped with `quote=False`, attribute values with quotes; only `http`,
  `https`, `mailto`, `tel` links, `www.` becomes `https://`; `<ol start="N">` when the first number
  is not 1; CR and CRLF normalized (A12-68, `snippets.py:360-466`).
- The guard sentence for several placeholders joins the last with " and " and no Oxford comma
  (`snippets.py:279-295`).

### Traps

- The deadline is wall-clock: per attempt 8 s hosted (`TRANSCRIPT_CLEANUP_TIMEOUT_S`), 120 s
  self-hosted; 1 retry for dictation, 2 when `timeout_s` is given (batch); give-up at `attempt *
  (retries + 1) + 1.0` s; `deadline_s` caps the whole call (`transcript_cleanup.py:52-91,
  449-463`). Python leaves the request on a daemon thread; C++ aborts it through the
  `CancelToken` (curl's transfer callback) and still reports Python's `last_error` strings
  ("empty input", "cleanup unavailable", "empty response", "canceled", "timed out after N s",
  the exception text).
- `last_error` is the contract: callers tell "no change" from failure only by it being unset
  after a call; a cancel set before the call returns "canceled" without sending (A12-70).
- `configure` rebuilds only when the provider or `connection_fingerprint` (id, kind, URL, key
  variable, resolved key) changes (`280-300`); a self-hosted profile calls
  `learn_server_models` before each request; each request gets a new uuid4 `session_id`
  (OpenCode Go header).
- Hosted catalogs (groq, opencode_go, opencode_zen) drop the caller's `temperature`,
  `reasoning_effort` and `extra_body`; `level = spec.thinking_levels.get(level, level)`
  (`text_generation.py:280-345`).
- Chat strips message keys starting with "_", turns `finish_reason` length or content_filter
  and a refusal into errors with the exact messages, and copies `reasoning_content`,
  `reasoning` and `reasoning_details` into the assistant message (`83-114`). Responses sends
  `store: false`, rebuilds input from the opaque `_responses` output, adds
  `include: ["reasoning.encrypted_content"]` for openai reasoning and drops temperature
  (`115-162`). Anthropic joins systems with blank lines and merges same-role turns
  (`163-207`). Google quotes the model in the path, excludes thought parts and falls back to
  `call_{index}` ids (`208-279`).
- Rewrite: the selection is the user message and the instruction is in the system prompt; with
  no selection the instruction is the user message; `<<NEEDS_SELECTION>>` is checked only
  without a selection (`text_rewrite.py:160`); a whitespace-only selection is no selection;
  over 20,000 characters is refused before sending; budget 30 s, 60 s when the message is over
  2,000 characters, never below the client's attempt timeout; `_describe_error` keeps the first
  line, at most 120 characters with "…"; the input is never returned on failure (`68-164`).
- `rewrite_standalone` never touches the dictation client and answers "Set up AI cleanup to
  rewrite text" when not ready; `dictionary_block` swallows errors and returns "".
- Never log a prompt, transcript, instruction, selection or key; log the exception type only.

## Risks

- `src/ui_personalize` passes through four packages in four waves; M4.3's `PersonalizeHost` and
  `PersonalizePage` must be right first time, or later pages report differences instead of
  fixing them.
- Prompt text is the product: one changed space changes what every model does. The generated
  `cleanup_prompts.json` and the golden vectors are the guard; never retype a sentence.
- Unicode semantics (full casefold, `\w`, code-point lengths, `difflib`) decide what the
  dictionary replaces, which snippet fires and what is learned; `fv_pyport` and the vectors are
  the guard.
- The wall-clock deadline of cleanup must hold against servers that trickle bytes; the
  loopback tests with a fake clock and a real socket both pin it.
- Workers must never hold a Settings widget (polish, dictation, catalogs, key status, local-server
  probes): every one goes through `TokenGate`, and each Python "closed mid-work" test is ported.
