# M8 Meeting intelligence: package specs

## Overview

Architecture section 11: **M8 Meeting intelligence**, areas a26 (meeting agent: prompts,
scheduler, tool policy, evidence, installed-agent meeting passes), a27 (the agent loop, which
OpenWhisper_CPP runs natively in process instead of OpenWhisper's Node and Bun sidecars), the rest of
a29 (custom reports, insight review, citations, live signals, past-meeting recall, the knowledge
folder, semantic history search, voice commands, re-run insights), the TypeSafe meeting features
and the judge parts of a12 that M5 did not take, and every row the M4 to M7 specs and the lead's
amendments 16 to 19 left to M8 (agent cleanup with its first-run offer and agent card, Codex
thinking levels, the SSE parser, the Insights model tile, the AI insights consent, the Meeting
Intelligence page and Home row).

**Demo** (run by the owner, amendment 18: it needs the owner's OpenRouter key, credit, agent
sign-in and microphone). (1) Settings > Meeting Mode > Intelligence: the built-in agent with
OpenRouter and a model; Meeting Mode tab: "AI insights" on, a meeting brief, Start; the one-time
"Turn On AI Insights" consent; after the two-minute warm-up the dashboard fills with key points,
decisions, actions, the note taker's live notes and transcript fixes, the activity strip ticks
("Model is thinking through the transcript…"); End runs transcript cleanup and the final report;
a tailored report is requested from the dashboard. (2) The same meeting re-run, or a new one,
with Claude Code chosen in the agent picker: the report is written by the installed agent over
the loopback MCP server. (3) Fast judgments on (M5.19's page) with voice commands: "Assistant,
mark that as a decision" adds a decision with "Decision noted" feedback; "note taker, replace
Acme with Acme Labs" adds a reversible spoken correction; highlights pulse per minute.

Workers prove every step with fakes: providers are loopback HTTP servers the test starts,
replaying hand-written or recorded SSE streams; installed agents are M5.7's `fv_fake_agent`
copied as `claude.exe`, `codex.exe` and `opencode.exe`; the judge is M5.4's `FakeJudge`; audio
and speech are M7's fakes. **No test contacts the internet, spends credit or starts a real agent
CLI**, and no `[interactive]` test is needed in M8 (nothing here hooks input, reads the
clipboard or opens a device; the folder picker and dialogs are injected and run offscreen).

### The native agent loop (owner decision, amendment 1)

OpenWhisper runs its default meeting AI in a Node sidecar (the Pi coding-agent SDK, `sidecar/`)
or a Bun sidecar (the OpenCode SDK, `sidecar-opencode/`), supervised from Python
(`meeting/agent/sidecar.py`, `opencode_sidecar.py`). OpenWhisper_CPP has no sidecar: the loop, its five
tools, its providers and its streaming run in process over `fv_http` and `fv_llm`
(`meeting_agent::NativeAgentCore`, M8.8, over `llm::stream_generate`, M8.1). Installed agent CLIs
(Claude Code, Codex, OpenCode) are still child processes through M6.2's drivers, driven by
`meeting_agent::InstalledAgentCore` (M8.4). The stored setting values stay OpenWhisper's: `pi`,
`opencode` and the legacy `direct` all select the built-in loop; `claude_code`, `codex`,
`opencode_cli` the installed agents. Where each sidecar behaviour lands:

| Sidecar behaviour (source) | In OpenWhisper_CPP |
|---|---|
| NDJSON JSON-RPC 2.0 framing, ids, parse errors, EPIPE (`rpc.ts`, A27-01) | dropped: no process boundary |
| Hello handshake, token, protocol and version checks, outdated-bundle message (`runner.ts:startSidecar`, `sidecar.py:_handle_hello`, `_validate_hello`, A27-02) | dropped (process only) |
| Spawn, `node.exe`/`bun.exe` selection, `CREATE_NO_WINDOW`, env key hand-off (`OPENWHISPER_LLM_API_KEY`, `_BASE_URL`, `_SIDECAR_TOKEN`), payload validation, component lease, runtime isolation root (`sidecar.py:780-960`, `opencode_sidecar.py`, A27-30, A27-32, A26-33) | dropped (process and packaging only); the key is resolved in process with `llm::resolve_api_key` (M8.8) |

**Recording the sidecars.** Node 24.15.0 (`C:\Program Files\nodejs\node.exe`) and Bun 1.3.14
(`%USERPROFILE%\.bun\bin\bun.exe`) are installed on this machine (looked at, not installed), and
the checkout carries the built bundles (`sidecar/dist/bundle.cjs`, `sidecar-opencode/dist/main.mjs`
with its `bun.exe`). M8.8 therefore **records** the Pi sidecar's behaviour (the model requests it
sends per turn, its progress events and its checkpoint replies) by running the checked-out
bundle under `node` against a loopback fake provider started by the harness (lead decision 3);
the SSE bodies the fake provider answers with are **hand-written**, transcribed from the fake
providers of `sidecar/src/pi-integration.test.ts` and `sidecar-opencode/src/adapter.test.ts`
(M8.1 owns them). The pure TypeScript tables (`protocolConfig`, `providerConfig`,
`retryDecision`, the tool descriptions) are vectors **hand-written** from the source with the
line cited, because generating them would need Bun to load the SDK packages from the checkout's
`node_modules`.

At most four workers run at a time; no wave chains a package after another. About 19,500 lines
of C++ source and 18,000 of tests. One directory has one owner per wave: `src/meeting_agent` is
M8.2, M8.4, M8.8 in waves 1 to 3; `src/meeting_intel` M8.3, M8.5, M8.9; `src/llm` M8.1, M8.6;
`src/meeting` M8.10, M8.11; `src/ui_meeting` M8.7, M8.11. `tools/parity/builders/a31.py` is
extended by M8.7 only; `a15.py` by M8.6 only.

**Rules that apply to every package below** (M0.md to M7.md's rules, unchanged, plus these):

- **`DEPS` lines.** A package that adds source files to `src/<dir>/` also owns that module's
  `DEPS` line for the libraries those files include (named in its section and in "New
  libraries" below), and a package that adds test files to `tests/<dir>/` owns that directory's
  `fv_test(... DEPS ...)`. Every test that runs M8.1's `SseProvider` (M8.5, M8.8, M8.9, M8.10,
  M8.11) adds `Boost::asio OpenSSL::SSL OpenSSL::Crypto`; a test that copies M5.7's
  `fv_fake_agent` adds a build dependency on that target (M8.11's end-to-end test; M8.4, M8.5 and
  M8.6 use M6.2's fake driver or an injected runner instead). No addition may
  create a cycle (`lint.layering`): `fv_meeting_agent` never depends on `fv_meeting_intel` or
  `fv_meeting`, and `fv_agents` never on `fv_llm`.
- **Nothing a test does leaves 127.0.0.1, spends credit or starts a real agent** (the overview's
  rule); providers are `SseProvider`s, agents `fv_fake_agent` with `USERPROFILE`,
  `CLAUDE_CONFIG_DIR`, `CODEX_HOME` and `XDG_CONFIG_HOME` in the test's temporary folder (M5.md's
  rule).

### Contracts

```cpp
namespace fv::llm {
struct SseEvent { std::string event, data, id; std::optional<int> retry_ms; };
class SseParser {                       // byte-exact WHATWG rules; not thread-safe
public:
    void feed(std::string_view bytes, const std::function<void(const SseEvent&)>&);
    void finish(const std::function<void(const SseEvent&)>&);   // flushes a final event
};
enum class StreamDelta { ThinkingStart, ThinkingDelta, ThinkingEnd, TextDelta,
                         ToolCallStart, ToolCallDelta, ToolCallEnd };
struct StreamEvent { StreamDelta kind; std::string text, tool_call_id, tool_name; };
using StreamSink = std::function<void(const StreamEvent&)>;   // on the calling thread
class StreamError : public TextGenerationError {               // what M8.8 retries on
public:
    std::optional<int> status;              // HTTP status, when one arrived
    bool transient = false;                 // 429, >= 500, connection error, dropped stream
    std::optional<double> retry_after_s;    // retry-after-ms, retry-after (s or HTTP date)
    bool output_seen = false;               // a delta reached the sink before the failure
};
// One attempt, no retries (the agent loop owns retries). Blocking; never on the GUI thread.
// Returns what generate() returns for the same reply; throws StreamError or
// TextGenerationError with M4.5's messages; a cancelled token throws the cancel error at once.
TextResult stream_generate(OpenAiCompatClient&, const TextLLMProfile&, GenerateRequest,
                           const StreamSink&);
}
```

### Traps

- Chat tool-call deltas are keyed by `index`; `id` and `function.name` come only in the first
  chunk of a call; arguments concatenate as text and are parsed once at the end; an empty
  arguments string means `{}`.
- OpenRouter sends `: OPENROUTER PROCESSING` comment lines while it waits: comments produce no
  event. It also streams `reasoning_details` (signed reasoning) that must be accumulated in order
  and replayed (M4.5's `test_wire_protocol_and_signed_tool_roundtrip`).
- Responses: the final `response.completed` carries the whole `output`; keep that as the replay
  (`_responses`), do not rebuild it from deltas; `include: ["reasoning.encrypted_content"]` and
  `store: false` stay as M4.5 sends them (`text_generation.py:115-162`).
- Anthropic: a `signature_delta` belongs to the open thinking block and must be replayed with it;
  `input_json_delta` fragments join into one JSON object.
- Google: the stream URL needs `?alt=sse`; the model id is quoted in the path as M4.5 does;
  `thoughtSignature` sits on the part and is replayed; thought parts never join the text
  (`text_generation.py:208-279`).
- `finish_reason` `length` and `content_filter`, and a refusal, raise M4.5's exact errors.
- A status line of 4xx or 5xx is reported from `on_head`, before any body is read; the error
  never carries the provider's body and nothing logs a request or response body (A27-24).
- Usage keys are normalized to `prompt_tokens`, `completion_tokens`, `total_tokens` with M4.5's
  `_usage` rules.
